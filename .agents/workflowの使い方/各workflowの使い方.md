# ワークフローの使い方まとめ

本プロジェクトには、小説執筆やプロット作成を効率化・高度化するための **5つの専用ワークフロー（スラッシュコマンド）** が用意されています。
それぞれの使用目的、正確な挙動、有効活用の方法を以下にまとめます。

> 🏷️ **コマンド名はすべて `fal-` で始まります**（fal＝ファルコン）。Claude Code や各種スキル集に同名の `brainstorm` `prompt` などが多数あるため、本プロジェクト専用のものだと一目で分かるようにしています。`/fal-` まで打てば5つに絞り込めます。

### 📌 全体像（5つの役割分担）

- **`/fal-brainstorm`** … 話の骨格をゼロから練る　➔ **発想**
- **`/fal-twist`** … どんでん返し・叙述トリックを設計し、フェアネスを検証する　➔ **仕掛け設計**
- **`/fal-polish`** … 決まった1案を1箇所ずつ修正・深掘りして仕上げる　➔ **磨き上げ**
- **`/fal-prompt`** … プロンプト集から最適なテンプレートを選んで実行する　➔ **日常の単発作業**
- **`/fal-refill-free_memos`** … 白紙のフリーメモを補充する　➔ **環境整備**

前の4つは「**発想 ➔ 仕掛け設計 ➔ 磨き上げ ➔ 単発の加工・検証**」という制作パイプラインを分担しており、役割が重複しないよう設計されています。最後の1つだけは執筆内容に関与しない、環境メンテナンス用のコマンドです。

> 💡 **`/fal-brainstorm` と `/fal-polish` は向きが逆です。** 前者は案を**増やす**（発散）、後者は1案を**詰める**（収束）。「もう案はいらない、これを良くしたい」と思ったら後者に移ります。

## 0. 使う前に知っておくこと

### 🖥️ 動く環境

**Antigravity・Claude Code のどちらでも、4つすべてが同じコマンド名で利用できます。**

手順書の実体は `.agents/workflows/` にあり、Claude Code 側の `.claude/commands/` にはそれを参照するだけの薄い橋渡しファイルが置かれています。したがって、

- **手順を変更したいときは `.agents/` 側だけを直せば、両環境に反映されます**（唯一の情報源を1箇所に保つ設計）。
- `.claude/commands/` 側を編集する必要があるのは、Claude Code 固有の事情（使用ツールの指定など）を足すときだけです。
- **コマンド名を変えたいときだけは、両側のファイル名を同時に直します**（➔ 末尾「🏷️ 命名規則」）。

> 💡 **両側ともファイル名がそのままコマンド名になります。** `.agents/workflows/fal-twist.md` も `.claude/commands/fal-twist.md` も `/fal-twist` です。ファイル名を揃えておけば、コマンド名も自動的に揃います。

### ⚙️ 4つの対話型ワークフローに共通する仕様

`/fal-brainstorm` `/fal-twist` `/fal-polish` `/fal-prompt` の4つには、共通の作法が組み込まれています。

- **質問は1ターンに1つだけ**。一度に質問攻めにされないよう設計されています。
- **選択肢には必ず「⭐AIの推奨＋その理由＋次点」が付く**。迷ったら推奨に乗れば進めます。
- **出力はすべて日本語**。ターミナル操作が必要な場合はUTF-8強制が前置されます。
- **回答は表（テーブル）ではなくブロック・カード形式**（`02_設定/AGENTS.md` の方針）。

### 🚧 「HARD-GATE」＝わざと止まる仕組み

4つの対話型ワークフローには、AIが早合点して完成品を出してしまうのを防ぐ安全装置（HARD-GATE）が入っています。**すぐに結論が出てこないのは不具合ではなく仕様です。**

- `/fal-brainstorm` … 発散〜再生成のループを**最低2周**し、かつユーザーが「収束」と言うまで完成あらすじを出しません。
- `/fal-twist` … 三層設計とフェアネス監査を終えるまで、トリックを「完成」として提示しません。
- `/fal-polish` … **確定操作を受けるまで本文を書き換えません。** 加えて1ターン1箇所、選択肢は6案＋ワイルドカード2案を必ず出します。
- `/fal-prompt` … `[ ]` の穴埋めと対象ファイルの確定を終え、**完成プロンプト全文を提示して承認を得るまで**実行しません。

急ぎたいときは、後述の操作コマンド（「収束」「そのまま実行」など）で明示的に短縮を指示します。

## 1. `/fal-brainstorm` （ミステリー深掘りブレスト）

- **使用目的:** エンタメ系ミステリーのあらすじやプロットを深く練り上げるための、本格的なブレインストーミングセッションを開始します。
- **使い方:** チャット欄で `/fal-brainstorm` と入力して起動します（引数は不要）。
  - `brainstorm/` フォルダに過去のセッションが残っていれば、起動時に「**続きから再開／新規セッション**」を1問だけ確認されます。

### 🔄 進み方（6フェーズ）

1. **セッション設定** … 大雑把なテーマ／絶対に入れたい・避けたい要素／グリル強度（light・standard・hard、既定は standard）を確認。
2. **発散** … 方向性の異なる案を **4〜6個＋ワイルドカード1個** 提示。各案は「フック・主人公・トリック・動機・舞台・構成…」といったファセット（要素）に分解された状態で出てきます。
3. **部分選択（枠指定）** … 案を丸ごと選んでも、要素単位で選んでも、**案ごとに別々の指示を同時に出してもOK**（➔ 詳細は下の「🎯 枠指定」）。
4. **傾向確認** … 2〜3周ごとに、AIが推定したあなたの好み（「◯◯を重視し、△△は避けたい」）を言語化して確認してきます。ここで誤解を訂正できるので、**違うと感じたら遠慮なく修正してください**。
5. **再生成** … 選択済み要素＋確認済みの嗜好を制約として、次世代の案を提示。以降3〜5を満足するまでループ。
6. **グリルモード（ストレステスト）** … 案が固まってきたら尋問モードへ。トリックの穴／動機の納得度／伏線の配置と回収／読者へのフェアネス／ご都合主義の有無を、1ターン1問で突いてきます。
7. **収束・出力** … 「収束」「まとめて」と指示すると、あらすじ確定版を作成。セルフレビュー＋「ミステリー読者」「担当編集者」の多視点レビューを経て保存されます。

### 🎯 枠指定（このワークフローの中心操作）

実際のブレストでは「案2は丸ごといい」より、「**案2のこの設定はいいから、それを残して他は作り直して**」のほうが圧倒的に多くなります。そのため部分選択は、案ごとに別々の指示を**1回の返答でまとめて出せる**ようになっています。

たとえば6案が出てきたときに、こう返せます。

```text
2改[舞台,主人公] 5改[フック] 1+3合[1のトリック+3の動機] 4,6却下
```

これは「**案2と案5は指定した設定だけ残して作り直し／案1と案3は指定した設定を合成して1案に／案4と案6は却下／残りの枠は新案**」という意味です。次のターンには、指定した3案＋新案＋ワイルドカードが並びます。

#### 使える指示は5種類

- **🔁 改** `2改[舞台,主人公]` … 指定した設定だけ残し、**それ以外を作り直す**。枠を1つ使う
  - `2改×3` と書けば、同じ縛りで3案つくらせて枠を3つ使えます
  - `[ ]` を省いて `2改` とだけ書くと、残す設定が一意に決まらない場合だけ1問聞かれます
- **🔗 合成** `1+3合[1のトリック+3の動機]` … 複数案の設定を組み合わせて1案に。`1+3+5合` も可。枠を1つ使う
- **📌 維持** `4維持` … 案4を変更せず次の一覧にも残す。枠を1つ使う
- **❌ 却下** `4,6却下` … 不採用。枠は使わない。理由は任意（書かなければAIが推定して記録します）
- **✨ 新案** … 指定枠を引いた**残りの枠が自動的に新案**になります。`新案3枠` `全部で8案` で調整も可

#### 書き方は3通り、どれでも通ります

- **1行ショートハンド**（上記）… 慣れると最速
- **テンプレート**（下記）… 選択肢の末尾に自動で添えられるので、コピーして埋めるだけ
- **自然文** … 「2と5は舞台を残して作り直して、1と3は混ぜて、4と6はなし」でも同じ意味に解釈されます

```text
─ 枠指定テンプレ（コピーして編集）───────────
改  : ● → 残す「          」
合成: ●+● → 使う「●の      ＋●の      」
維持: ●
却下: ●,● → 理由「          」
新案: 残り枠すべて
──────────────────────────
```

> 💡 テンプレの全文が出るのは**初回の発散時だけ**です（毎回出すと画面が埋まるため）。もう一度見たいときは「**テンプレ**」と入力してください。

#### 知っておくと便利な挙動

- **確認は曖昧なときだけ。** 指定が明確なら聞き返さず即生成し、代わりに冒頭の `📥受領` 行で解釈を1行示します。ここがズレていたらその場で指摘してください。
- **どの設定がどこから来たか必ず表示されます。** 各案に「継承：舞台＝…（案2より）／更新：トリック＝…」が付くので、残せと言った設定が本当に残っているかを目視で確認できます。
- **言及しなかった案は却下扱い**になります。「4と6は不採用」と書かなくても、触れなければ落ちます（理由は「未言及・推定」として記録されます）。
- **ワイルドカード枠は必ず残ります。** 指定枠で埋め尽くしても1つだけ逆張り案が出ます（発想の固着を防ぐため）。
- **キープ指定は以後の既定になります。** 「残して」と言った設定は単発の採用ではなく、外すと言うまで続く制約として `preferences.md` に昇格します。
- **AIは無条件に従いません。** 残せと指定した設定が案の足を引っ張っている場合は、`🔎所見` として指摘が入ります。

### 📁 作られるファイル

セッション中は**毎ターン**、以下が自動更新されます（会話が長くなって文脈が圧縮されても内容を失わないための仕組み）。

- `brainstorm/<セッション名>_tree.md` … アイデアツリー。全分岐をノードID（N1、N1-2…）で記録
- `brainstorm/<セッション名>_preferences.md` … 嗜好プロファイル（採用／却下した要素の蓄積）
- `brainstorm/<セッション名>_summary.md` … 収束フェーズで生成される最終成果物

> 💡 収束時には「**ボツにしたが光る要素リスト**」が必ず併記されます。今回使わなかった案も、後の作品のためにここに貯まっていきます。

### 🔖 しおりと分岐（後から戻るための仕組み）

ブレストは一本道ではありません。「案1で進めたけど、やっぱり案3の路線も見てみたい」は必ず起きます。**しおりは、その"やり直し"を安全に行うための機能**です。

#### なぜ戻れるのか

`tree.md` には、**採否にかかわらず提示された案が全文で残っています**。選ばなかった案も消えないため、後から同じ分岐点に立ち戻り、**当時選ばなかった選択肢をそのまま再提示させる**ことができます。しおりは、その「戻りたくなりそうな地点」に目印を付けておく機能です。

> 💡 **しおりは案のコピーではありません。** 実体は「このノードIDに⭐を付けて、`tree.md` 末尾の一覧に転記する」だけ。だから何個打ってもファイルは重くなりません。

#### ノードIDの読み方

分岐点には `N1` `N1-1` `N1-2` … という階層番号（ノードID）が自動で振られます。ハイフンが増えるほど深い階層です。

```text
N1        … 1回目の発散（最初に6案出たところ）
N1-1      … N1 での選択を受けた2世代目
N1-2      … N1-1 での選択を受けた3世代目
```

毎ターンの冒頭に出る `📍現在地` 行に、現在のノードIDとルートからのパスが表示されます。

```text
📍現在地: N1-2（パス: テーマ > 案1 > 第2世代 > A+C+F統合）
```

#### 使い方は4つだけ

- **「しおり」** … いま居るノードに⭐を付ける。⭐には `しおり1` `しおり2` … と通し番号が振られます
- **「N1-2に戻る」／「しおり2に戻る」** … その地点まで戻り、**当時選ばなかった選択肢を再提示**させる
- **「一覧」** … しおり一覧と現在地パスを表示する
- **「比較 N1-2 N1-3」** … 2つの枝を並べて比較し、AIの優劣所見と理由をもらう

#### 戻ったときに何が起きるか

1. AIが `tree.md` から該当ノードを読み直し、**当時の選択肢を再提示**します（あらすじを説明し直す必要はありません）
2. そこで新しく選んだ内容は、**新しい枝番号**で記録されます（例：`N1-2` に戻って選び直すと `N1-2-2` が生える）
3. **元の枝は削除されません。** 戻ったせいで、それまで進めてきた路線が失われることはありません
4. あとから「比較」で、両方の枝を突き合わせて選べます

#### 打つべきタイミング（実用的な目安）

- **大きな決断をする直前** … 「主軸をこの案にする」と決める前に1つ打っておくと、後戻りが一瞬で済みます
- **捨てるのが惜しい案があったとき** … 「今回はAを採るが、Bも捨てがたい」と感じた瞬間が打ちどきです
- **`/fal-twist`（トリック錬成）へ移る直前** … トリック設計中に「この仕掛けを通すには動機を変えたい」と気づくのは頻出パターンです。移行前に1つ打っておくと、プロット側へ即座に戻れます
- **セッションを中断するとき** … 現在地は自動保存されますが、⭐を打っておくと再開時の一覧で目立ちます

#### 知っておくべき注意点

- **しおりは `tree.md` に依存します。** ファイルを消す・別セッション名で作り直すと戻れなくなります
- **`/fal-twist` とは共有、`/fal-polish` にはありません。** トリック錬成中も同じしおりに戻れますが、磨き上げ側は1手ずつ取り消す「**戻す**」という別の仕組みです（➔「3. `/fal-polish`」）
- **戻る先はノード単位です。** 「あの案のあの一文だけ戻したい」という粒度には対応していません。そこまで細かい修正は `/fal-polish` の領分です

### 🎮 会話中に使える操作コマンド

- **枠指定（`2改[舞台]` `1+3合` `4維持` `4,6却下` `残り新案`）** … 上記「🎯 枠指定」を参照
- **「テンプレ」** … 枠指定テンプレートの全文を再表示する
- **「全部改[〇〇]」** … 提示された全案に同じキープ指定をかけて作り直させる
- **しおり系（`しおり` `N1-2に戻る` `しおり2に戻る` `一覧` `比較 N1-2 N1-3`）** … 上記「🔖 しおりと分岐」を参照
- **「グリル」／「softer」「harder」** … 尋問モードの開始と強度変更
- **「収束」「まとめて」** … 最終出力へ

### ✨ 有効活用の仕方

- **ゼロからのアイデア出し:** 新しい小説のコンセプトや設定を固めたい時に最適です。1ターン1問のペースで質問が来るため、対話を通じて自然とアイデアが引き出されます。
- **長期間のプロット構築:** 状態がすべてファイルに保存されるため、日をまたいでも「続きから」再開でき、文脈を見失いません。
- **枝分かれを恐れず試せる:** 分岐は消されずツリーに残るので、「Aの路線も捨てがたい」と思ったら、しおりを打って別路線を試し、後から比較できます（➔ 上の「🔖 しおりと分岐」）。
- **そのままトリック設計へ移行できる:** 骨格が固まったら、セッションを閉じずに「**トリック錬成**」と伝えるだけで `/fal-twist` に接続できます（➔ 詳細は「2. `/fal-twist`」の「🔗 `/fal-brainstorm` との連携」）。

## 2. `/fal-twist` （どんでん返し・叙述トリック錬成）

- **使用目的:** ミステリーの醍醐味である「どんでん返し」や「叙述トリック」の設計・強化・検証に特化したセッションを開始します。
- **使い方:** チャット欄で `/fal-twist` と入力して起動します。
  - `brainstorm/` に既存セッションがあれば、「**既存のブレストに接続する／単体でトリック設計を始める**」を1問だけ確認されます。接続した場合は、そこまでのプロット文脈と嗜好をそのまま引き継ぎます。

### 🔄 進み方（6フェーズ・真相からの逆算）

1. **前提確認** … 既存プロットの有無／騙しの規模（ラスト一撃の大逆転か、中盤の中規模ツイスト連打か）／絶対に守りたい制約。
2. **「読者の思い込み」の棚卸し** … トリックの土台は読者が無意識に置く前提です。裏切れる思い込みを4〜6個＋ワイルドカードで洗い出します（例：「語り手は真実を語っている」「この二人は別人だ」）。**どの思い込みを裏切るかが決まるまで、型選びには進みません。**
3. **型の選択** … 型カタログ（どんでん返し系・叙述トリック系・支援技法）から適合する型を3〜5個提示。ここで「**叙述トリックは文章媒体特有の技法**（映像化すると成立しないものが多い）」という媒体適性の確認が入ります。
4. **三層の逆算設計** … 「**真相層**（実際に何が起きたか）➔ **表層**（読者に見せる物語。どこを書かないか）➔ **誤導層**（どこへ注意を逸らすか）」の順に、真相側から組み立てます。
5. **伏線・手がかり設計** … 各手がかりについて「初読時の見え方／再読時の意味／配置位置／カムフラージュ方法」を対応表に落とします。
6. **フェアネス監査** … 手がかりの後出しがないか、再読しても矛盾しないか、驚きだけで納得が置き去りになっていないか、既視感はないか、トリック都合でキャラが壊れていないかを尋問。
7. **出力** … 真相シート＋伏線対応表＋監査結果を完成させます。

### 🚫 設計上の禁じ手（監査で弾かれるもの）

- **地の文で嘘を書くこと** … 真実だけを不完全・多義的に配置して、読者が勝手に誤読する形にします（信頼できない語り手を意図的に使う場合のみ、その旨を明記して例外扱い）。
- **手がかりが1個だけ／直前配置だけ** … 「後出し伏線」として却下されます。**最低3個・分散配置**が原則。
- **二重読みが成立しない手がかり** … 再読時に意味が反転しないものは、そもそも伏線と認められません。

### 📁 作られるファイル

- `brainstorm/<セッション名>_twist_sheet.md` … **真相シート＋伏線対応表＋監査結果**（このワークフロー固有の成果物）
- `/fal-brainstorm` から接続した場合は、既存の `tree.md` に枝を継ぎ足し、完成した真相シートへの参照を該当ノードに書き戻します（新規ファイルは作りません）。

### 🎮 固有の操作コマンド

`/fal-brainstorm` 共通のコマンド（しおり／戻る／一覧／比較／softer・harder／収束）に加えて、

- **「再読テスト」** … 現時点の設計で再読シミュレーションだけを即実行
- **「型カタログ」** … トリックの型一覧を表示
- **「禁じ手チェック」** … 地の文の虚偽・後出し伏線・二重読み不成立の3点を即時確認

### 🔗 `/fal-brainstorm` との連携（このワークフロー最大の強み）

`/fal-twist` は `/fal-brainstorm` の**姉妹ワークフロー**として作られており、ファイル形式（tree.md／preferences.md）・選択肢フォーマット・しおり運用をすべて共有しています。そのため「あらすじ作りの続きとして、そのままトリック設計に入る」ことができます。

#### ① 接続する2つのルート

**ルートA：ブレストの途中から呼び出す（同一セッションで継続）**

`/fal-brainstorm` で対話している最中に、そのまま次のように伝えます。

```text
トリック錬成
```

セッションを中断せず、その場でトリック設計モードに切り替わります。話の流れが途切れないので、「この案、仕掛け次第で化けそう」と感じた瞬間に踏み込めるのが利点です。

> 💡 この呼び出し方は `/fal-brainstorm` `/fal-twist` 双方の手順書に操作コマンドとして登録済みです。万一反応しない場合は、ルートBか、次のように明示的に指示してください。
> `.agents/skills/twist-trick-forge/SKILL.md に従って、このセッションに接続してトリック設計を始めてください`

**ルートB：後日 `/fal-twist` を起動して接続する**

日を改める場合はこちらです。`/fal-twist` を起動すると `brainstorm/` 内の `*_tree.md` が検出され、

> 「既存のブレストセッションに接続しますか？　それとも単体でトリック設計を始めますか？」

と1問だけ聞かれるので、**「接続する」** を選びます。複数セッションがある場合は、どのセッションかを伝えてください。

#### ② 接続すると何が引き継がれるか

- **プロットの現在地** … `tree.md` を読み込み、どの枝のどの案まで決まっているかを把握した状態で始まります。あらすじを説明し直す必要はありません。
- **あなたの好み** … `preferences.md` の嗜好プロファイル（採用／却下してきた要素の傾向）を引き継ぐため、提示される型や案が最初からあなた寄りになります。
- **しおり・分岐** … ブレスト側で打ったしおりや分岐にそのまま戻れます。

そのうえで、フェーズ0の残り（**騙しの規模**＝ラスト一撃か中盤ツイスト連打か、**絶対に守りたい制約**＝「この人物は犯人にしない」等）だけを確認して本題に入ります。

#### ③ 接続中のファイルの扱い

- **新しい `tree.md` は作られません。** 既存の `tree.md` に、トリック設計の分岐が**枝として継ぎ足されます**。
- トリック固有の成果物として `brainstorm/<セッション名>_twist_sheet.md`（真相シート＋伏線対応表＋監査結果）が追加されます。
- 完成時には、`tree.md` の該当ノードに **`twist_sheet.md` への参照が書き戻されます**。これにより、後からしおりでその地点に戻り、**別のトリック案を第2案として試す**ことができます。

> 💡 もし接続したのに新しいセッション名でファイルを作り始めたら、「既存の `<セッション名>_tree.md` に枝を継ぎ足してください」と指示して修正させてください。

#### ④ 切り替えるベストタイミング

- **接続に向くタイミング:** 犯人・動機・舞台といった**骨格が一通り決まった後**。フェーズ1で「読者の思い込み」を棚卸しするには、裏切る対象となるプロットが必要なためです。
- **早すぎる場合:** テーマしか決まっていない段階では、まず `/fal-brainstorm` を2〜3周させて骨格を固めるほうが結果的に早く進みます。
- **戻ってよい:** トリック設計の途中で「この仕掛けを成立させるには動機を変えたい」と気づいたら、**`/fal-brainstorm` 側の該当ノードに戻って再発散**できます。行き来は前提の設計です。

#### ⑤ 典型的な往復の流れ（例）

1. `/fal-brainstorm` … フェーズ1〜4を2周し、犯人と動機の候補が固まる ➔ 「**しおり**」を打つ
2. そのまま「**トリック錬成**」 ➔ 読者の思い込みを棚卸し ➔ 型を選択 ➔ 三層設計
3. フェアネス監査で「動機がトリック都合で不自然」と指摘される ➔ 「**しおり1に戻る**」で 1. の地点へ
4. `/fal-brainstorm` 側で動機だけ再発散し、新しい枝として採用
5. 再度トリック設計に戻り、監査を通す ➔ `twist_sheet.md` 完成、`tree.md` に参照が書き戻される
6. 最後に `/fal-brainstorm` で「**収束**」 ➔ トリックを織り込んだあらすじ確定版を `summary.md` に出力

#### ⑥ 単体起動を選ぶべきケース

以下の場合は接続せず「単体でトリック設計を始める」を選びます。

- 既存プロットと無関係に、**トリックのアイデアだけを試作**したいとき
- 別作品・短編用の仕掛けを考えたいとき（既存セッションの嗜好や制約に引きずられないため）
- すでに完成した仕掛けを持ち込んで、**監査だけ**を受けたいとき

### ✨ 有効活用の仕方

- **トリックの壁打ち:** 読者を騙す巧妙なトリックを作りたい時や、ラストの展開にインパクトを持たせたい時に、専門的な観点から詰められます。
- **`/fal-brainstorm` との連携:** 上記のとおり、「基本的なあらすじができた後に、トリック部分だけを重点的に強化・検証する」というシームレスな使い方が非常に強力です。
- **完成済みトリックの検査にも使える:** ゼロから作るだけでなく、すでにある仕掛けを持ち込んで「再読テスト」「禁じ手チェック」だけ回す、という使い方も有効です。

## 3. `/fal-polish` （ピンポイント磨き上げ）

- **使用目的:** すでにある1案を、**1箇所ずつ選択肢で修正・深掘りして仕上げます**。`/fal-brainstorm` が「案を増やす」道具なのに対し、こちらは「1案を詰める」道具です。
- **使い方:** `/fal-polish` の後に磨きたい案を貼って起動します（引数なしでも可）。
  - ブレストの途中なら「**磨き**」と伝えるだけで接続できます（案の貼り直しは不要）。
  - 他のツールで作った案を貼るだけでも使えます。

### 🔧🔍 扱うのは2種類だけ

- **🔧 修正** … すでに書かれている文の**表現・内容を差し替える**。本文を上書きします
- **🔍 深掘り** … まだ決まっていない情報を**決める**。本文の下に注釈として足します

この2つを交互に繰り返して、直すところがなくなったら保存して終了、という流れです。

### 🔄 進み方

1. **取り込み** … 案を貼ると、**各文に番号（①②③…）を振って再表示**されます。以後、箇所の指定はこの番号でできます。
2. **モード選択** … 「🔧修正／🔍深掘り／✅終了」の3択。最初から「③を修正」と言えばこの確認は飛ばされます。
3. **箇所の特定** … 番号で指定／文をそのまま貼る／「**候補**」と言えばAIが直すべき箇所を理由付きで6つ提案します。
   - **番号だけ言えば済みます。** 「③」のように大きめの指定でも聞き返されず、その中で最も具体的な要素（引用符でくくれる一文など）を対象として選択肢が出ます。何を対象にしたかは `📍対象` 行に明示されるので、違えばその場で言い直してください
   - 絞り込みの確認が入るのは、**どこを対象にしても選択肢が濁るときだけ**です
4. **選択肢** … **通常6案＋ワイルドカード2案**。各案には「採用すると何が変わるか」が1行付きます。⭐AI推奨＋理由＋次点も付きます。
5. **確定と反映** … 確定すると、修正は本文を上書き、深掘りは注釈として追記されます。同時に `⚠️波及` が示されます（下記）。
6. 2〜5を繰り返し、「終了」で保存へ。

### 🎯 一発で決まらない前提で作ってあります

選択肢の選び方は **`/fal-brainstorm` の枠指定と同じ記法**なので、覚え直しは要りません。

```text
3          … 案3で決定（本文に反映される）
3+5合      … 3と5の方向性を合成して再提示（まだ決定ではない）
3+5合 決定 … 合成した結果をそのまま確定
3改[もっと短く] … 案3を縛りにして6案を作り直す
別案        … まったく別の6案＋W2
```

自然文（「3と5を混ぜた感じで、もう少し短く」）でも同じ意味に解釈されます。`合` と `改` で方向性を絞り込むループは、何周してもかまいません。

> 💡 **確定と言うまで本文は変わりません。** AIが気を利かせて勝手に書き換えることはない設計です（HARD-GATE）。

### ⚠️ 確定のたびに出る「波及」の3点

一文を差し替えると、その一文だけでは済まないことがあります。確定のたびに、次の3点が必ず報告されます。

1. **周辺の取り残し** … 差し替えた文の**直前・直後・括弧書き・ラベル**が古い前提のまま残っていないか。**ここが最も見落としやすい箇所**です
   - 実例：「罰が当たったのかもしれない」を別の表現に差し替えたところ、直後の「（誤解か、韜晦か）」だけが「罰」を前提にしたまま取り残されました
2. **他項目への影響** … 他の番号の記述と矛盾しないか、既存の伏線を壊さないか
3. **新たに生じた宿題** … その確定によって未確定になった点。次の深掘り候補として1つだけ挙がります

### 📁 作られるファイル

- `brainstorm/<セッション名>_polish.md` … 作業ファイル。**毎ターン更新**されます
  - 本文（最新）／注釈（深掘りの確定内容）／変更履歴（変更前・変更後・選んだ理由）／不採用だが使える表現のストック
- 終了時に**保存先フォルダを尋ねられ**、日本語タイトルを付けてそこへ移動されます（作業ファイルは残りません。履歴は最終ファイルに全部入っています）。

### 🎮 会話中に使える操作コマンド

- **「候補」** … 直すべき箇所をAIが理由付きで6つ提案する
- **「今の全文」** … 現在の本文を番号付きで表示する（何度も直すと現状を見失うため）
- **「戻す」** … 直前の確定を1つ取り消す
- **「別案」** … 選択肢を総入れ替えする
- **「ストック」** … 不採用にした案のうち光るものの一覧を表示
- **「ブレストに戻す」** … 骨格から作り直したくなったら `/fal-brainstorm` へ（**磨いた内容は破棄されません**）
- **「トリック錬成」** … `/fal-twist` へ接続
- **「終了」「保存」** … 保存して終わる

### ✨ 有効活用の仕方

- **「なんか違う」を言語化せずに進める:** 一発で理想の表現が出ないのが前提なので、「3と5の中間」「3をもっと短く」と方向だけ示せば絞り込めます。自分で言葉を探す必要がありません。
- **設定の穴を潰す:** 深掘りモードは「答えを並べる」のではなく「**その答えが物語に何をもたらすか**」で6案を散らします。確定するたびに次の未確定が1つ提示されるので、芋づる式に設定が埋まります。
- **矛盾を早期に見つける:** 確定のたびに `⚠️波及` が出るため、「表現を直したら伏線が壊れていた」に後から気づく事故を防げます。保存時にも全体のセルフレビューが入ります。
- **ボツ表現が貯まる:** 選ばなかった案のうち光るものはストックに残るので、別の場面や別作品で再利用できます。

## 4. `/fal-prompt` （プロンプト・ディスパッチャー）

- **使用目的:** プロンプト集（`01_free_memo/プロンプト集.md`）の中から、現在の目的に最適なテンプレートをAIが自動で選び、`[ ]` を埋めて実行してくれます。
- **使い方:** やりたいことを一言添えて起動します。

  ```text
  /fal-prompt 第5章の伏線が回収できてるか見て
  ```

  引数なし（`/fal-prompt` だけ）でも起動でき、その場合は「今日は何をしますか？」と、よく使う入口を添えて1問だけ尋ねられます。

### 🔄 動作の流れ

1. **プロンプト集を読み直す** … 記憶ではなく毎回ファイルを読むため、**編集した内容が即座に反映されます**。
2. **テンプレート選定** … 依頼を「工程」に分類し、⭐推奨＋理由＋次点の形で提示。
3. **対象の特定** … 参照・編集するファイルのパスを明示して確認（IDEで開いているファイルが第一候補になります）。
4. **パラメータ補完** … `[ ]` を埋めます。AIが推定できる箇所は勝手に埋め、**推定した箇所は「（推定）」と明示**されます。質問は本当に判断できないものだけ、1ターン1問。
5. **部品スニペットの付与** … 「推測と創作を分けて書く」「ボツ案も列挙する」などの共通条件を文脈に応じて最大3つまで追加（表を使わないルールは常時付与）。
6. **完成プロンプトの提示と承認** … 全文が ```text ブロックで提示され、`[このまま実行]` `[ここを直したい]` `[別のテンプレートにする]` を選びます。
7. **実行 ➔ フィードバック** … 実行後、「このテンプレートを追加してはどうか」「この条件行を足してはどうか」という**プロンプト集への追記提案**が出ます。

### 🎮 操作コマンド

- **「別のテンプレート」** … 選定をやり直し、次点以下を提示させる
- **「プロンプトだけ」** … 実行せず、完成プロンプトの提示で停止（**他のAIツールに貼り付けたいとき**に便利）
- **「そのまま実行」** … 承認ステップを省略して即実行（提示自体は必ず行われます）
- **「一覧」** … プロンプト集のクイックインデックスを表示
- **「追記して」** … 追記提案をプロンプト集に反映

### ✨ 有効活用の仕方

- **日常タスクの効率化:** 文章の校正、設定の整理、特定要素のチェックなど、「プロンプトを探してコピペする」手間を省きたい単発タスクに最適です。
- **自動ナビゲーション:** 依頼内容が重厚なプロット作成やトリック設計に該当する場合は、AIが `/fal-brainstorm` や `/fal-twist` への切り替えを1問で提案してくれます（勝手には切り替わりません）。判断基準は「**複数ターンで分岐を記録しながら煮詰める作業なら委譲、1〜2ターンで完結するならこのまま実行**」。
- **使うほど育つ:** プロンプト集にテンプレートを追加すれば、そのぶん `/fal-prompt` の対応範囲がそのまま広がります。**章番号の変更・章の並べ替え・名称変更をしてもメンテ不要**（AIは番号ではなく内容で照合するため）。
  - ⚠️ **唯一メンテが必要なのは、`01_free_memo/プロンプト集.md` を移動・改名したとき**です。その場合は `.agents/skills/prompt-dispatcher/SKILL.md` と `.agents/workflows/fal-prompt.md` の2箇所を修正してください。

## 5. `/fal-refill-free_memos` （フリーメモ補充）

- **使用目的:** `01_free_memo` フォルダの `free_memo_01.md` 〜 `free_memo_10.md` のうち、**存在しない番号のファイルを自動生成**し、白紙メモのストックを常に10個に保ちます。
- **使い方:** チャット欄で `/fal-refill-free_memos` と入力して起動します。
  コマンドを使わず、PowerShell で直接スクリプトを叩いても結果は同じです。

  ```powershell
  [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $env:PYTHONUTF8=1; python .agents/scripts/refill_free_memos.py
  ```

  ※ PowerShell と Python が前提です。文字化け防止のため、UTF-8指定を必ず前置してください。
  ※ カレントディレクトリはプロジェクトルート（`idea_of_novel/`）にしてください。

### ⚠️ 正確な挙動（誤解しやすいポイント）

このスクリプトは **メモの「中身」を一切見ません**。判定しているのは**ファイル名の有無だけ**です。

- `free_memo_01.md` 〜 `free_memo_10.md` のうち、**存在しない番号だけ**を新規作成します。
- **既存ファイルは絶対に上書きしません。** 何度実行しても安全です（書きかけのメモが消える心配はありません）。
- 対象は **01〜10 の固定範囲**。11個目以降は作られません。
- 作成されるファイルには、「このメモはアイデアであって決定事項ではない」旨のAI向け注意書きが最初から入っています。

### 📝 正しい運用（ここが肝心）

上記のとおり**ファイル名の有無で判定する**ため、メモを使ったら**リネームするか、別フォルダへ移動する**のが正しい使い方です。

- ✅ `free_memo_03.md` に書いた内容が固まった ➔ `01_free_memo/その他/○○について.md` などへ**改名・移動** ➔ `/fal-refill-free_memos` で 03 が補充される
- ❌ `free_memo_03.md` という名前のまま中身だけ書き込む ➔ ファイルは存在するので**補充対象にならず**、白紙ストックが減ったままになる

### ✨ 有効活用の仕方

- **執筆環境の整備:** アイデア出しでフリーメモを消費した後に実行することで、常に10個の白紙メモをストックしておけます。手作業でファイルを作る煩わしさがなくなります。
- **定期実行が向いています:** 上書きの危険がないので、「作業の区切りごとにとりあえず叩く」運用で問題ありません。

## 💡 状況に応じた使い分けのコツ

- **「新しい話を考えたい」「あらすじをゼロから練りたい」** ➔ `/fal-brainstorm`
- **「トリックを思いつきたい」「結末に強烈などんでん返しを入れたい」「この仕掛け、フェアか検証したい」** ➔ `/fal-twist`
- **「この案でいくけど、ここの表現を変えたい」「この設定を決めたい」「なんか違うが言葉にできない」** ➔ `/fal-polish`
- **「ちょっと文章を見てほしい」「伏線の抜け漏れチェックなど、特定の作業を頼みたい」** ➔ `/fal-prompt`
- **「メモ帳（MDファイル）が足りなくなった」** ➔ `/fal-refill-free_memos`

> 💡 **`/fal-brainstorm` と `/fal-polish` の分かれ目：** まだ**別の案も見たい**なら前者、**この案で行くと決めた**なら後者です。案が1つに決まった後もブレストを続けると、せっかく固めた骨格が毎回ゆらぎます。

### 🔗 実践的な併用パターン

- **新作を立ち上げる:** `/fal-brainstorm` で骨格を作る ➔ 収束させて `summary.md` を得る ➔ `/fal-twist` で同じセッションに接続し、仕掛けを設計する ➔ `/fal-polish` で文面と設定を1箇所ずつ詰める ➔ `/fal-prompt` で「検証・監査」のテンプレートを回して仕上げる。
- **案は決まったが詰めが甘い:** `/fal-brainstorm` の途中で「**磨き**」と伝えて `/fal-polish` へ。案の貼り直しは不要で、嗜好プロファイルもそのまま引き継がれます。磨いている最中に骨格から作り直したくなったら「**ブレストに戻す**」で戻れます。**行き来は前提の設計です。**
- **既存プロットの弱点を潰す:** `/fal-prompt` で矛盾チェック ➔ 小さな穴なら `/fal-polish` でその箇所だけ直す ➔ 大きな穴なら `/fal-brainstorm` に戻り、該当のしおりから再発散。
- **迷ったらまず `/fal-prompt`:** 依頼が重ければ AI 側が `/fal-brainstorm` `/fal-twist` `/fal-polish` を提案してくれるため、入口として使って問題ありません。

### 🏷️ 命名規則：`fal-` 接頭辞

**このプロジェクトのワークフローは、コマンド名をすべて `fal-` で始めます**（fal＝ファルコン）。

**目的：** Claude Code や各種スキル集には `brainstorm` `prompt` といった一般名のコマンドが多数あり、そのまま使うと**どれが本プロジェクトのものか判別できなくなる**ためです。`/fal-` まで打てば候補が5つに絞られる、という実用上の利点もあります。

#### ファイル名とコマンド名の対応

**両環境とも、ファイル名（拡張子を除く）がそのままコマンド名になります。**

| 環境 | フォルダ | ファイル名 | できるコマンド |
|---|---|---|---|
| Antigravity | `.agents/workflows/` | `fal-twist.md` | `/fal-twist` |
| Claude Code | `.claude/commands/` | `fal-twist.md` | `/fal-twist` |

- 余計な接頭辞（`workflow-` など）は付けません。付けるとその分までコマンド名に入ります。
- **両側のファイル名を同じにしておけば、コマンド名も自動的に揃います。**

#### 改名するときに直す箇所

1. `.agents/workflows/fal-〇〇.md` のファイル名
2. `.claude/commands/fal-〇〇.md` のファイル名
3. 両ファイル内の見出しと相互参照（橋渡し側は `.agents/workflows/fal-〇〇.md` を指しています）
4. このドキュメント
5. `.agents/skills/*/SKILL.md` の `description`（起動コマンド名が書かれています）と `01_free_memo/プロンプト集.md`

**最後にプロジェクト全体を旧名で検索し、取りこぼしを潰してください。** 特に5は見落としやすい箇所です。

> 💡 **ファイル名を変えたら Antigravity のウィンドウを再読み込みしてください。** ワークフロー一覧はキャッシュされることがあり、再読み込みまで新しい名前が `/` メニューに出ないことがあります。

> 💡 **ファイル名を変えたら Antigravity のウィンドウを再読み込みしてください。** ワークフロー一覧はキャッシュされることがあり、再読み込みまで新しい名前が `/` メニューに出ないことがあります。

### 📐 ファイル参照のルール（編集時の注意）

手順書・スキル内でテンプレートや参照資料を指すときは、**プロジェクトルートからのパスを書いてください**（例：`.agents/skills/twist-trick-forge/trick-catalog.md`）。

`templates/` `reference/` のような、実在しないフォルダを前提にした相対表記は、AIがファイルを見つけられず途中で止まる原因になります（過去に4ファイル・6箇所で発生し、修正済み）。
