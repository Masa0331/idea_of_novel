# ワークフローの使い方まとめ

本プロジェクトには、小説執筆やプロット作成を効率化・高度化するための **6つの専用ワークフロー（スラッシュコマンド）** が用意されています。
それぞれの使用目的、正確な挙動、有効活用の方法を以下にまとめます。

> 🏷️ **コマンド名はすべて `fal-` で始まります**（fal＝ファルコン）。Claude Code や各種スキル集に同名の `brainstorm` `prompt` などが多数あるため、本プロジェクト専用のものだと一目で分かるようにしています。`/fal-` まで打てば6つに絞り込めます。

### 📌 全体像（6つの役割分担）

- **`/fal-synopsis`** … 面白い話の骨だけを速く作る（細かい設定は無視する）　➔ **骨子づくり**
- **`/fal-brainstorm`** … 話の骨格をゼロから練る　➔ **発想**
- **`/fal-twist`** … どんでん返し・叙述トリックを真相から逆算して作り、ずるくないかを見る　➔ **仕掛け設計**
- **`/fal-setting`** … 設定を作る・直す・確かめる・畳む　➔ **設定管理**
- **`/fal-prompt`** … プロンプト集から最適なテンプレートを選んで実行する　➔ **日常の単発作業**
- **`/fal-refill-free_memos`** … 白紙のフリーメモを補充する　➔ **環境整備**

前の5つは「**骨子づくり ➔ 発想 ➔ 仕掛け設計 ➔ 設定管理 ➔ 単発の加工・検証**」という制作パイプラインを分担しており、役割が重複しないよう設計されています。最後の1つだけは執筆内容に関与しない、環境メンテナンス用のコマンドです。

> 💡 **`/fal-synopsis` と `/fal-brainstorm` は深さが違います。** 前者は**面白いかどうかだけ**を見て骨を速く作る、後者はそこに設定と辻褄を肉付けする。⭐ **骨がつまらないうちに設定を練っても、面白くはなりません。**

> 💡 **`02_設定/` に書き込めるのは `/fal-setting` だけです。** ほかの3つ（骨子・発想・仕掛け）は設定ファイルを触りません。決まったことを設定ファイルに落とすときは「**設定に反映して**」と言うと `/fal-setting` につながります。

## 0. 使う前に知っておくこと

### 🖥️ 動く環境

**Antigravity・Claude Code のどちらでも、6つすべてが同じコマンド名で利用できます。**

手順書の実体は `.agents/workflows/` にあり、Claude Code 側の `.claude/commands/` にはそれを参照するだけの薄い橋渡しファイルが置かれています。したがって、

- **手順を変更したいときは `.agents/` 側だけを直せば、両環境に反映されます**（唯一の情報源を1箇所に保つ設計）。
- `.claude/commands/` 側を編集する必要があるのは、Claude Code 固有の事情（使用ツールの指定など）を足すときだけです。
- **コマンド名を変えたいときだけは、両側のファイル名を同時に直します**（➔ 末尾「🏷️ 命名規則」）。

> 💡 **両側ともファイル名がそのままコマンド名になります。** `.agents/workflows/fal-twist.md` も `.claude/commands/fal-twist.md` も `/fal-twist` です。ファイル名を揃えておけば、コマンド名も自動的に揃います。

### ⚙️ 5つの対話型ワークフローに共通する仕様

`/fal-synopsis` `/fal-brainstorm` `/fal-twist` `/fal-setting` `/fal-prompt` の5つには、共通の作法が組み込まれています。

- **質問は1ターンに1つだけ**。一度に質問攻めにされないよう設計されています。
  - 💡 `/fal-brainstorm` では、「**質問やめて**」と言えばAIからの質問が止まります（再開は「質問していい」）。
- **選択肢には必ず「⭐AIの推奨＋その理由＋次点」が付く**。迷ったら推奨に乗れば進めます。
- **選択肢の出し方は2通りです**（Claude Code の場合）。
  - **案を比べる場面はテキスト**で `A)` `B)` `C)` … と本文に並びます。記号・番号・名前のどれで答えても通ります。⭐ **会話に残るので、あとから読み返せます。**
  - **軽い分岐だけ、選択の窓（クリックで選ぶやつ）**が出ます。「次に何をするか」やはい・いいえなど、説明がほぼ要らないときだけです。
  - 💡 **窓は答えると選択肢の中身が消えます。**だから比べる材料は窓に入れず、本文に置く決まりにしてあります。
- **出力はすべて日本語**。ターミナル操作が必要な場合はUTF-8強制が前置されます。
- **回答は表（テーブル）ではなくブロック・カード形式**（`02_設定/AGENTS.md` の方針）。

### 📐 物語系の3つは、まったく同じ決まりで動きます

`/fal-brainstorm` `/fal-twist` `/fal-setting` の3つは、**同じ土台の上に乗っています。**決まりは `/fal-brainstorm` 側（`.agents/skills/mystery-deep-brainstorm/SKILL.md`）に1箇所だけ書かれていて、残り2つはそれを読んで従うだけです。

つまり、**覚えることは `/fal-brainstorm` のぶんだけで足ります。**

> 💡 **`/fal-synopsis` だけは、わざと軽くしてあります。**使う記号は4つだけ、決定も作りません（✅ を付けません）。骨を速く作ることだけに絞った道具だからです。

| 共通の決まり | 中身 |
|---|---|
| **使う記号** | 11個だけ（✅🟡🗂❌／◎○△／⭐⚠️／📋🎯）。増えません |
| **番号を振らない** | 設定も、直す場所も、トリックの型も、**短い名前**で呼びます |
| **表を使わない** | `brainstorm/` の中はカード形式。途中に行を足しても壊れないため |
| **普段使いの言葉** | 説明は日常語で。⚠️ ただし**作品に入る言葉**（セリフ案・地の文の案・手がかりの文面案）は対象外 |
| **⭐おすすめ＋理由＋次点** | 省略されません |
| **逆張り案を必ず1つ** | 案を出すときは、あえて反対の方向の案が毎回1つ混ざります |
| **目安と固定** | **AIが出した数字・細部はぜんぶ「目安」。**話に合わせて勝手に直され、`📝目安を直した：…` の1行が出るだけです |
| **どこに響くか** | 何かを決めるたび、前に決めたことの**何を解くか／何を壊すか**が報告されます |
| **📋宿題 ／ 🗂とっておく ／ ❌やめたこと** | 3つとも同じ扱い。🎯付きは話題が来たとき必ず出し直されます |
| **初読メモ** | 本文を書いたら、**初めて読む人が引っかかるところ**が章ごとに並びます |
| **毎ターン、ファイルが更新される** | 会話の記憶に頼りません。いつ中断しても続きから再開できます |
| **面白さが先** | **これは作品の初期を助ける道具です。**設定に引っかかっても案は丸められず、**設定を変える案が選択肢に出ます**（何が変わる／何が困る／どこが混乱する、まで書かれます） |
| **選んだあと、チェックで内訳を決める** | 案を選ぶと、**どこを決定にするかのチェックボックス**が出ます。⭐ 先頭の「**全部このまま決定する**」を選べば1クリックで終わります |
| **一区切りの整理** | 決まったことが3件たまる／宿題が1件片づく/章を1つ直す、などで**AIのほうから確認が出ます**（1件1行＋チェック） |
| **チャットモード** | 「次に何をするか」の選択肢に必ず入ります。**形式をやめてふつうに話せます**（ファイルの更新は続きます） |

💡 **意味がすぐ取れない業界語は、3つとも使いません**（発散／抵触／棚卸し／裁定 など）。「案を増やす／引っかかる」と書かれます。
　※ `収束` `まとめて` は例外で、**あなたが打つ操作の言葉**として残しています。

### 🚧 「HARD-GATE」＝わざと止まる仕組み

5つの対話型ワークフローには、AIが早合点して完成品を出してしまうのを防ぐ安全装置（HARD-GATE）が入っています。**すぐに結論が出てこないのは不具合ではなく仕様です。**

- `/fal-brainstorm` … ユーザーが「**収束**」「**まとめて**」と言うまで、完成あらすじを出しません。
- `/fal-twist` … 「**三つの層**」と「**ずるくないかを見る**」を終えるまで、仕掛けを「完成」として出しません。
- `/fal-setting` … **決めてもらうまで設定ファイルを書き換えません。** 加えて**1ターン1箇所**しか直さず、**消す前には必ず参照元を洗い出して見せます**。
- `/fal-synopsis` … **矛盾や辻褄を理由に、面白い案を取り下げません。**気づいたことは「引っかかり置き場」に溜め、直すのは次の工程に回します。
- `/fal-prompt` … `[ ]` の穴埋めと対象ファイルの確定を終え、**完成プロンプト全文を提示して承認を得るまで**実行しません。

急ぎたいときは、後述の操作コマンド（「収束」「そのまま実行」など）で明示的に短縮を指示します。

### 💬 チャットモードと、3つのフリーメモ

物語系の3つは、どれも**チャットモード**に切り替えられます。「次に何をするか」と訊かれたときの選択肢に、**必ず1つ並びます。**

- **やめるもの** … `【いま】``【受けた】`の2行／案4〜6個＋逆張り案／⭐おすすめ／1ターン1問。⭐ **ふつうに会話できます**
- **続くもの** … ⚠️ **ファイルの更新は続きます。**話の中で決まったことは、その場で書き足されます（戻ったときに消えません）

チャットモードに入ると、AIは `01_free_memo/fal用メモ/` の中を読みます。

| ファイル | 何を置くか |
|---|---|
| `fal用_作品案メモ①〜⑤.md` | 作品の思いつき。まだ形になっていないもの。**①から順に使う**（長くなったら次の番号へ）／⭐ **常に5本置いてあります** |
| `fal用_雑メモ.md` | 何でも置き場 |
| `fal用_機能修正用メモ.md` | ⚠️ **作品ではなく、この道具そのものへの不満・直したいこと** |

- ⭐ **書きっぱなしで構いません。**整える必要はありません
- ⚠️ **メモの中身が勝手に議題にされることはありません。**「こんなことが書いてありますが、触りますか」と一言出るだけです
- ⚠️ `fal用_機能修正用メモ.md` を読んでも、**AIがワークフローを勝手に直すことはありません**
- 戻るときは「**戻る**」「**案を出して**」。⚠️ **コマンドを打ち直す必要はありません**

### 🧭 この3つの、行き着く先

物語系の3つは、最終的に**プロット**（各話のあらすじと、登場人物が何をするかを具体的に書いたもの）を作り、そこから小説を書くための道具です。

⚠️ **プロット担当の `/fal-plot`（仮）は、まだ作っていません。**いまは3つとも、そこへ渡そうとはしません。

## 1. `/fal-synopsis` （あらすじの骨子づくり）

**役割**：**面白い話の骨だけを、速く作る。**細かい設定・辻褄・整合は、ここでは**わざと**扱いません。

⭐⭐ **面白いあらすじができれば、設定はあとから帳尻を合わせられます。逆はできません。**設定をどれだけきれいにしても、骨がつまらなければつまらない作品になる、という考え方の道具です。

**使い方**：`/fal-synopsis` で起動します。始めに2問だけ訊かれます（このあらすじは**全体のどこか**／どんな**役割**を持たせたいか）。

### 🔄 入り口は2つ

- **モードA｜作り直す** … 既にあるあらすじを、もっと面白くする。⭐ **まず15〜30行の骨子に圧縮して1回だけ見せ**、そこから案を出します（圧縮した時点では、まだ何も変わりません）
- **モードB｜ゼロから作る** … 話を1から作る。⭐ **読むファイルは最低限だけ。**読まないことが速さになります

### 🚫 わざとやらないこと（HARD-GATE）

- **矛盾・辻褄・既存設定との食い違いを理由に、面白い案を取り下げません。**気づいたことは「引っかかり置き場」に黙って足され、会話は止まりません
- **ここで書いたものは、何ひとつ決定ではありません。**✅ は付かず、`02_設定/` も `brainstorm/` も触られません
- **細かい設定の提案をしません。**新しい案を既存の設定に合わせようともしません（案に余計な制約が付くだけのため）

💡 **溜まった引っかかりは、次の工程で片づけます。**辻褄は `/fal-brainstorm`、設定ファイルへの反映は `/fal-setting` の仕事です。

### 🔣 使う記号（4つだけ）

`👤` ユーザーが言ったこと ／ `🤖` AIが足したこと ／ `⭐` おすすめ・要点 ／ `⚠️` 注意

💡 **物語系の3つ（11個）より少ないのは、意図的です。**速さのために、覚えることを削ってあります。

### 📁 作られるファイル

- `synopsis/<日付>_<短い名前>.md` … 本体1本（雛形は同フォルダの `synopsis-template.md`）
- `synopsis/<日付>_<短い名前>_案B.md` … 別バージョン。⭐ **気に入らない案は上書きせず、こちらに分けられます**
- ⚠️ `brainstorm/` にも `02_設定/` にも書かれません

### 📏 長さの目安

**15〜30行。**超えると「細部が入り込んでいる合図です」と**一度だけ**知らせが出ます。⚠️ 強制的に削られることはありません。

### 🎮 操作の言葉

**案について**：`1と3を混ぜて` ／ `2は舞台だけ残して` ／ `4は別バージョンへ` ／ `5はやめ` ／ `もう3案` ／ `出し直し`
**進み方**：`山場からやり直す` ／ `通しにして` ／ `短く` `3行で`
**確認**：`引っかかり` ／ `役割は？`（最初の2問の答えを表示）
**渡す**：`辻褄を合わせたい`（➔ `/fal-brainstorm`）／ `仕掛けを作りたい`（➔ `/fal-twist`）
**チャットモード**：`チャットモード` `ふつうに話したい` ／ `戻る` `案を出して`

### ✨ 有効活用の仕方

- **設定に縛られた頭をほどく:** 「その設定と合わない」で案が丸められないので、いま持っている設定の外側の話が出てきます
- **気に入らない案を捨てずに残す:** `_案B.md` に分かれるため、大胆な案を安心して試せます
- **骨ができたら卒業する:** 骨子が固まるとAIから1回だけ「次へ渡しますか」と訊かれます。そこから `/fal-brainstorm` に移れば、辻褄合わせが始まります

## 2. `/fal-brainstorm` （ミステリー深掘りブレスト）

**役割**：話の骨格をゼロから練る。

⭐ **操作はひとつだけです。AIが案を並べ、あなたが選ぶか、指摘で覆す。**それ以外は覚えなくて構いません。

### 🔄 進み方

1. **最初の質問**（1ターン1問。大雑把なテーマ／絶対に入れたい・避けたい要素）
2. **AIが案を4〜6個＋逆張り案を1個出す**
3. **あなたが選ぶ** — 自然文でOK（「1と3を混ぜて」「⭐A」「2は舞台だけ残して作り直して」）
4. **どこを決定にするかを、チェックボックスで選ぶ** — ⭐ 先頭の「**全部このまま決定する**」で1クリック終了
5. **もう一段よくするか、1問だけ訊かれる**（このまま進む／もっといい案を出す／あらすじを直す）
6. **一区切りなら、決まったことがまとめて出る**（1件1行＋チェック）
7. **次に何をするか訊かれる** — ここに**チャットモード**も並びます
8. 選ばれたものを反映して、次の案が出る ➔ **2へ戻る**
9. 「**収束**」「**まとめて**」と言うと、あらすじ確定版になります

### 🖥 毎ターンの画面

```text
【いま】〈やっていること〉 ／ 宿題12 ／ 決めてほしいこと1
【受けた】案1と案3を混ぜる

（案 または 報告）

⭐おすすめ：案2 — 理由が1行
⚠️：〈決めごとに引っかかるとき／前の決定を壊すときだけ〉

質問：〈1つだけ〉
　A) …　⭐おすすめ
　B) …
```

💡 **フッターや操作一覧は出ません。**質問の選択肢が、そのまま次の一手の案内になります。

💡 **選択肢は基本テキストで出ます。**クリックで選ぶ窓が出るのは、「次に何をするか」のような軽い分岐だけです。

### 📁 作られるファイル（2本だけ）

- `brainstorm/<セッション名>.md` … **いま効いているものだけ**（決まったこと／宿題／とっておく／やめたこと／まだ入れてない）
- `brainstorm/<セッション名>_あらすじ.md` … **作品の本文**と、初めて読む人が引っかかるところ

⚠️ **以前は3本ありましたが、読まれない記録が膨らんで設定を追えなくなるため、1本にまとめました。**
💡 **管理番号は振りません。**設定は「番の相手」「弟の死因」のような**短い名前**で呼びます。取り消すときも「**番の相手を戻して**」で通ります。

### 🔣 使う記号（11個だけ）

```text
✅決まった    🟡検討中    🗂とっておく    ❌やめた
◎必須        ○優先      △あれば          ← AIが付けたものは「◎必須(仮)」
⭐おすすめ    ⚠️注意
📋宿題        🎯（とっておいた案が戻るきっかけ）
```

### 🎚 どれくらい大事か（◎ ○ △）

「絶対に要る設定」と「はまれば使いたい設定」を同じ棚に置くと、まとめるときに同じ重さで扱ってしまいます。

- **◎必須** … これが無いと話が成り立たない
- **○優先** … 使えるなら必ず使う。落とすときは理由が書かれる
- **△あれば** … はまる場所があれば使う。無くても話は立つ

💡 **AIが勝手に確定はしません。**AIが付けたものは `◎必須(仮)` と書かれ、あなたが「(仮)」を外して確定します。
💡 言い忘れても大丈夫です。AIが推定して `(仮)` 付きで1行示します（訊かれません）。

### ⚠️ AIが必ず言う3つ

1. **⭐おすすめとその理由**（次点も言えるなら添えられます）
2. **どこに響くか** … 新しい設定が、前に決めた何を**解くか／壊すか**。⚠️ **「壊す」側は省略されません**
3. **決めごとに引っかかったら言う** … 「絶対にやらないこと」に触れる案には ⚠️ が付きます
   - 💡 **引っかかる＝禁止ではありません。**気づかせるための表示で、採るかどうかはあなたが決めます

### 🎛 目安と固定 — ここが発想の足かせを外します

- **固定** … あなたが自分で出したもの／「この形のまま使う」と言ったもの
- **目安** … それ以外。**AIが案の中で出した数字・固有名・細部は、ぜんぶ目安**

💡 **目安は、話に合わせてAIが勝手に直します。**確認は求められず、`📝目安を直した：「三十年」→「十五年」（戻すときは「三十年に戻して」）` の1行が出るだけです。
⚠️ **年数・年齢・人数・距離は、あなたが指定したのでなければ全部目安です。**動かせない出来事を先に並べて、数字はあとから逆算します。

### 📝 初読メモ（あらすじに、読者が引っかかる場所が書かれます）

あらすじを書き出すと、その場で「**初めて読んだ人が引っかかるところ**」が章ごとに並びます。

- 種別は **疑問**（なんで？）／**引っかかり**（腑に落ちない）／**ご都合**（都合よく運びすぎ）
- **1章あたり最大3件。**確実に止まるところだけ
- 状態は **🟡まだ直していない** ／ **✅直した** ／ **🗂あえて残す**（先で明かす謎なら、引っかかること自体が正しい）
- ⭐ **直し方が必ず添えられます。**指摘だけでは終わりません
- 💡 **番号は振りません。**章ごとに並ぶだけです

### 📋 宿題 ／ 🗂 とっておく ／ ❌ やめたこと

- **📋宿題** … **決めないと先へ進めないこと。**新しい案の方向は、まず宿題から選ばれます
- **🗂とっておく** … 一覧からは下ろすが記録は残す。**🎯が付いていると、その話題に来たときAIが必ずもう一度出します**
  - 💡 「**惜しい**」「捨てたくない」と言えば、必ず🎯が付きます
  - ⚠️ 「終了」「もう見ない」と言ったものは、ここには回りません
- **❌やめたこと** … 理由が1行だけ残ります（同じ案が再提案されないため）
  - ⚠️ **やめたのは案であって、その素材まで禁止したわけではありません**

### 📤 まだ入れてない

決めたのに、あらすじや `02_設定/` にまだ反映していないものが積まれます。

⚠️ **AIが `02_設定/` を勝手に書き換えることはありません。**
⭐ **ただし、積みっぱなしにもしません。**直したほうがいいものが出たら、**変更の提案**が出ます。

```text
【設定を直しますか】chr_a01_時風隼（探偵）.md の【キャラクター略歴】

なぜ直すか：今回決めた出会いの順序と、略歴の順序が食い違っている
困ること：なし
混乱すること：chr_a06 にも同じ順序が書いてある（そちらも直す必要あり）

- [ ] 全部このまま直す　⭐おすすめ
- [ ] 出会いの順序 … 前：看病 → 神社 ／ 後：神社 → 人になって助ける
- [ ] いまは直さない
```

- **あなたが許可したときだけ、AIがファイルを直します。**1件ごとに「前」と「後」が必ず書かれます
- **断ったものは**「まだ入れてない」に残り、⚠️ **次の一区切りまで蒸し返されません**
- 💡 「**設定に反映して**」と言えば、いつでもこの提案が出ます

💡 「**片づけて**」「**見直して**」と言うと、たまったものが一度に出ます（＝一区切りの整理の**詳しい形**）。

### 🎮 会話中に使える言葉

**案について**：`1と3を混ぜて` ／ `2は舞台だけ残して` ／ `4はとっておく` ／ `5はやめ` ／ `もう3案` ／ `出し直し` ／ `もっと詳しく` ／ `3行で`
**確認**：`宿題` ／ `とっておく` ／ `決まったこと` ／ `まだ入れてない` ／ `片づけて` `見直して` `整理して`
**決める**：`◎` `○` `△` を付ける ／ `〈名前〉を戻して`
**設定を直す**：`設定に反映して` `設定を直して`（➔ `/fal-setting` へ。⚠️ 許可するまで直されません）
**進行**：`質問やめて`（AIからの質問を止める。再開は `質問していい`）／ `収束` `まとめて`
**チャットモード**：`チャットモード` `ふつうに話したい` ／ 戻るのは `戻る` `案を出して`
**メモ**：`メモを見て` ／ `メモに書いて`
**つなぐ**：`トリック錬成`（➔ `/fal-twist` へ）／ `磨き` `ポリッシュ`（**このまま**、あらすじの文を1箇所ずつ直す形に切り替わります）／ `設定に反映`（➔ `/fal-setting` へ）

💡 **記法を覚える必要はありません。**自然文で書けば同じ意味に解釈されます。

### ✨ 有効活用の仕方

- **迷ったら ⭐おすすめに乗る。**理由が1行付いているので、違うと思ったらそこを突けば覆せます
- **AIの答えが薄いと思ったら、遠慮なく突く。**「本当にそうなるか」「その人ならこうするのでは」——この突きがいちばん話を良くします
- **実際にあった事例を持ち込む。**実在の技術・事件・記録に載る案は、作り物の型より強くなります
- **「終わり」と言えばいつでも止まります。**状態ファイルは毎ターン更新されているので、次回はそのまま続けられます

## 3. `/fal-twist` （トリック錬成）

**役割**：どんでん返し・叙述トリック（＝文章だからこそ成り立つ、読者の思い違いを使った仕掛け）を、**真相のほうから逆算して作る。**

⭐ **良い仕掛けには「驚き」と「納得」の両方が要ります。**驚きだけなら反則に見え、納得だけなら平坦になります。この2つを両立させるための道具です。

**使い方**：チャット欄で `/fal-twist` と入力します。`brainstorm/` に既存セッションがあれば、「**そのセッションにつなぐ／仕掛けだけ単体で作る**」を1問だけ聞かれます。

### 🔄 進み方（5つ。行き来してかまいません）

```text
裏切る思い込みを決める → 型を選ぶ → 三つの層を組む → 手がかりを配る → ずるくないかを見る
```

1. **裏切る思い込みを決める** … 仕掛けの土台は、読者が無意識に置いている前提です（「語り手は本当のことを言っている」「この二人は別人だ」）。4〜6個＋逆張り案1個が出ます。⚠️ **どれを裏切るかが決まるまで、型選びには進みません。**
2. **型を選ぶ** … 型カタログから合うものを3〜5個。組み合わせも可（「人数の思い違いを主軸に、時間の思い違いを補助で」）。
3. **三つの層を組む** … **本当に起きたこと ➔ 読者に見せるもの ➔ 目をそらす仕掛け**。⭐ **必ず真相の側から組みます。**
4. **手がかりを配る** … 1つにつき「初めて読むときどう見えるか／二度目に読むと何を意味するか／どこに置くか／どう紛れさせるか」。
5. **ずるくないかを見る** … 下記。

### 🔍 「ずるくないかを見る」＝5つの問いかけ

⭐ **見るのは「作った側」ではなく「読む側」です。**`/fal-brainstorm` の初読メモと同じ考え方で、**ここまでの話を知らない人がどう読むか**だけを見ます。

- **初めて読む人へ** … 真相にたどり着ける材料は、本文に置いてあるか。後から出していないか
- **二度目に読む人へ** … 真相を知って読み返したとき、食い違う記述はないか。逆に「二度目に光る」記述はあるか
- **納得は残っているか** … 驚きだけで納得が置き去りになっていないか
- **どこかで読んだ形になっていないか** … 型カタログのままになっていないか
- **人物が壊れていないか** … 仕掛けの都合で人の動きが不自然になっていないか（⚠️ **いちばん多い失敗**）

### 🚫 やらないこと（見るところで落とされます）

- **地の文で嘘を書くこと** … 本当のことだけを、足りない形・二通りに読める形で置き、**読者が自分で読み違える**ようにします（語り手自身が事実を取り違えている型を使うときだけ例外。その場合は真相ファイルにそう書きます）。
- **手がかりが1つだけ／直前にしか無いこと** … 後出し扱いで落とされます。**最低3つ・散らして置く**のが原則。
- **二度目に意味が変わらない手がかり** … それは手がかりではありません。
- **型をそのまま当てはめること** … ⚠️ **必ず「この話でしか成り立たない一点」を足します。**⭐ 実際にあったこと・実在の技術に載る形にできないかを先に考えます（作り物の型より強くなるため）。

### 📁 作られるファイル

- `brainstorm/<セッション名>_真相.md` … **このワークフロー固有の成果物。**三つの層／手がかり／明かし方／見た結果／やめたけれど光る案
- 状態ファイル `brainstorm/<セッション名>.md` は**新しく作られません。**既存の1本に書き足され、完成時に真相ファイルへの参照が1行足されます

### 🎮 固有の言葉

`/fal-brainstorm` 共通の言葉（`宿題` ／ `とっておく` ／ `片づけて` ／ `まだ入れてない` ／ `収束` `まとめて`）に加えて、

- **「二度目テスト」** … いまの設計で「二度目に読む人へ」だけを即座に見る
- **「型カタログ」** … トリックの型一覧を出す
- **「反則チェック」** … 地の文の嘘・後から出した手がかり・二度目に意味が変わらない手がかり、の3点だけを即座に見る

💡 **型は番号ではなく名前で呼びます。**「人数の思い違いで行こう」で通ります。

### 🔗 `/fal-brainstorm` とのつなぎ方

**その場でつなぐ**：ブレスト中に「**トリック錬成**」と言うだけです。セッションは中断されず、話の流れも切れません。「この案、仕掛け次第で化けそう」と思った瞬間に踏み込めます。

**後日つなぐ**：`/fal-twist` を起動すると既存セッションが見つかり、「つなぐ／単体で作る」を1問だけ聞かれます。**「つなぐ」**を選べば、あらすじを説明し直す必要はありません（「絶対の制約」と「決まったこと」がそのまま引き継がれます）。

> 💡 万一その場でつながらないときは、こう言えば確実です。
> `.agents/skills/twist-trick-forge/SKILL.md に従って、このセッションにつないでトリック設計を始めてください`

**切り替えるタイミング**

- ⭐ **向くのは、犯人・動機・舞台といった骨格が一通り決まったあと。**裏切る思い込みを洗い出すには、裏切る対象の話が要るためです
- **早すぎる場合**（テーマしか決まっていない）は、まず `/fal-brainstorm` を2〜3周させたほうが結果的に早く進みます
- **戻ってよい**：「この仕掛けを成立させるには動機を変えたい」と気づいたら、ブレスト側に戻って動機だけ出し直せます。**行き来は前提の設計です**

**単体で始めるほうがよい場合**

- 既存の話と無関係に、**仕掛けだけ試作**したいとき
- 別作品・短編用の仕掛けを考えたいとき（既存セッションの制約に引きずられないため）
- すでにできている仕掛けを持ち込んで、**見てもらうだけ**にしたいとき

### ✨ 有効活用の仕方

- **仕掛けの壁打ち:** ラストにインパクトが欲しいとき、専門の観点から詰められます。
- **完成済みの仕掛けの検査にも使える:** ゼロから作るだけでなく、すでにある仕掛けを持ち込んで「二度目テスト」「反則チェック」だけ回す使い方も有効です。
- **型をそのまま採らない:** カタログは引き出しであって答えではありません。⭐ **「この話だけの一点」を足せたかどうかが、面白さの分かれ目です。**

## 4. `/fal-setting` （設定の作業台）

**役割**：設定を**作る・直す・確かめる・畳む**。⭐ **`02_設定/` に書き込めるのは、このコマンドだけです。**

**使い方**：`/fal-setting 天川光の占いの設定を変えたい` のように一言添えて起動します（引数なしでも可）。ブレストやトリック錬成の途中なら「**設定に反映して**」と言うだけでつながります（**貼り直しは不要**）。

⭐ **中心はひとつだけ。AIが案を並べ、あなたが選ぶ。選ぶまでファイルは変わりません。**

### 🛠 引き受ける5つの作業

- **新規作成** … まだ無い設定（キャラ・場所・道具・乗り物・世界観・用語）を作り、しかるべきフォルダに置く
- **書き換え・深掘り** … 既にある設定の一部を差し替える。決まっていない箇所を決める
- **整合チェック** … 設定同士の矛盾・用語の揺れ・項目の抜けを洗い出す
- **削除・統廃合** … どこからも使われていない設定、重複した設定を畳む
- **反映** … ほかのコマンドで決まったことを、設定ファイルに落とす

💡 **どれかを指定する必要はありません。**一言告げれば、どの作業かはAI側で見分けます。

### 🔄 進み方

1. **場所を指す** … 3通りのどれでも通ります。
   - **文をそのまま貼る** ／ **名前で言う**（「光の占いのところ」） ／ **「候補」と言う** ➔ 直したほうがいい場所が理由付きで6つ出ます
2. **案が出る** … **違う方向へ4〜6案＋逆張り案1個。**各案に「**その設定にすると話がどう変わるか**」が1行付きます
3. **選ぶ** … 自然文でかまいません（「1と4を混ぜて」「もっと軽く」「別案」）
4. **決めると、その場で反映** … 同時に下の4行と3点が出ます
5. 1〜4を繰り返し、「終わり」で閉じます

💡 **番号（①②③）は振られません。**`/fal-brainstorm` と同じで、**短い名前とその一文の引用**で場所を指します。

### ⚠️ 決めたあとに必ず出る4行と3点

```text
✅決めた：…
どこに響くか：…
📝目安を直した：…
📌今回 AI が足した設定：…（無いときも「なし」と出ます）
```

そのうえで3点が報告されます。

1. **すぐ隣の取り残し** … 書き換えた記述の直前・直後・括弧書き・見出しが、古い前提のまま残っていないか。⭐ **ここがいちばん見落とされます**
2. **ほかのファイルへの影響** … 別の設定ファイル・一覧ファイル・用語集と食い違わないか（固有名で検索して確かめます）
3. **新しく出てきた宿題** … 次に決める候補が1つだけ挙がります

⚠️ 3つとも無いときは「**どこにも響かない**」と書かれます。黙って飛ばされることはありません。

### 🚫 このコマンドが触らないもの

- `brainstorm/<セッション名>.md` ／ `_あらすじ.md` ／ `_真相.md`
- `synopsis/<日付>_<短い名前>.md`

⚠️ 食い違いを見つけても**報告するだけ**です。⭐ **あらすじの文そのものを直したいときは、`/fal-brainstorm` で「磨き」と言ってください。**
（設定＝こちら、文＝ブレスト側、という分担です。同じファイルを2つのコマンドが書くと、どちらが新しいか分からなくなるため）

### 📁 書き足す先

- `02_設定/` … キャラクター／場所・建物／道具・アイテム／乗り物／サイドストーリー
- `00_作品コンセプト＆トータル設定/` … concept.md ／ 世界観設定.md ／ 用語集.md ／ 文体のガイドライン.md
- ⭐ **新しいファイルを作ると、一覧ファイル（`全キャラクターリスト.md` など）にも足されます。**忘れると誰からも見つからなくなるためです

⚠️ **消すときは、必ず先に「どのファイルから参照されているか」が一覧で出ます**（HARD-GATE）。参照が残っているものが黙って消されることはありません。

### 🎮 会話中に使える言葉

**場所**：`候補`（直したほうがいい場所を6つ）／ `いまの全文`
**案**：`1と4を混ぜて` ／ `1をもっと軽く` ／ `別案` ／ `もっと詳しく` ／ `3行で`
**戻す**：`〈名前〉を戻して`（直す前に戻す）
**作業**：`作って` ／ `矛盾を見て` `点検して` ／ `もう要らない` `畳んで` ／ `設定に反映して`
**確認**：`宿題` ／ `とっておく` ／ `決まったこと` ／ `片づけて` `見直して`
**設定について**：`足かせは？`（いまの案を狭めている設定を1つ名指し。⚠️ 外すかどうかは決められません）
**つなぐ**：`ブレストに戻す`（➔ `/fal-brainstorm`）／ `トリック錬成`（➔ `/fal-twist`）／ `あらすじ`（➔ `/fal-synopsis`）
**終わり**：`終わり` `保存`

### ✨ 有効活用の仕方

- **決めた設定の置き場所を迷わない:** どのフォルダのどの雛形に従うかはAI側が見ます。命名規則も既存に合わせられます。
- **消す判断を安全にする:** 「もう要らない」と言えば、まず**参照元の一覧**が出ます。消してから「あれ、どこかで使っていた」に気づく事故を防げます。
- **矛盾を溜めない:** `/fal-synopsis` の「引っかかり置き場」や `/fal-brainstorm` の宿題で溜まった食い違いは、ここで一件ずつ片づけられます。
- **AIの思いつきが混ざらない:** 決定を書いたターンには `📌今回 AI が足した設定` が必ず出ます。無いときも「なし」と明示されます。

## 5. `/fal-prompt` （プロンプト・ディスパッチャー）

- **使用目的:** プロンプト集（`01_free_memo/プロンプト集.md`）の中から、現在の目的に最適なテンプレートをAIが自動で選び、`[ ]` を埋めて実行してくれます。
- **使い方:** やりたいことを一言添えて起動します。

  ```text
  /fal-prompt 第5章の伏線が回収できてるか見て
  ```

  引数なし（`/fal-prompt` だけ）でも起動でき、その場合は「今日は何をしますか？」と、よく使う入口を添えて1問だけ尋ねられます。

### 🔄 動作の流れ

1. **プロンプト集を読み直す** … 記憶ではなく毎回ファイルを読むため、**編集した内容が即座に反映されます**。
2. **テンプレート選定** … 依頼を「工程」に分類し、⭐推奨＋理由＋次点の形で提示。
3. **対象の特定** … 参照・編集するファイルのパスを明示して確認（IDEで開いているファイルが第一候補になります）。
4. **パラメータ補完** … `[ ]` を埋めます。AIが推定できる箇所は勝手に埋め、**推定した箇所は「（推定）」と明示**されます。質問は本当に判断できないものだけ、1ターン1問。
5. **部品スニペットの付与** … 「推測と創作を分けて書く」「ボツ案も列挙する」などの共通条件を文脈に応じて最大3つまで追加（表を使わないルールは常時付与）。
6. **完成プロンプトの提示と承認** … 全文が ```text ブロックで提示され、`[このまま実行]` `[ここを直したい]` `[別のテンプレートにする]` を選びます。
7. **実行 ➔ フィードバック** … 実行後、「このテンプレートを追加してはどうか」「この条件行を足してはどうか」という**プロンプト集への追記提案**が出ます。

### 🎮 操作コマンド

- **「別のテンプレート」** … 選定をやり直し、次点以下を提示させる
- **「プロンプトだけ」** … 実行せず、完成プロンプトの提示で停止（**他のAIツールに貼り付けたいとき**に便利）
- **「そのまま実行」** … 承認ステップを省略して即実行（提示自体は必ず行われます）
- **「一覧」** … プロンプト集のクイックインデックスを表示
- **「追記して」** … 追記提案をプロンプト集に反映

### ✨ 有効活用の仕方

- **日常タスクの効率化:** 文章の校正、設定の整理、特定要素のチェックなど、「プロンプトを探してコピペする」手間を省きたい単発タスクに最適です。
- **自動ナビゲーション:** 依頼内容が重厚なプロット作成やトリック設計に該当する場合は、AIが `/fal-brainstorm` や `/fal-twist` への切り替えを1問で提案してくれます（勝手には切り替わりません）。判断基準は「**複数ターンで分岐を記録しながら煮詰める作業なら委譲、1〜2ターンで完結するならこのまま実行**」。
- **使うほど育つ:** プロンプト集にテンプレートを追加すれば、そのぶん `/fal-prompt` の対応範囲がそのまま広がります。**章番号の変更・章の並べ替え・名称変更をしてもメンテ不要**（AIは番号ではなく内容で照合するため）。
  - ⚠️ **唯一メンテが必要なのは、`01_free_memo/プロンプト集.md` を移動・改名したとき**です。その場合は `.agents/skills/prompt-dispatcher/SKILL.md` と `.agents/workflows/fal-prompt.md` の2箇所を修正してください。

## 6. `/fal-refill-free_memos` （フリーメモ補充）

- **使用目的:** `01_free_memo` フォルダの `free_memo_01.md` 〜 `free_memo_10.md`（白紙メモを常に10個）と、`01_free_memo/fal用メモ/` の `fal用_作品案メモ①.md` 〜 `⑤.md`（常に5個）のうち、**存在しない番号のファイルを自動生成**します。
- **使い方:** チャット欄で `/fal-refill-free_memos` と入力して起動します。
  コマンドを使わず、PowerShell で直接スクリプトを叩いても結果は同じです。

  ```powershell
  [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $env:PYTHONUTF8=1; python .agents/scripts/refill_free_memos.py
  ```

  ※ PowerShell と Python が前提です。文字化け防止のため、UTF-8指定を必ず前置してください。
  ※ カレントディレクトリはプロジェクトルート（`idea_of_novel/`）にしてください。

### ⚠️ 正確な挙動（誤解しやすいポイント）

このスクリプトは **メモの「中身」を一切見ません**。判定しているのは**ファイル名の有無だけ**です。

- `free_memo_01.md` 〜 `free_memo_10.md`、および `fal用メモ/fal用_作品案メモ①.md` 〜 `⑤.md` のうち、**存在しない番号だけ**を新規作成します。
- **既存ファイルは絶対に上書きしません。** 何度実行しても安全です（書きかけのメモが消える心配はありません）。
- 対象は **free_memo は 01〜10、fal用_作品案メモ は ①〜⑤ の固定範囲**。それ以降は作られません。
- 作成されるファイルには、「このメモはアイデアであって決定事項ではない」旨のAI向け注意書きが最初から入っています。

### 📝 正しい運用（ここが肝心）

上記のとおり**ファイル名の有無で判定する**ため、メモを使ったら**リネームするか、別フォルダへ移動する**のが正しい使い方です。

- ✅ `free_memo_03.md` に書いた内容が固まった ➔ `01_free_memo/その他/○○について.md` などへ**改名・移動** ➔ `/fal-refill-free_memos` で 03 が補充される
- ❌ `free_memo_03.md` という名前のまま中身だけ書き込む ➔ ファイルは存在するので**補充対象にならず**、白紙ストックが減ったままになる

### ✨ 有効活用の仕方

- **執筆環境の整備:** アイデア出しでフリーメモを消費した後に実行することで、常に10個の白紙メモ（＋fal用_作品案メモ5本）をストックしておけます。手作業でファイルを作る煩わしさがなくなります。
- **定期実行が向いています:** 上書きの危険がないので、「作業の区切りごとにとりあえず叩く」運用で問題ありません。

## 💡 状況に応じた使い分けのコツ

- **「とにかく面白い話の骨がほしい」「いまのあらすじ、つまらない気がする」** ➔ `/fal-synopsis`
- **「新しい話を考えたい」「あらすじをゼロから練りたい」「辻褄を合わせたい」** ➔ `/fal-brainstorm`
- **「トリックを思いつきたい」「結末に強烈などんでん返しを入れたい」「この仕掛け、ずるくないか見てほしい」** ➔ `/fal-twist`
- **「この設定を決めたい」「キャラを作りたい」「設定に矛盾がないか見て」「この設定はもう要らない」** ➔ `/fal-setting`
- **「ちょっと文章を見てほしい」「伏線の抜け漏れチェックなど、特定の作業を頼みたい」** ➔ `/fal-prompt`
- **「メモ帳（MDファイル）が足りなくなった」** ➔ `/fal-refill-free_memos`

> 💡 **`/fal-synopsis` と `/fal-brainstorm` の分かれ目：** **骨がつまらない**と感じているなら前者、**骨はいいが辻褄が心配**なら後者です。順番を逆にすると、面白くない話をきれいに整えるだけになります。

> 💡 **`/fal-brainstorm` と `/fal-setting` の分かれ目：** 直したいのが**あらすじの文**なら前者（「**磨き**」と言えば1箇所ずつ直す形に切り替わります）、**設定ファイルの中身**なら後者です。

> 💡 **「案はもう足りている。整理したいだけ」というときは、まだ `/fal-setting` ではありません。** `/fal-brainstorm` のまま「**片づけて**」と言ってください。案を1つに絞りきる前に溜まったものを整理するのは、ブレスト側の仕事です。

### 🔗 実践的な併用パターン

- **新作を立ち上げる:** `/fal-synopsis` で面白い骨を作る ➔ 「**辻褄を合わせたい**」で `/fal-brainstorm` につなぐ ➔ 「収束」で `summary.md` を得る ➔ 「**トリック錬成**」で `/fal-twist` につなぎ、仕掛けを作る ➔ 「**設定に反映して**」で `/fal-setting` につなぎ、決まったことを `02_設定/` に落とす ➔ `/fal-prompt` で検証のテンプレートを回して仕上げる。
  - ⭐ **同じ状態ファイルの上で動くので、途中でコマンドを打ち直す必要すらありません。**「トリック錬成」「磨き」「設定に反映して」と言うだけでつながります。
- **文を詰めたい:** `/fal-brainstorm` の途中で「**磨き**」と伝えれば、そのまま1箇所ずつ直す形に切り替わります。案の貼り直しは不要で、「絶対の制約」と「決まったこと」もそのまま引き継がれます。⚠️ **設定ファイルを直すのは `/fal-setting` の仕事**なので、そちらは「設定に反映して」で渡します。
- **既存プロットの弱点を潰す:** `/fal-prompt` で矛盾チェック ➔ 設定の食い違いなら `/fal-setting` で1件ずつ片づける ➔ 骨格そのものが弱いなら `/fal-synopsis` に戻って作り直す。
- **迷ったらまず `/fal-prompt`:** 依頼が重ければ AI 側が `/fal-synopsis` `/fal-brainstorm` `/fal-twist` `/fal-setting` を提案してくれるため、入口として使って問題ありません。

### 🏷️ 命名規則：`fal-` 接頭辞

**このプロジェクトのワークフローは、コマンド名をすべて `fal-` で始めます**（fal＝ファルコン）。

**目的：** Claude Code や各種スキル集には `brainstorm` `prompt` といった一般名のコマンドが多数あり、そのまま使うと**どれが本プロジェクトのものか判別できなくなる**ためです。`/fal-` まで打てば候補が6つに絞られる、という実用上の利点もあります。

#### ファイル名とコマンド名の対応

**両環境とも、ファイル名（拡張子を除く）がそのままコマンド名になります。**

| 環境 | フォルダ | ファイル名 | できるコマンド |
|---|---|---|---|
| Antigravity | `.agents/workflows/` | `fal-twist.md` | `/fal-twist` |
| Claude Code | `.claude/commands/` | `fal-twist.md` | `/fal-twist` |

- 余計な接頭辞（`workflow-` など）は付けません。付けるとその分までコマンド名に入ります。
- **両側のファイル名を同じにしておけば、コマンド名も自動的に揃います。**

#### 改名するときに直す箇所

1. `.agents/workflows/fal-〇〇.md` のファイル名
2. `.claude/commands/fal-〇〇.md` のファイル名
3. 両ファイル内の見出しと相互参照（橋渡し側は `.agents/workflows/fal-〇〇.md` を指しています）
4. このドキュメント
5. `.agents/skills/*/SKILL.md` の `description`（起動コマンド名が書かれています）と `01_free_memo/プロンプト集.md`

**最後にプロジェクト全体を旧名で検索し、取りこぼしを潰してください。** 特に5は見落としやすい箇所です。

> 💡 **ファイル名を変えたら Antigravity のウィンドウを再読み込みしてください。** ワークフロー一覧はキャッシュされることがあり、再読み込みまで新しい名前が `/` メニューに出ないことがあります。

### 📐 ファイル参照のルール（編集時の注意）

手順書・スキル内でテンプレートや参照資料を指すときは、**プロジェクトルートからのパスを書いてください**（例：`.agents/skills/twist-trick-forge/trick-catalog.md`）。

`templates/` `reference/` のような、実在しないフォルダを前提にした相対表記は、AIがファイルを見つけられず途中で止まる原因になります（過去に4ファイル・6箇所で発生し、修正済み）。
