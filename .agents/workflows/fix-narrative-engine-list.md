# ナラティブエンジンリストの自動修正ワークフロー

## 前提条件
- 修正対象となる既存のリストファイル（例：`06_narrative_engine_list/list_a_negative_200.md`）がユーザーから指定されていること
- フォーマット規則は `06_narrative_engine_list/format_narrative_engine_list.md` を厳密に守ること

## 生成品質における最重要ルール
- 各項目の「定義」「効果」「例」は、過去の抽象的・簡素な記述を見直して具体化すること。文字数の目安として、**『定義』は80文字以上、『効果』は60文字以上、『例』は90文字以上**を目指し、簡潔かつ情報密度を高くリライトすること。（参考: `list_d_last_scene_180.md` の品質と深み）
- ただし、「定義」「効果」「例」の文字数に関しては、簡潔に分かりやすくまとまっており、他の説明がなくても十分なものに関しては、文字数が規定より短くても良い。
- **【重要：世界観の遵守】** リライトするリストの内容は、基本的に小説『ハヤブサ探偵事務所の独特なやり方』の雰囲気、世界観に合った内容にすること。ハードボイルドすぎる展開、大規模な敵組織の登場、ヤクザのような抗争、武器として銃を使う、といった設定は使用しないこと。
- **「例」には原則としてハヤブサ探偵事務所のキャラクター（隼、亜紀人、望など）を登場させ**、彼らの具体的な行動やセリフを交えた作中世界に即したシーンを描写すること。
- **【重要：キャラ崩壊の防止】** ただし、鬱・イヤミス展開や一般的なサスペンスのプロットなど、既存キャラクターの設定や性格に著しくそぐわない場合（例：隼が不当に悪事に加担する、亜紀人が見知らぬ家族構成になる等）は、無理に既存キャラクターを当てはめないこと。その場合はキャラ崩壊（OOC）を防ぐため、「探偵A」「妻B」「友人C」のような**架空の匿名キャラクター（A、B等）を使用して例文をリライトする**こと。
- **【重要：テーマ特化型フォーマットの尊重と変更許可】** 修正対象のリストが通常の「例:」と異なるテーマ特化型の例文サブ形式を用いている場合（例：「王道の予感」「裏切り展開」のような2段構成の例文形式）は、その形式を**尊重・維持しながらリライトする**こと。また、修正の過程でリストのコンセプトをより明確に伝えるためにフォーマットを改善する必要があると判断した場合は、フォーマット規則ファイルの基本構造（見出しレベル・箇条書きなど）を維持しつつ、「例:」の内部表現は柔軟に変更して良い。
  ```
  * 王道の予感：「[読者が期待する定番展開の具体的なシチュエーション]」
  * 裏切り展開：[その展開固有の、ユニークな裏切り方の描写]
  ```

## 手順
このワークフローは、対象リストの項目数が多い場合のLLMの出力制限やタイムアウトを回避するため、**対話型のステップ・バイ・ステップ方式**で進めます。

### 1. 対象ファイルの分析（内部処理）
- ユーザーから指定された既存ファイルを読み込み、修正が必要な項目数や全体のボリュームを把握する。
- 1回（1ターン）で処理するチャンクを**「20〜30項目」**に制限するよう計画を立てる。

### 2. チャンク単位での直接編集と進捗報告（対話型処理）
以下のステップで、ファイルの一部分（20〜30項目）を修正し、ユーザーに確認を取りながら進める。
1. **直接編集ツールの実行**:
   - `multi_replace_file_content` や `replace_file_content` ツールを使用して、対象ファイルの指定チャンク部分のテキストを直接書き換える。
   - ※一時的なPythonスクリプトの作成はエラーの原因になりやすいため、原則として使用せず直接ファイル編集ツールを用いること。
2. **ユーザーへの進捗報告と確認**:
   - チャンクの修正が完了するごとに、一度処理を停止してユーザーに進捗（例：「No.1〜20の修正が完了しました。続けて21〜40を処理してよいですか？」等）を報告する。
   - ユーザーからの継続指示（承認）を待ってから、次のチャンクの処理を開始する。
   - ※通知について：ユーザーが待ち時間に別の作業をしている可能性があるため、進捗報告時はチャットで明確に返信を促すメッセージを出力し、システム通知が確実にユーザーに届くようにする。

### 3. ジャンルタグの自動修正と最終報告
1. **ジャンル修正の実行**: 全ての項目の修正が完了し、ユーザーから次のステップへの移行許可が出た後、`/fix-genre-tags` または同等の処理を実行し、ジャンルタグに不整合（《》の閉じ忘れや独自のタグ使用など）がないか確認・修正する。
2. **最終報告**: ユーザーに対し、「指定されたリストの修正、キャラ崩壊防止への対応、ジャンルタグの修正手続きが全て完了したこと」を通知する。
