# ナラティブエンジンリストの一括作成ワークフロー

## 前提条件
- リストの種類（章のアルファベット）、テーマ、総数（基本は200個）をユーザーから指定されていること
- 生成先は `06_narrative_engine_list/` 配下の指定ファイルであること
- フォーマット規則は `06_narrative_engine_list/format_narrative_engine_list.md` を厳密に守ること

## 生成品質における最重要ルール（追加）
- 各項目の「定義」「効果」「例」は、シンプルで抽象的な短文で済ませず具体化すること。文字数の目安として、**『定義』は80文字以上、『効果』は60文字以上、『例』は90文字以上**を目指し、簡潔かつ情報密度を高く作成すること。（参考: `list_d_last_scene_180.md` の品質と深み）
- ただし、「定義」「効果」「例」の文字数に関しては、簡潔に分かりやすくまとまっており、他の説明がなくても十分なものに関しては、文字数が規定より短くても良い。
- **【重要：世界観の遵守】** 作成するリストの内容は、基本的に小説『ハヤブサ探偵事務所の独特なやり方』の雰囲気、世界観に合った内容にすること。ハードボイルドすぎる展開、大規模な敵組織の登場、ヤクザのような抗争、武器として銃を使う、といった設定は使用しないこと。
- **「例」には原則としてハヤブサ探偵事務所のキャラクター（隼、亜紀人、望など）を登場させ**、彼らの具体的な行動やセリフを交えた作中世界に即したシーンを描写すること。
- **【重要：キャラ崩壊の防止】** ただし、鬱・イヤミス展開や一般的なサスペンスのプロットなど、既存キャラクターの設定や性格に著しくそぐわない場合（例：隼が不当に悪事に加担する、亜紀人が見知らぬ家族構成になる等）は、無理に既存キャラクターを当てはめないこと。その場合はキャラ崩壊（OOC）を防ぐため、「探偵A」「妻B」「友人C」のような**架空の匿名キャラクター（A、B等）を使用して例文を作成する**こと。
- 200個のリストを作成する際、質の低い無味乾燥な量産を避けるため、まずは**「20個の極めて詳細で高品質なベース概念（定義・効果・例）」**を作成し、それに「孤独な」「色褪せない」などの接頭語やバリエーションを掛け合わせて200個のリストに増幅・展開する手法を強く推奨する。
- **【重要：テーマ特化型フォーマットの許可】** リストのテーマや内容によっては、通常の「例:」に加えて、またはそれに代えて、テーマに即した独自の例文サブ形式を使用して良い。たとえば「王道展開からの裏切り」をテーマにするリストでは、例文を以下のような2段構成にすることが推奨される：
  ```
  * 王道の予感：「[読者が期待する定番展開の具体的なシチュエーション]」
  * 裏切り展開：[その展開固有の、ユニークな裏切り方の描写]
  ```
  このような形式変更は、リストのコンセプトをより明確に伝えるために有効な場合は積極的に取り入れること。フォーマット規則ファイルの基本構造（見出しレベル・箇条書きなど）を維持しつつ、「例:」の内部表現は柔軟に変更して良い。

## 手順
このワークフローは、作成する項目数が多い場合のLLMの出力制限やタイムアウトを回避するため、**対話型のステップ・バイ・ステップ方式**で進めます。

### 1. 計画の立案と出力形式の確認（内部処理）
- ユーザーに指定されたテーマ（例：「流山の秋」「鳥」「ことわざ」など）と出力数（例：200個）を確認する。
- フォーマットファイル（`format_narrative_engine_list.md`）の規則（見出し4、名称＋ジャンル、定義・効果・例の箇条書き等）と、**同ファイルの中にある「ジャンル選択リスト」**を再確認する。
- **重要**: 見出しに付与するジャンル（《》で囲む部分）は、必ず「ジャンル選択リスト」に明記されている既存の候補から選び、一言一句違わず指定すること。候補にない独自のジャンル名や、勝手な表記揺れ・派生語（例：「心理学・情報戦」や「人間ドラマ・愛情」など）は決して作成・指定しないこと。
- 1回（1ターン）で処理するチャンクを**「20〜30項目」**に制限するよう計画を立てる。

### 2. チャンク単位での直接作成と進捗報告（対話型処理）
以下のステップで、ファイルの一部分（20〜30項目ずつ）を作成し、ユーザーに確認を取りながら進める。
1. **直接編集ツールの実行**:
   - 新規作成の場合は `write_to_file` ツールを使用し、2回目以降の追記の場合は直接ファイル編集ツール等を使用してファイルの末尾に生成した内容を追記する。（一時的なPythonスクリプトの作成はエラーの原因になりやすいため、原則として使用せず直接ファイル編集ツールを用いること）
2. **ユーザーへの進捗報告と確認**:
   - チャンクの作成・追記が完了するごとに、一度処理を停止してユーザーに進捗（例：「No.1〜20の作成と追記が完了しました。続けて21〜40を作成してよいですか？」等）を報告する。
   - ユーザーからの継続指示（承認）を待ってから、次のチャンクの処理を開始する。
   - ※通知について：ユーザーが待ち時間に別の作業をしている可能性があるため、進捗報告時はチャットで明確に返信を促すメッセージを出力し、システム通知が確実にユーザーに届くようにする。

### 3. ジャンルタグの自動修正と最終報告
1. **ジャンル修正の実行**: 全ての項目の作成が完了し、ユーザーから次のステップへの移行許可が出た後、`/fix-genre-tags` または同等の処理を実行し、ジャンルタグに不整合（《》の閉じ忘れや独自のタグ使用など）がないか確認・修正する。
2. **最終報告**: ユーザーに対し、「指定されたリスト（全〇〇個）の作成と追記、ジャンルタグの修正手続きが全て完了したこと」を通知する。
