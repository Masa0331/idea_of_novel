# ピンポイント磨き上げ（修正＆深掘り）

## 概要

すでにある1案を、**1箇所ずつ・選択肢駆動で仕上げる**。

**中核原理：AIは選択肢を並べるだけで、本文を書き換えない。本文が変わるのは、ユーザーが確定操作をした瞬間だけである。**

姉妹スキルとの役割分担：

- `mystery-deep-brainstorm`（`/fal-brainstorm`）… 複数案を**発散**させる（案を増やす）
- `twist-trick-forge`（`/fal-twist`）… 真相から逆算して仕掛けを**設計**する
- 本スキル（`/fal-polish`）… 確定した1案を**収束**させる。文単位の修正と、未確定情報の深掘り

扱う作業は2種類だけ：

- **🔧 修正** … すでに書かれている文の**表現・内容を差し替える**。本文を上書きする
- **🔍 深掘り** … まだ決まっていない情報を**決める**。本文の下に注釈として足す

<HARD-GATE>
1. **確定前に本文を書き換えてはならない。** 「選択肢の提示 → ユーザーの確定操作」を必ず経る。「明らかに良くなるから」「ユーザーの意図は明白だから」は例外にならない。
2. **1ターン1箇所。** 複数箇所を同時に直さない。ユーザーが複数挙げたら、優先順を1問で確認して1つずつ処理する。
3. **選択肢は通常6個＋ワイルドカード2個を必ず出す。** 3つや4つで済ませない。出し切れないと感じたら、それは箇所の切り出しが大きすぎるサイン。箇所を絞り直す。
</HARD-GATE>

## 状態管理

会話コンテキストの記憶に頼らず、**毎ターン**作業ファイルを更新する。雛形はこのスキルと同じフォルダ（`.agents/skills/pinpoint-polish/`）の `polish-sheet-template.md`。

- `brainstorm/<セッション名>_polish.md` … 作業ファイル。本文（最新）／注釈／変更履歴／不採用ストックを持つ

終了時に、ユーザーが指定したフォルダへ日本語タイトルを付けて**移動**する（作業ファイルは残さない。履歴は最終ファイルに全部入っている）。

## フェーズ構成

### フェーズ0：素材の取り込み（1ターン）

1. 起動時に本文が渡されていればそれを使う。なければ「磨きたい案を貼ってください」と**1問だけ**尋ねる
2. `/fal-brainstorm` から接続した場合は、いま扱っている案を本文として持ち込み、`brainstorm/<セッション名>.md` の「絶対の制約」と「決まったこと」を引き継ぐ（**貼り直しは不要**）
3. 取り込んだら、本文に **番号アンカー（①②③…）を振って再表示**する。以後、箇所の指定はこの番号で行える
4. 同じターンでフェーズ1の2択も出す（取り込みだけでターンを消費しない）

嗜好プロファイルを引き継いだ場合は、選択肢の生成時に必ず反映する。

### フェーズ1：モード選択（毎ラウンドの入口）

```
次はどうしますか？
　🔧 修正 … 書かれている文を差し替える
　🔍 深掘り … 決まっていないことを決める
　✅ 終了 … 保存して終わる
```

ユーザーが最初から「③を修正」のように箇所まで言った場合は、この2択を飛ばしてフェーズ2を省略し、直接フェーズ3へ進む。**分かりきった確認でターンを使わない。**

### フェーズ2：箇所の特定

指定の方法は3通り。どれで来ても受け付ける：

- **番号** … 「③」「④の後半」
- **文を貼る** … 「罰が当たったのかもしれない」
- **「候補」** … AIが直すべき箇所を提案する（下記）

「候補」と言われたら、修正・深掘りの候補を**理由付きで6つ**挙げる：

```
⭐直す候補（番号で選んでください）

1 🔧 ③「罰が当たったのかもしれない」
　　直接的すぎて、神罰ミスリードが読者に見透かされる
2 🔍 ④「隼が知らないきょうだい」の正体
　　未確定。ここが決まらないと①の通数も動かせない
（6つまで）
```

#### 箇所が大きくても、絞り込みの確認で1ターン使わない

番号だけ（「③」）を指定された場合は、**その中で最も具体的な要素——引用符でくくれる一文、固有名詞、数値——を対象と見なして、そのまま選択肢を出す。** 聞き返さない。

代わりに、**冒頭で前提を1行明示する**。読み違えていればユーザーがその場で言い直せる：

```text
📍対象: ③のうち「罰が当たったのかもしれない」
　　　　（③には〈仕掛けの設計〉〈この一文〉〈誤解か韜晦かの含み〉が含まれます。
　　　　　別の部分なら言ってください）
```

**1問で絞るのは、どれを対象にしても選択肢が濁るときだけ。** 判定基準は「6案＋W2を、互いに異なる軸で出し切れるか」。出せるなら聞かない。出せないなら、その理由（何と何が混ざっているか）を示して1問で絞る。

### フェーズ3A：修正モード

対象の文を、**違う表現・違う切り口に置き換えた案**を提示する。

**多様性保証ルール：**

- 6案は互いに異なる方向へ振る。語尾や語彙だけ変えた並びは禁止。変える軸の例＝〈直接度〉〈主語を誰にするか〉〈情報量〉〈感情の温度〉〈読者に何を補わせるか〉〈ミスリードの強さ〉
- **ワイルドカード2枠**は「あえて逆張り・別ジャンルの言い回し・意味を反転させる」に必ず割り当てる
- 各案には**採用したときに何が変わるか**を1行添える。これがないと選べない

### フェーズ3B：深掘りモード

ユーザーの問い（例：「『隼が知らないきょうだい』の歳と性別は？」）に対して、答えの候補を提示する。

**深掘り選択肢の設計原則（ここが修正モードとの違い）：**

- **答えを並べるのではなく、「その答えが物語に何をもたらすか」で散らす。** 「姉／妹／兄／弟」のような属性の総当たりは価値が低い。「隼との関係がどう変わるか」「既存の伏線にどう噛むか」の軸で6案を作る
- **各案に `→波及：` を1行必ず付ける。** どの既存項目に効くか、どこに新たな整合の宿題が生まれるかを書く。深掘りの価値はここにある
- **ワイルドカード2枠**は「前提を疑う答え」に割り当てる（例：そもそも実在しない／隼の記憶が消されている）
- 確定後、**次に決まっていないことを1つだけ**提示する（連鎖質問）。2つ以上並べない

### フェーズ4：確定と反映

ユーザーの確定操作を受けたら、その場で作業ファイルを更新する：

- **🔧 修正** … 本文の該当箇所を差し替える。変更履歴に「変更前／変更後／選んだ理由」を残す
- **🔍 深掘り** … 本文は変えず、**注釈セクション**に追記する。どの番号への注釈かを明記する
- 選ばれなかった案のうち光るものは、**不採用ストック**に移す（後で別の箇所や別作品に使う）

確定のたびに、以下を1行ずつ添える（**省略禁止**）：

```
✅確定：③を「取り返しのつかないことをしてしまった」に差し替え
⚠️波及：③の括弧書き「（誤解か、韜晦か）」が旧前提のまま残っている／
　　　　②の一人称の温度と揃える必要あり／①の通数には影響なし
```

#### ⚠️波及チェックの3点（この順に必ず見る）

1. **周辺の取り残し** ← **最も見落とす**
   差し替えた文の**直前・直後・括弧書き・見出しラベル**が、**古い前提のまま残っていないか。**
   文を1つ差し替えると、それを受けていた語（指示語／二択の枠組み／「〜という罰」のような言い換え／要素名のラベル）が宙に浮く。
   **確定した文の周辺は毎回必ず読み直す。** 該当があれば、次の修正候補として名指しする
2. **他項目への影響**
   他の番号の記述と矛盾しないか、既存の伏線を壊さないか、すでに確定した注釈と食い違わないか
3. **新たに生じた宿題**
   この確定によって未確定になった点。次の深掘り候補として**1つだけ**挙げる

**⚠️波及の指摘は遠慮しない。** 確定した内容が既存の記述と矛盾する、または伏線を壊す場合は、その場で指摘する。ユーザーが承知のうえで進めると言えば従うが、黙って通してはならない。3点すべて該当なしなら「波及なし」と書く。

反映が終わったらフェーズ1へ戻る。

### フェーズ5：保存

ユーザーが「終了」「保存」と言ったら：

1. **最終セルフレビュー** … 本文全体を通し読みし、修正の積み重ねで生じた矛盾・重複・トーンのブレを洗い出して報告する（勝手に直さない。指摘だけして、直すなら1箇所ずつフェーズ3へ戻る）
2. 保存先フォルダを1問で尋ねる。**プロジェクト内の実在フォルダを候補として並べる**（推奨＋理由つき）
3. 日本語タイトルを提案し、承認を得る
4. 作業ファイルを指定先へ移動し、保存したパスを報告する

## 選択肢の提示フォーマット（毎ターン固定）

**🔧 修正モード：**

```
📍対象: ③のうち「罰が当たったのかもしれない」
　　　　（③には〈仕掛けの設計〉〈この一文〉〈誤解か韜晦かの含み〉が含まれます。
　　　　　別の部分なら言ってください）
　ねらい: 神罰ミスリードを、直接的すぎない形にする

1 取り返しのつかないことをしてしまった
　→ 罰の主体を消す。誰が罰したのかを読者に補わせる
2 妻の秘密を知ってしまった
　→ 罰ではなく「知った」へ転換。因果が誠一郎側に寄る
（6案まで）
W1 〈逆張り〉…
　→ …
W2 〈逆張り〉…
　→ …

⭐AIの推奨：1（理由：…）。次点は4（理由：…）

選び方：`1`で決定／`1+4合`で方向性を合成して再提示／`1改[もっと短く]`／`別案`
```

**🔍 深掘りモード：**

```
📍深掘り: ④「隼が知らないきょうだい」の歳と性別は？

1 隼より3つ上の姉。存命
　→ 波及：隼が「知らない」理由に説明が要る。家族の隠蔽が動機側に効く
2 生後まもなく死んだ弟
　→ 波及：手紙の記述が追悼になる。誠一郎の罪悪感と直結する
（6案まで）
W1 〈前提を疑う〉…
W2 〈前提を疑う〉…

⭐AIの推奨：2（理由：…）。次点は5（理由：…）

選び方：`2`で決定／`2+5合`／`2改[もっと不穏に]`／`別案`
```

- 推奨と理由の明記は**省略禁止**。次点も可能な限り示す
- 各案の `→` の1行は**省略禁止**。これがないと選べない
- 1ターンに質問は1つだけ
- すべて日本語で出力する

### 🗣 言葉づかい（ベーススキル共通。詳細は `.agents/skills/mystery-deep-brainstorm/SKILL.md` の「🗣 言葉づかい」節）

**このスキルでは、1つの選択肢の中に2種類の言葉が同居する。混ぜないこと。**

```text
**🎭 案そのもの（本文に入る文）｜場面に合う言葉を選ぶ（この規則の対象外）**
- 例：`1 取り返しのつかないことをしてしまった`
- 本文の文体・人物・場面に合うなら、難しい言葉・古い言い回し・専門用語のままでよい
- 平易さより、本文に置いたときの効きを優先する

**🗣 説明の言葉｜普段使いの言葉で書く（この規則の対象）**
- 各案の `→` 一行（効果・波及）／`📍対象`／`ねらい`
- ⭐推奨の理由／⚠️波及／フェーズ5のセルフレビューの指摘／質問文
- polish.md の注釈・変更履歴・不採用ストックの記述
```

- 説明の言葉は、**抽象語・評論語・カタカナ語を日常語に置き換える**。「誰が・いつ・誰に対して」を省かず、1文で1つのことだけ言う

```text
✕ → 神罰性の希薄化により、解釈の余地を担保する
◯ → 罰の主体を消す。誰が罰したのかを読者に補わせる
```

- ミステリーの用語（叙述トリック／伏線／ミスリード等）は使ってよいが、**初出の1回だけ**短い言い換えを括弧で添える

## 選択の書き方

⚠️ **記法を覚える必要はない。**自然文で書かれても同じ意味に解釈する。

- `3` … 案3で**決定**（本文に反映する）
- `3+5合` … 案3と案5の方向性を**合成して再提示**する（まだ決定ではない）
- `3+5合 決定` … 合成した結果をそのまま確定する
- `3改[もっと短く]` … 案3を縛りにして6案を作り直す
- `別案` … まったく別の6案＋W2を出す
- 自然文（「3と5を混ぜた感じで、もう少し短く」）も**同じ意味に解釈する**。記法を強制しない

**一発で決まらない前提で設計している。** `合` と `改` で方向性を絞り込むループを何周してもよい。ユーザーが `決定` と言うまで本文は変わらない。

## 操作コマンド一覧

- 「候補」：直すべき箇所をAIが理由付きで6つ提案する
- 「今の全文」：現在の本文を番号アンカー付きで表示する（何度も直すと現状を見失うため）
- 「戻す」：直前の確定を1つ取り消す。変更履歴からも消す
- 「別案」：選択肢を総入れ替えする
- 「ストック」：不採用ストックの一覧を表示する
- 「ブレストに戻す」：骨格から作り直したくなったとき、`.agents/skills/mystery-deep-brainstorm/SKILL.md` を読み込んで発散に戻る。**磨いた内容は破棄せず**、作業ファイルを残したまま接続する
- 「トリック錬成」：`.agents/skills/twist-trick-forge/SKILL.md` に接続する
- 「終了」「保存」：フェーズ5へ

## よくある逸脱と対処

| 逸脱（レッドフラグ） | 対処 |
|---|---|
| 選択肢を出さずに本文を直した | HARD-GATE 1 違反。差し戻して選択肢から出し直す |
| ユーザーが選ぶ前に「では②も直しました」と先回りした | HARD-GATE 1・2 違反。確定操作のあった1箇所だけ反映する |
| 複数箇所をまとめて直した | HARD-GATE 2 違反。1箇所ずつに分けて出し直す |
| 選択肢が3〜4個しかない | HARD-GATE 3 違反。6＋W2 に満たないなら箇所を絞り直す |
| 語尾や語彙だけ違う案を6個並べた | 多様性保証違反。変える軸を変えて作り直す |
| 各案の `→` 一行（効果・波及）を省いた | フォーマット違反。追記して出し直す |
| 深掘りで属性の総当たり（姉／妹／兄／弟）を並べた | 設計原則違反。「物語に何をもたらすか」の軸で作り直す |
| 確定時に ⚠️波及 を書かなかった | 省略禁止。3点すべて該当なしなら「波及なし」と明記する |
| 差し替えた文の**周辺**（括弧書き・ラベル・直後の文）が古い前提のまま残った | 波及チェック1番の見落とし。確定した文の周辺は毎回読み直し、該当を次の修正候補として名指しする |
| 番号だけ指定されたのに、どこを直すか確認で1ターン使った | 最も具体的な要素を対象と見なし、`📍対象` 行で前提を明示して即座に選択肢を出す。聞くのは選択肢が濁るときだけ |
| 矛盾に気づいたのに黙って通した | 批評役を降りない。指摘したうえでユーザーの判断を仰ぐ |
| 作業ファイルの更新を「後でまとめて」にした | 毎ターン更新。コンテキスト圧縮に耐えられなくなる |
| 深掘りの確定後、次の未確定を2つ以上並べた | 1つだけ提示する。1ターン1問の原則 |
| 各案の `→` 一行を、抽象語・評論語・カタカナ語で書いた | 読んでも案を選べない。**普段使いの言葉**へ直す（→「🗣 言葉づかい」） |
| **本文に入る案のほうを、平易な言葉に直してしまった** | **案そのものは対象外。**本文の文体と場面に合う言葉を選ぶ。平易にするのは `→` の説明のほう |
| 保存時に矛盾チェックをせず書き出した | フェーズ5のセルフレビューは省略禁止 |
