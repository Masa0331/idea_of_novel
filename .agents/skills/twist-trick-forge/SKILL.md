# どんでん返し・叙述トリック錬成

## 概要

エンタメ系ミステリーのどんでん返しと叙述トリックを、**真相からの逆算設計**で作り込む。

**中核原理：良いどんでん返しは「驚き」と「納得」の両立である。読者のどの思い込みを裏切るかを先に決め、真相 → 表の物語 → 誤導 の三層を逆算で設計し、フェアネス監査で検証する。**

姉妹スキル `mystery-deep-brainstorm` とファイル形式・選択肢フォーマット・しおり運用を共有する。単体起動も、ベーススキルの深掘り中に「トリック錬成」で呼び出すことも可能。

<HARD-GATE>
フェーズ3（三層設計）とフェーズ5（フェアネス監査）を完了するまで、トリックを「完成」として提示してはならない。監査を省略した納品は禁止。「シンプルなトリックだから監査不要」は例外にならない。ルールの文言への違反は、ルールの精神への違反である。
</HARD-GATE>

## 状態管理

ベーススキルと同じ規則で毎ターン更新する：

- `brainstorm/<セッション名>_tree.md`：分岐記録（ノードID・しおり⭐・元の枝は削除しない）
- `brainstorm/<セッション名>_preferences.md`：嗜好プロファイル（採用/却下要素、推定傾向の確認履歴）
- `brainstorm/<セッション名>_twist_sheet.md`：**真相シート＋伏線対応表**（このスキル固有の成果物。templates/ 参照）

ベーススキルから呼ばれた場合は、既存の tree.md に枝を継ぎ足す（新規ファイルを作らない）。

## フェーズ構成

### フェーズ0：前提確認（1〜2ターン、1ターン1問）

1. 既存プロット・あらすじの有無（あれば読み込む。ベーススキル経由なら tree.md から引き継ぐ）
2. 騙しの規模：ラスト一撃の大逆転か／中盤の中規模ツイストの連打か／両方か
3. 制約：絶対に守りたい要素（例：この人物は犯人にしない）、グリル強度（既定 standard）

### フェーズ1：「読者の思い込み」の棚卸し

トリックの土台は読者が無意識に置く前提である。現在のプロットから **裏切れる思い込みを4〜6個＋ワイルドカード1個** 洗い出し、推奨付き選択肢で提示する。

- 例：「語り手は真実を語っている」「この二人は別人だ」「事件は現在進行形だ」「探偵側は安全圏にいる」
- ワイルドカード枠は「読者がまさか疑わないメタ的前提」（章構成・作中文書の書き手など）に割り当てる
- どの思い込みを裏切るかが決まるまで、トリックの型選びに進まない

### フェーズ2：型の選択

`reference/trick-catalog.md` を読み込み、選んだ思い込みに適合する型を **推奨＋理由＋次点つき** で3〜5個提示する。部分選択可（例：「人物誤認を主軸に、時間誤認を補助で」）。

**媒体適性の確認を必ず行う**：叙述トリックは文章媒体特有の技法（映像化すると成立しないものが多い）。その特性を活かすか、映像化耐性も欲しいかを1問で確認する。

### フェーズ3：三層の逆算設計

選んだ型で、以下の順に設計する。各層ごとに案を提示し承認を取る（逐次検証）：

1. **真相層**：実際に何が起きていたか。5W1Hを曖昧さゼロで文章化
2. **表層**：読者に見せる物語。真相のどこを「書かない」か、どこを「別の意味に読める形で書く」かを決める
3. **誤導層**：読者の注意をどこに向けるか。ミスリード役（疑わしい別人・偽の謎）と、真の手がかりから注意を逸らす仕掛け

**鉄則：嘘は書かない。読者が勝手に誤読するよう、真実だけを不完全・多義的に配置する。地の文の明示的な虚偽は禁じ手**（信頼できない語り手を意図的に使う場合のみ、その旨を設計に明記して例外とする）。

### フェーズ4：伏線・手がかり設計

twist_sheet.md の伏線対応表を埋める。各手がかりについて：

- 初読時の見え方／再読時の意味（**二重読みが成立しない手がかりは伏線ではない**）
- 配置位置（序盤・中盤・直前のどこに置くか。直前に寄ると唐突、序盤だけだと忘れられる）
- カムフラージュ方法（日常描写に紛れ込ませる・別の話題の途中に置く等）

手がかりは最低3個。1個だけの「後出し伏線」は監査で却下される。

### フェーズ5：フェアネス監査（グリル特化版）

1ターン1問・推奨回答付きで、以下を尋問する：

- **手がかり監査**：真相を推理可能にする情報は本文に提示されているか。後出しはないか
- **再読シミュレーション**：真相を知った読者が冒頭から読み直したとき、矛盾する記述はないか。逆に「二度目に光る」記述はあるか
- **納得度監査**：驚きだけで納得が置き去りになっていないか。「そんなの分かるわけがない」と「言われてみれば」の境界はどこか
- **既視感監査**：型カタログ上のよくある実装そのままになっていないか。ひねりの独自性はどこか
- **動機整合**：トリックのために人物の行動が不自然になっていないか（トリック優先でキャラが壊れるのは典型的な失敗）
- 矛盾が見つかったら該当ノードへ戻り、フェーズ3〜4を修正する

### フェーズ6：出力

ユーザーの明示的な指示で実行：

1. twist_sheet.md を完成させる（真相シート＋伏線対応表＋監査結果）
2. セルフレビュー：三層の整合・伏線の二重読み成立・禁じ手の不使用を最終確認
3. **「ボツにしたが光るトリック案」を別セクションで必ず併記**
4. ベーススキルのセッションから呼ばれた場合は、tree.md の該当ノードに twist_sheet.md への参照を書き戻す

## 選択肢の提示フォーマット

ベーススキルと完全共通（📍現在地表示／4〜6案＋ワイルドカード／**⭐AI推奨＋理由＋次点は省略禁止**／部分選択可／1ターン1問／全出力日本語）。

## 操作コマンド

ベーススキル共通コマンド（しおり／戻る／一覧／比較／softer・harder／収束）に加えて：

- 「再読テスト」：現時点の設計で再読シミュレーションだけを即時実行
- 「型カタログ」：reference/trick-catalog.md の一覧を表示
- 「禁じ手チェック」：地の文の虚偽・後出し伏線・二重読み不成立の3点を即時確認

## よくある逸脱と対処

| 逸脱（レッドフラグ） | 対処 |
|---|---|
| 監査を経ずにトリックを「完成」と提示した | HARD-GATE違反。フェーズ5を実施する |
| 地の文で嘘を書く設計にした | 禁じ手。真実の不完全提示に組み直す |
| 伏線が1個・直前配置のみ | 後出し扱い。最低3個・分散配置に修正 |
| 驚き重視で納得度の検証を飛ばした | 納得度監査を実施する |
| トリック都合で人物の行動が不自然 | 動機整合の監査へ戻る |
| 型カタログの実装例をそのまま採用した | 既視感監査。独自のひねりを1点以上加える |
| 選択肢に推奨と理由を付けなかった | フォーマット違反。出し直す |
