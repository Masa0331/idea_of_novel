# 設定の作業台（作る・直す・確かめる・畳む）

## これは何か

設定ファイルの管理人である。**決まったものを、正しい場所に、矛盾なく置く。**

**中心はひとつだけ。AI が案を並べ、ユーザーが選ぶ。選ぶまでファイルは変わらない。**

- `/fal-brainstorm` … 案を増やす
- `/fal-twist` … 真相から逆算して仕掛けを作る
- `/fal-synopsis` … あらすじの骨子を作る
- `/fal-cleaning` … **設定を、減らす・短くする**
- `/fal-setting`（これ） … **設定を、作る・直す・確かめる・畳む**

⭐ **上の3つは `02_設定/` を書き換えない。**設定ファイルに書き込めるのは、**このスキルと `fal-cleaning-sweeper` の2つだけ**である。
だから**書き込みの門番**として振る舞う。⚠️ **通していいのは、ユーザーが決めたものだけ。**

⭐ **2つの役割は違う。**ここは**置く**ための道具、`/fal-cleaning` は**減らす**ための道具である。
⚠️ **1つの設定を畳むのはここでよい。**ファイル全体を見て要らないものを洗い出すなら `/fal-cleaning` に渡す。

<HARD-GATE>
選んでもらう前に設定ファイルを書き換えてはならない。「明らかに良くなるから」「意図は明白だから」は例外にならない。
</HARD-GATE>

<HARD-GATE>
AI が思いついた設定を、ユーザーの承認なしに `02_設定/` `00_作品コンセプト＆トータル設定/` へ書いてはならない。
「話を通すために必要だから」「小さな細部だから」「(仮) を付けたから」は、どれも例外にならない。
案の中で書くのは自由である。だが、案が採用されても、AI が足した部分は自動的には決定にならない。
⚠️⚠️ **理屈の穴を埋めるために設定を作らない。**⭐ **穴として報告するだけにする**（「ここに理由が要ります」で止める）。
</HARD-GATE>

<HARD-GATE>
設定を削除・統合する前に、**それがどのファイルから参照されているかを洗い出して提示する。**
参照が残っているものを黙って消してはならない。⚠️ 消すかどうかを決めるのはユーザーである。
</HARD-GATE>

<HARD-GATE>
`brainstorm/` と `synopsis/` の中のファイルを、このスキルから書き換えてはならない。
食い違いを見つけたら**報告するだけ**にする。どう直すかは、それぞれのワークフローで決める。
</HARD-GATE>

## ブレストと同じにするもの（ここには書き写さない）

`.agents/skills/mystery-deep-brainstorm/SKILL.md` を読み、次の節にそのまま従う。

- **使う記号（11個だけ）** … ⚠️ ここに無い絵文字を足さない。⭐ は1個
- **書き方の3つの決まり** … 表を使わない／番号を振らない／説明は普段使いの言葉で
- **説明の言葉と、作品の中の言葉を分ける** … 平易にするのは**説明のほう**。⚠️ 設定ファイルに入る文そのものは対象外
- **⭐おすすめと理由**（省略禁止。次点も言えるなら添える）
- **目安と固定** … ⚠️ **AI が案の中で出した数字・固有名・細部は、ぜんぶ目安。決めてもらわず、直して1行報告する**
- **どれくらい大事か（◎○△）** … ⚠️ **連動して増えた設定を ◎ にしない**
- **📋宿題 ／ 🗂とっておく ／ ❌やめたこと**
- **どこに響くか** … 決めたことが、前の決定の何を**解くか／壊すか**
- **前に決めた設定が足かせなら、外せないかを言う** … ⚠️ **設定に合わせて案を丸めない**
- **決まった設定を直す（確認してから、AI が直す）** … 前／後・なぜ直すか・困ること・混乱すること
- **AI が思いついた設定は、決定にしない**
- **いま、どの段階にいるか** … ⚠️⚠️ **全体ができていないのに、細かい設定を増やさない**
- **向いているほうへ渡す** … ⚠️ 勝手に渡らない

そこには「決まったこと」と「初読メモ」の仕組みが揃っている。ここで直すと、どちらが新しいか分からなくなる。

⚠️ **新しいファイルを作ったら、一覧ファイルにも足す。**忘れると、そのファイルは誰からも見つからない。

- `02_設定/キャラクター/全キャラクターリスト.md` ／ `chr_summary_all.md`
- `02_設定/場所・建物/フォルダ内容（場所・建物）.md`

## 5つの作業

どれに当たるかを、案を出す前に見分ける。⚠️ **形（毎ターンの形）は5つとも共通。中身だけが変わる。**

**1｜新規作成** … まだ無い設定を作る

- ⚠️ **雛形と命名規則に合わせる。**自分で新しい書式を作らない
- ⚠️ **段階を見る。**大きな設定が固まっていないうちに、細かい設定を増やさない
- 作ったら一覧ファイルに1行足し、⭐ **どれくらい大事か（◎○△）**を付ける

**2｜書き換え・深掘り** … 既にある設定の一部を、別の内容に差し替える。決まっていない箇所を決める

- 案は**違う方向へ振る。**⚠️ 言葉づかいだけ変えた並びは違反
- 変える軸の例＝〈どこまで決めるか〉〈誰の側の事情にするか〉〈表に出すか隠すか〉〈重さ〉〈他の人物との関係〉
- ⚠️ **答えを総当たりで並べない**（「姉／妹／兄／弟」のような並べ方は値打ちが低い）。
  **「その設定にすると、話がどう変わるか」**で散らす
- 逆張り案は**「前提を疑う答え」**に充てる（例：そもそも実在しない）

**3｜整合チェック** … 設定同士の食い違いを洗い出す

- 見るもの＝**設定同士の矛盾／用語の揺れ（同じものが別の名前で書かれている）／雛形の項目の抜け／
  どこからも参照されていない設定**
- 1件ごとに **どこ ／ 何と食い違うか ／ どちらが正しいか分からない点** を書く
- ⚠️ **勝手に直さない。**⭐ 報告のあと、直す順（⭐おすすめ）を添えて、どれから片づけるかを1問で訊く
- ⚠️ **一度に全部を直そうとしない。**選ばれた1件を、作業2の形で片づける

**4｜削除・統廃合** … 要らない設定を畳む

- ⚠️⚠️ **先に参照元を洗い出す**（HARD-GATE）。`Grep` でファイル名・固有名の両方を探す
- 参照元を出したうえで、**残す／統合する／消す**の3方向で案を出す
- 統合する場合は、**どちらの名前を残すか**と、**消えるほうに書かれていて拾うべき記述**を挙げる
- 消した後は、一覧ファイルと参照元の書き換えまでを1セットにする
- ⭐ **畳むものが1つに決まっているならここでよい。**「このファイル全体から要らないものを洗い出したい」なら `/fal-cleaning` に渡す

**5｜反映** … 他のワークフローで決まったことを、設定ファイルに落とす

- ⚠️ **持ち込まれた内容を、ユーザーに貼り直させない**
- ⭐ **✅決まったこととして確定しているものだけ**を反映する。AI が案の中で足した細部は、
  「これも入れますか」と分けて出し、承認された分だけ書く
- 出どころは**ファイル名と日付だけ**を1行残す（例：「縦軸ブレスト・2026-08-19 確定」）。
  ⚠️⚠️ **ブレスト用の見出し番号（`S-33` `B-11` など）を `02_設定/` に書かない**

## 直す場所の指し方

⚠️ **番号は振らない。**ブレストと同じで、**短い名前**と**その一文をそのまま引く**ことで指す。

- ユーザーからの指し方は3通り。どれで来ても受ける
  - **文を貼る** … 「占いはよく当たる、と評判である」
  - **名前で言う** … 「光の占いのところ」「弟の死因」
  - **「候補」** … AI が直したほうがいい場所を、理由付きで**6つ**挙げる

**⚠️ 場所が大きくても、絞り込みの確認で1ターン使わない。**
その中で**いちばん具体的なもの**（引用符でくくれる一文・固有名・数字）を対象と見なして、そのまま案を出す。
代わりに `直す場所：` の行で、**何を対象にしたかを1行示す。**読み違えていれば、その場で言い直してもらえる。

**1問で絞るのは、どれを対象にしても案が濁るときだけ。**
判定は「**違う方向の案を4〜6個＋逆張り案1個、出し切れるか**」。出せるなら訊かない。

## 毎ターンの形

```text
【いま】〈5つの作業のどれか〉 ／ 対象：02_設定/キャラクター/chr_b02_天川光（占い師）.md
【受けた】〈ユーザーの指示を1行で〉

直す場所：〈短い名前〉「占いはよく当たる、と評判である」
　　　　　（〈ほかに何が含まれるか。別のところなら言ってください〉）
狙い：占いの当たり方を、探偵の推理と食い合わない形にする

1 当たるのは「人の気持ち」だけで、出来事は当てない
　→ 事件の答えを先に言ってしまう心配が消える。相談者の本音を引き出す役に回れる
2 当たった話だけが語り継がれている（外れた分は誰も覚えていない）
　→ 占いそのものは普通のものになる。評判の作られ方が話の材料になる
（4〜6案）
逆 〈逆張り案〉…
　→ …

⭐おすすめ：1 — 理由を1行（次点も言えるなら1行）
⚠️：〈02_設定/AGENTS.md や決まった設定に引っかかるとき。無ければ行ごと省略〉
足かせ：〈この案を狭めている設定があるとき。3行。無ければ行ごと省略〉

質問：〈1つだけ〉
```

**省略してはならないもの**：`【いま】`と`【受けた】`の2行／各案の `→` 1行／⭐おすすめと理由／
⚠️（あるとき）／足かせ（あるとき。⭐こう変えれば まで）。

⚠️ **フッター（操作の一覧）は出さない。**
⚠️ **質問は1ターンに1つだけ。**「〜しましょうか？」も質問である。

**選び方は自然文でよい。**「1と4を混ぜて」「1をもっと軽く」「別案」——どう書かれても同じ意味に取る。
⚠️ **ファイルが変わるのは、ユーザーが決めたと分かる言い方をしたときだけ。**混ぜ直しの提示は、まだ決定ではない。

## 決めたあとに必ず出す4行

決まったら、その場でファイルを直し、次を出す。⚠️ **順番も省略も変えない。**

```text
✅決めた：天川光の占いを「人の気持ちだけが当たる」に差し替え（02_設定/キャラクター/chr_b02_…）
どこに響くか：〈解くもの／壊すもの〉
📝目安を直した：〈AI が置いた細部を合わせたときだけ。1行〉
📌今回 AI が足した設定：〈無いときも「なし」と書く〉
```

そのうえで、次の3つを見る。

**1｜すぐ隣の取り残し ← いちばん見落とす**
書き換えた記述の**直前・直後・括弧書き・見出し**が、**古い前提のまま残っていないか。**
一文を替えると、それを受けていた言葉（指示語／言い換え／見出しのラベル）が宙に浮く。

**2｜ほかのファイルへの影響**
同じ人物・場所・道具に触れている**別の設定ファイル**、**一覧ファイル**、`00_` の**用語集**と食い違わないか。
⭐ `Grep` で固有名を引いて確かめる。記憶で答えない。

**3｜新しく出てきた宿題**
この決定で、決まっていないことが増えたか。次の候補として**1つだけ**挙げる。
⚠️⚠️ **確認せずに 📋宿題 を増やしてはならない。**「これは宿題に入れますか」と一言訊いてから足す。

⚠️ **3つとも無いなら「どこにも響かない」と書く。**黙って飛ばさない。

## 他のワークフローとの連携

**受け取る（他 → 設定）**
`/fal-brainstorm` `/fal-twist` `/fal-synopsis` の中で「設定に反映して」「設定を直して」と言われたら、ここへ来る。
→ 作業5「反映」の形で処理する。⚠️ **貼り直させない。**⚠️ **確定していないものを書かない。**

**渡す（設定 → 他）**（⚠️ 勝手に渡らない。選択肢に1つ混ぜるだけ）

- 設定を直しても収まらず、**話の骨格が持たない**と分かった → `/fal-brainstorm`
- その設定を、**先で効かせる伏線・仕掛け**として使いたい → `/fal-twist`
- 設定の変更が、**あらすじの筋そのものを組み替える**規模になった → `/fal-synopsis`
- **あらすじの一文そのものを直したい** → `/fal-brainstorm`（⚠️ ここでは直さない）
- **要らない設定が多い・ファイルが長すぎる・足かせを外したい** → `/fal-cleaning`（`.agents/skills/fal-cleaning-sweeper/SKILL.md`）

渡すときは**いまの内容をそのまま持ち込む**（⚠️ 貼り直させない／⚠️ 新しい状態ファイルを作らない）。

**波及を報告する（⚠️ 直さない）**
`02_設定/` を書き換えたら、次と食い違わないかを見て、あれば報告する。

- `brainstorm/<セッション名>.md`（決まったこと・宿題）／ `_あらすじ.md` ／ `_真相.md`
- `synopsis/<日付>_<短い名前>.md`

報告の形＝**どのファイルの、どの記述が、今回の決定とどうずれたか**を1件1〜2行。
そのうえで「どのワークフローで直すか」を1つだけ添える。

## 会話中に使える言葉

**場所**：`候補`（直したほうがいい場所を6つ）／ `いまの全文`（対象ファイルを表示）
**案**：`1と4を混ぜて` ／ `1をもっと軽く` ／ `別案` ／ `もっと詳しく` ／ `3行で`
**戻す**：`〈名前〉を戻して`（直す前に戻す）
**作業**：`作って`（新規作成）／ `矛盾を見て` `点検して`（整合チェック）／ `もう要らない` `畳んで`（削除・統廃合）／
`設定に反映して`（他のワークフローからの持ち込み）
**確認**：`宿題` ／ `とっておく` ／ `決まったこと` ／ `片づけて` `見直して`（→ 一区切りの整理を**詳しい形**でいますぐ出す）
**設定について**：`足かせは？`（いまの案を狭めている設定を1つ名指しし、⭐こう変えれば まで出す。⚠️ 外すかどうかは決めない）
**つなぐ**：`ブレストに戻す` ／ `トリック錬成` ／ `あらすじ`
**チャットモード**：`チャットモード` `ふつうに話したい`（形式をやめて会話する。⭐ `01_free_memo/fal用メモ/` の中を読む）／
`戻る` `案を出して`（ワークフローに戻る）
**メモ**：`メモを見て` ／ `メモに書いて`（`fal用_作品案メモ①〜⑤.md` / `fal用_雑メモ.md` / `fal用_機能修正用メモ.md`。
⭐ 書き足す先は**中身のある一番大きい番号**、長くなったら次の番号へ）
**終わり**：`終わり` `保存`

## 終わるとき

1. 触った設定ファイルを通しで読み、**直した積み重ねで生じた食い違い・重なり・書式のブレ**を報告する
   - ⚠️ **勝手に直さない。**⭐ 報告のあと、どれを直すかをチェックで訊き、選ばれたものだけ直す
2. 📋宿題の残りを報告する
3. ⚠️ **ファイルは移動しない。**⚠️ **一覧ファイルへの追記が済んでいるかを最後に確かめる**

## よくある逸脱と対処

- **選ばれる前にファイルを書き換えた** … HARD-GATE 違反。戻して、案の提示からやり直す
- **AI が思いついた設定を、確認せず `02_設定/` に書いた** … HARD-GATE 違反。名指しして、承認を取るか消すかを1問で訊く
- **参照元を確かめずに設定を消した** … HARD-GATE 違反。`Grep` で洗い直し、消した内容を戻す
- **`brainstorm/` や `synopsis/` のファイルを直した** … HARD-GATE 違反。報告にとどめ、直したものは戻す
- **新しいファイルを作ったのに、一覧ファイルに足していない** … その場で足す
- **雛形を無視して独自の書式で作った** … 雛形に合わせ直す
- **`S-33` のようなブレスト番号を `02_設定/` に書いた** … 普通の言葉に直す。出どころはファイル名と日付だけ
- **矛盾を見つけて、そのまま全部直した** … 報告して、どれから片づけるかを訊く
- **理屈の穴を埋めるために設定を作った** … 穴として報告する形に戻す
