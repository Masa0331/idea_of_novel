# プロンプト・ディスパッチャー

## 概要

`01_free_memo/プロンプト集.md` を**唯一の情報源（Single Source of Truth）**として扱い、ユーザーの一言から最適なテンプレートを選び、`[ ]` を埋めた完成プロンプトを組み立てて実行する。

**中核原理：ユーザーに「テンプレートを探させない・`[ ]` を埋めさせない」。意図の受け取り → テンプレート選定 → 対象特定 → パラメータ補完 → 完成プロンプトの提示 → 承認 → 実行、の順に進める。**

テンプレートの中身をこのスキルに複製してはならない。**毎回プロンプト集.md を読み込む**こと。ユーザーがテンプレートを追加すれば、このスキルの能力は自動的に増える。

<HARD-GATE>
以下を満たすまで、選んだプロンプトを実行してはならない。
1. `[ ]` プレースホルダが1つも残っていない（推定で埋めた箇所は「推定である」と明示すること）
2. 参照・編集の対象ファイル（またはテキスト範囲）が確定している
3. 完成プロンプト全文をユーザーに提示している

「意図が明確だから」「短いテンプレートだから」「ユーザーが急いでいそうだから」は例外にならない。
未確定のまま実行して的外れな大量出力を出すことが、このスキルが防ごうとしている失敗そのものである。
ルールの文言への違反は、ルールの精神への違反である。
</HARD-GATE>

## 起動時の必須動作

1. `01_free_memo/プロンプト集.md` を読み込む（省略禁止。記憶で代用しない）
2. ユーザーの入力（`/fal-prompt` の引数）を意図として解釈する
3. 引数がない場合のみ、「今日は何をしますか？」と1問だけ尋ね、よく使う入口を4つ程度添える

**このスキル内で引用しているプロンプト集の章名・セクション名は、すべて執筆時点の例示である。**
プロンプト集は継続的に加筆・再編される前提のファイルであり、名称が一致しないことは異常ではない。
一致しない場合は、クイックインデックスと実際の見出しを読み、相当する箇所を内容から特定して進めること。
「該当セクションが見つからない」を理由に停止してはならない。

## 委譲ルール（既存スキルとの棲み分け）

以下に該当する場合、このスキルで処理せず**該当スキルへの切り替えを提案**する（勝手に切り替えず、1問で確認する）：

- 腰を据えたあらすじ・プロットの発想セッション → `mystery-deep-brainstorm`（`/fal-brainstorm`）
- どんでん返し・叙述トリックの設計、伏線の逆算設計 → `twist-trick-forge`（`/fal-twist`）

単発の軽い壁打ち、単発のチェック、単発の生成はこのスキルで処理してよい。
判断基準：**複数ターンにわたり分岐を記録しながら煮詰める作業なら委譲。1〜2ターンで完結する作業ならこのスキルで実行。**

## フェーズ構成

### フェーズ1：テンプレート選定

意図を「工程」に分類し、プロンプト集.md の該当章からテンプレートを選ぶ。章番号は変動しうるため、**番号ではなく工程で照合**すること。

- 整理したい／まとめたい／見づらい／分割したい／設定変更の影響を知りたい → 「ファイルの整理・統合・レイアウト調整」
- 矛盾を潰したい／薄い／説明を足したい／専門用語を噛み砕きたい → 「ブラッシュアップ・補強」
- アイデアが欲しい／展開を変えたい／似た案ばかり／ボツ案を使いたい → 「ストーリー展開・アイデア考案」
- 章立て／中だるみ／引き／あらすじ・ログライン → 「プロット・構成の設計」
- キャラを動かしたい／口調／名前／動機 → 「キャラクター設定・世界観の構築」
- 本文を書きたい／描写／会話／推敲 → 「本文執筆・推敲」
- チェックして／確認して／破綻してない？／伏線／時系列／フェアネス／既視感 → 「検証・監査」
- 調べて／分析して／用語集／既存作品 → 「リサーチ・分析」
- スキル／ワークフロー／回答が浅い → 「AI環境の運用」

**この工程分類は例示であり、固定リストではない。**プロンプト集に新しい工程の章が追加されている場合もある。
どの工程にも当てはまらないと感じたときは、分類を諦める前に必ずクイックインデックスと章見出しを実際に読み、
近い章がないか確認すること。それでも該当がなければフェーズ6へ進む。

提示フォーマット（**推奨＋理由＋次点は省略禁止**）：

```
⭐推奨：〈テンプレート名〉（章：〇〇）
　理由：…
次点：〈テンプレート名〉（こちらが向くのは…の場合）
```

- 複数工程にまたがる依頼（例「整理して矛盾も直して」）は、**工程を分割**して順に実行することを提案する。1回のプロンプトに混ぜない
- 該当テンプレートが存在しない場合 → フェーズ6の「新規テンプレート提案」へ

### フェーズ2：対象の特定

参照・編集するファイルを推定し、パスを明示して確認する。推定の手がかり：

- `00_作品コンセプト＆トータル設定/` … concept.md／世界観設定.md／文体のガイドライン.md／用語集.md
- `01_free_memo/` … 断片メモ、ギミック・どんでん返し、作品テーマ、その他（科学・医学の調べ物）
- `02_設定/` … キャラクター／場所・建物／道具・アイテム／サイドストーリー
- `brainstorm/` … 進行中のブレストセッション（tree.md／preferences.md／twist_sheet.md）

- 対象が1つに絞れる場合は、断定せず「このファイルで合っていますか」と確認する
- 候補が複数ある場合は、番号付きで提示して選ばせる（質問はこれ1つだけ）
- ユーザーがIDEで開いているファイルがあれば、それを第一候補にする

### フェーズ3：パラメータ補完（1ターン1問）

`[ ]` を埋める。**AIが推定できるものは勝手に埋め、質問は本当に判断できないものだけに絞る**。

- 埋めた箇所は完成プロンプト提示時に「（推定）」と付けて可視化する
- 質問には必ず**推奨値と理由**を添える（例：「案の数は5個を推奨します。3個だと方向性が偏り、10個だと粒度が落ちるためです」）
- 1メッセージに質問は1つだけ
- 3問を超えそうな場合は、残りを推定値で埋め、「この値で進めますが、変更があれば言ってください」と一括提示に切り替える（質問攻めにしない）

### フェーズ4：部品スニペットの付与

プロンプト集の「コピペ用『部品』スニペット集」から、文脈に合うものを完成プロンプトの末尾に足す。

**常時付与（本プロジェクトの既定）：**
- 「回答は表（テーブル）形式を使わず、カテゴリ分けされたブロック・カード形式で書いてください」（`02_設定/AGENTS.md` の方針）

**文脈に応じて付与：**
- 設定・事実に踏み込む作業 → 「推測と創作を分けて書く」
- 案出し系 → 「⭐推奨と理由・次点を添える」「ボツ案も列挙する」
- 長文生成・改稿系 → 「出力後に自己レビューして条件違反を指摘する」
- 前提が薄い依頼 → 「不足情報があれば作業前に質問する」

付与しすぎると指示が薄まる。**3つまで**を目安とする。

### フェーズ5：完成プロンプトの提示と実行

1. 完成プロンプト全文を ```text コードブロックで提示する（他のAIツールにも貼れる形にするため）
2. 選択肢を添える：`[このまま実行]` `[ここを直したい]` `[別のテンプレートにする]`
3. 承認を得たら、**そのプロンプトを自分で実行**する
   - 例外：ユーザーが最初から「即実行」「そのままやって」と指示している場合は、提示と実行を同一ターンで行ってよい（提示の省略は不可）
4. 実行結果を出力する。ファイルを書き換える作業の場合、**変更前に対象範囲を示し、破壊的な上書きは事前確認する**

### フェーズ6：フィードバック（プロンプト集の育成）

実行後、以下に該当すれば提案する（提案のみ。書き込みはユーザーの承認後）：

- **該当テンプレートがなかった場合**：今回組み立てたプロンプトを新規テンプレート案として整形し、プロンプト集のどの章に追記するかを提案する
- **既存テンプレートに不足があった場合**：追加すべき条件行を提案する
- **同じ `[ ]` の埋め方を繰り返している場合**：その値を既定値としてテンプレートに書き込むことを提案する

この工程があるため、使うほどプロンプト集が育つ。省略しないこと。

## 出力の原則

- 全出力は日本語
- 1ターンに質問は1つだけ
- 推奨・理由・次点の明記は省略禁止
- ユーザー向けの回答は表形式を避け、カード・ブロック形式で書く
- ターミナル操作が必要な場合はUTF-8強制を前置する
  （`[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $env:PYTHONUTF8=1`）

## 操作コマンド

- 「別のテンプレート」：フェーズ1に戻り、次点以下を提示し直す
- 「プロンプトだけ」：フェーズ5の提示までで停止し、実行しない（他のAIツールに貼る用途）
- 「そのまま実行」：承認ゲートを省略して即実行（提示は行う）
- 「一覧」：プロンプト集のクイックインデックスを表示する
- 「追記して」：フェーズ6の提案をプロンプト集に書き込む

## よくある逸脱と対処

| 逸脱（レッドフラグ） | 対処 |
|---|---|
| プロンプト集.md を読まずに記憶で答えた | 起動時必須動作の違反。読み込んでやり直す |
| `[ ]` を残したまま実行した | HARD-GATE違反。停止してフェーズ3へ戻る |
| 対象ファイルを確認せず推測で編集した | HARD-GATE違反。対象を確定してから実行する |
| 完成プロンプトを見せずに結果だけ出した | HARD-GATE違反。プロンプトを提示して承認を取る |
| 推奨・理由・次点を省いた | フォーマット違反。出し直す |
| パラメータを1ターンで質問攻めにした | 1問に絞る。3問を超えるなら推定値で一括提示に切り替える |
| 複数工程を1つのプロンプトに混ぜた | 工程を分割して順に実行する |
| 腰を据えたブレストをこのスキルで処理した | 委譲ルール違反。`/fal-brainstorm` または `/fal-twist` を提案する |
| スニペットを何個も付けて指示を薄めた | 3つまでに絞る |
| 該当テンプレートがないのに黙って自作した | フェーズ6でプロンプト集への追記を提案する |
| 章名・セクション名が一致しないので停止した | 名称は例示。内容から相当箇所を特定して進める |
