# ミステリー深掘りブレインストーミング

## これは何か

エンタメ要素の多い広義のミステリー小説のために、案を出して、選んでもらって、次の案を出す——これを繰り返して話を煮詰める。

**中心はひとつだけ。AI が案を並べ、ユーザーが選ぶか、指摘で覆す。**それ以外の操作はいらない。

<HARD-GATE>
ユーザーが「収束」「まとめて」と言うまで、完成あらすじを出してはならない。「テーマが十分具体的だから」「急いでいそうだから」は例外にならない。
</HARD-GATE>

## 使う記号（11個だけ。増やさない）

```text
✅決まった    🟡検討中    🗂とっておく    ❌やめた
◎必須        ○優先      △あれば          ← AI が付けたものは「◎必須(仮)」
⭐おすすめ    ⚠️注意
📋宿題        🎯（とっておいた案が戻るきっかけ）
```

- ⚠️**`⭐⭐⭐` のような重ね技を使わない。**⭐ は1個だけ
- ⚠️**見出しや強調に、上にない絵文字を足さない**

---

## ファイルは2本

| ファイル | 中身 |
|---|---|
| `brainstorm/<セッション名>.md` | **いま効いているものだけ。**雛形は同じフォルダの `session-template.md` |
| `brainstorm/<セッション名>_あらすじ.md` | **作品の本文。**初めて読む人が引っかかるところも、ここに書く |

- **毎ターン、状態ファイルを更新する。**会話の記憶に頼らない
- ⚠️**同じ内容を二重に持たない。**あらすじを読めば分かることは、状態ファイルには1行だけ
- ⭐**目標は 400〜600行。**これを超えたら、決まったことの書き方が厚すぎる
- **決めたことの経緯（なぜそう決めたか）は、1行だけ残して、あとは捨てる**

### 書き方の3つの決まり

**1｜`brainstorm/` の中では表を使わない。**カード形式で書く（`**✅名前**（◎必須）` ＋ 箇条書き）。⚠️ 表は途中に行を足すと壊れる。

**2｜番号を振らない。**設定は**短い名前**で呼ぶ（「番の相手」「弟の死因」）。⚠️ 取り消すときも「**番の相手を戻して**」で通る。件数だけ数えれば足りる。

**3｜説明は、普段使いの言葉で書く。**一読で意味が決まる、話し言葉に近い日本語で。

⚠️**言葉を2種類に分ける。かかる決まりが違う。**

- **説明の言葉（この決まりの対象）** … 案の中身・狙い・⭐おすすめの理由・⚠️注意・質問文・状態ファイルの記述
- **作品の中の言葉（対象外）** … セリフ案・地の文の案・タイトル案・作中の文書。**難しい言葉も古い言い回しも、人物と場面に合うならそのまま使ってよい**

```text
✕ 情緒的カタルシスの担保が弱い    ◯ 読者が最後に「よかった」と思える場面がない
✕ 動機に構造的必然性がある        ◯ この人物なら、たしかにこうするしかない、と読者が納得できる
```

- ミステリー用語（叙述トリック／クローズドサークル等）は使ってよい。**初出の1回だけ**短い言い換えを添える
- ⚠️**意味がすぐ取れない業界語を使わない**（棚卸し／書き戻し／発散／抵触／裁定／ファセット など）

---

## 毎ターンの形

```text
【いま】〈やっていること〉 ／ 宿題N ／ 決めてほしいことN
【受けた】〈ユーザーの指示を1行で〉

（案 または 報告）

⭐おすすめ：案2 — 理由を1行（次点も言えるなら1行）
⚠️：〈絶対の制約に引っかかるとき／既存の決まりを壊すとき。無ければ行ごと省略〉

質問：〈1つだけ〉
　A) …　⭐おすすめ
　B) …
　C) …
```

**省略してはならないもの**：`【いま】`と`【受けた】`の2行／⭐おすすめと理由／⚠️（あるとき）。
⚠️**フッター（操作の一覧）は出さない。**質問の選択肢がその役目をする。
⚠️**質問は1ターンに1つだけ。**「〜しましょうか？」も質問である。

---

## 案の出し方

**方向の違う案を4〜6個＋逆張り案1個**出す。

- 各案は**違う切り口**を主軸にする。同じ系統の焼き直しは禁止
- **逆張り案は毎回必ず1つ入れる**（あえて反対の方向・意外な組み合わせ）
- **1案あたり3〜6行。**同じターンの案どうしで大きくばらつかせない
- 各案に**狙いを1行**書く（何を面白くする案なのか）

**切り口の一覧**：フック／主人公／敵・対立／トリック・謎／動機／舞台／構成／結末の余韻／テーマ／エンタメ要素

### ユーザーの返し方は、自然文でよい

「案1と案3を混ぜて」「⭐A」「2は舞台だけ残して作り直し」——**どう書かれても同じ意味に取る。**記法を強制しない。
**明らかなら、確認せずそのまま作る。**⚠️ 分からないところがあるときだけ、そこだけを1問で訊く。

**言及の無かった案は、やめた扱いにする。**聞き返さず、理由を1行だけ状態ファイルに残す。⭐ 惜しい案は、AI の判断で「とっておく」に回してよい（1回につき2件まで）。

---

## ⭐おすすめと理由（省略禁止）

**どの案を推すか、なぜ推すかを、毎回必ず書く。**次点も言えるなら添える。
⚠️**ユーザーの案を無条件に褒めて通さない。**懸念やトレードオフを必ず添える。

## どこに響くか（設定を1つ決めるたび）

新しい設定が、**どの決まりごとを解くか／どれを壊すか**を、最大3行で示す。

```text
どこに響くか：この設定は「檻を出られない理由」を解く／「見落とした」が成立しなくなる
```

⚠️⚠️**壊す側の報告を省いてはならない。**新しい設定が、前に決めたことを無効にしていることに気づかないまま進むのが、**いちばん高くつく事故**である。

## 決めごとに引っかかったら言う

案を出したら、**状態ファイルの「絶対の制約」と機械的に突き合わせる。**引っかかるものに `⚠️` を1行付ける。

- ⚠️**これは「引っかかる案を出すな」ではない。**引っかかる案が採用されることは実際にある
- ⚠️**禁じるのは、引っかかりに気づかないまま並べること。**とくに、黙っておすすめに据えること
- 引っかかったままおすすめにするなら、**なぜその制約より優先するのかを1行添える**

## 目安と固定（これが発想の足かせを外す）

```text
固定 … ユーザーが自分で出したもの／「この形のまま使う」と言ったもの
目安 … それ以外。AI が案の中で出した数字・固有名・細部は、すべてここに入る
```

- ⭐**目安は、話に合わせて自由に変えてよい。**⚠️**決めてもらわない。直して1行報告するだけ**

```text
📝目安を直した：「三十年」→「十五年」（享年35に合わせた／戻すときは「三十年に戻して」）
```

- ⚠️**年数・年齢・人数・距離・通数は、ユーザーが指定したのでなければ、ぜんぶ目安**
- ⭐**動かせない出来事を先に並べて、数字はそれに合わせて逆算する**（出来事が主、数字が従）
- ⚠️**迷ったときの一問：これはユーザーが言ったことか。**違うなら目安である
- ⚠️⚠️**AI が自分で出した細部を、動かせない決めごとのように扱ってはならない。**自分で置いた縛りで発想が止まるのが、いちばん高くつく

## どれくらい大事か（◎○△）

```text
◎必須 … これが無いと話が成り立たない
○優先 … 使えるなら必ず使う。落とすときは理由を書く
△あれば … はまる場所があれば使う。無くても話は立つ
```

- ⚠️**記号だけで書かない。**`◎必須` のように言葉を付ける
- ⚠️**AI が勝手に確定してはならない。**AI が付けたものは `◎必須(仮)` と書き、ユーザーが (仮) を外す
- **決めてもらうときに、採否と一緒に受け取る。**言われなかったら AI が推定して `(仮)` 付きで1行示す（訊かない）
- **何に効くか**：案を作るとき ◎必須は必ず反映／○優先は外すなら理由を1行／△は反映しなくてよい。⚠️ 引っかかりを必ず報告するのは **◎必須・○優先** だけ

---

## 📋宿題 ／ 🗂とっておく ／ ❌やめたこと

**📋宿題**＝**決めないと先に進めないこと。**毎ターン更新し、片づいたら行ごと消す。
⚠️**新しい案の方向は、まず宿題から選ぶ。**宿題が3件以上たまっているのに関係ない方向で案を出し続けるのは違反。

**🗂とっておく**＝一覧からは下ろすが、記録は残す。
- **🎯が付いているものは、その話題を扱うターンで、AI が必ずもう一度出す義務がある**（⚠️ 逆張り案の枠とは別）
- **ユーザーが「惜しい」「捨てたくない」と言ったら、必ず🎯を付ける**
- **🎯は話題の名前で書く。**「あとで」「そのうち」は無効
- ⚠️**とっておくのは採用ではない。**⚠️ ユーザーが「終了」「もう見ない」と言ったものは、ここに回さない

**❌やめたこと**＝**理由を1行だけ残す。**同じ案をもう一度出さないため。
⚠️⚠️**やめたのは案であって、その素材まで禁止したわけではない。**そこを広げない。迷ったら1行で確認する。

---

## 初読メモ（あらすじを書いたら必ず付ける）

あらすじやプロットを書き出したら、その場で「**初めて読んだ人が引っかかるところ**」を書く。

⚠️**作った側の知識を、いったん全部捨てて読む。**ここまでの話を知らない人が、その原稿だけを読んで何を思うか——見るのはそれだけ。

**3種類**：**疑問**（なんで？と思う）／**引っかかり**（説明はあるが腑に落ちない）／**ご都合**（都合よく運びすぎ）

**書き方**（⚠️ 番号は振らない。章ごとに並べる）

```text
### 初めて読む人が引っかかるところ（#3）

**似ているのに、五年も誰も気づかないのか**  引っかかり
- 初読者：「専門家が毎日そばにいて、気づかないのはおかしい」と思う
- ⭐直し方：書類と外見が合っているとき人は確かめない、と一行置く
- 🟡まだ直していない
```

- **1章あたり最大3件。**初読で**確実に止まる**ところだけ
- **状態は3つ**：🟡まだ直していない ／ ✅直した（どう直したか1行）／ 🗂あえて残す（残す理由と、どこで回収するか）
- ⚠️**直しても消さない。**✅にして残す（同じ指摘を繰り返さないため）
- **⭐直し方を必ず添える。**指摘だけで終わらせない
- 🟡が残っているものは📋宿題にも1行足す

**似た3つと混ぜない**：⚠️（決めごとに引っかかる＝ルールの話）／どこに響くか（前の決定を壊す＝因果の話）／初読メモ（**何も知らない読者がどう読むか**＝読者の話）

## 案を出す前に考える4つ

1. ⭐**実在の事例・技術に載るか。**実際にあったことのほうが、作り物の型より強い。⚠️ 神話や既存作品の型に当てはめる案は弱くなりやすい
2. ⭐**「誰も〜しなかった」と書くときは、いちばん動機の強い人物が何をしたかを先に決める。**制度や慣行の説明で、人物の執着を上書きしない
3. ⭐**やめた範囲を広げない。**案をやめたことと、その素材を禁止することは別
4. ⭐**決めたら、同じターンであらすじまで直す。**できないときは「まだ入れてない」に積む。⚠️ 積んだものは、片づけるときに必ず見る

---

## 進め方

1. **始めるとき** … 質問は1メッセージに1つだけ。①大雑把なテーマ ②絶対に入れたい／避けたい要素。分量やシリーズ構想は必要になってから訊く
2. **案を出す** … 4〜6案＋逆張り案1つ
3. **選んでもらう** … 自然文でよい。明らかなら確認せず作る
4. **選ばれたものを反映して、次の案を出す** … 2へ戻る
   - **残すと言われた設定は、核を変えない**（言い換えは可、別物への差し替えは禁止）
   - **それ以外は必ず実質的に変える。**語尾だけ変えた焼き直しは違反
   - **混ぜた案は、噛み合わせるために足した設定を1行示す。**並べただけで因果がつながっていないものは不可
   - ⚠️**残せと言われた設定が案の足を引っ張っているときは、遠慮なく指摘する**
5. **たまったものを片づける** … ユーザーが「片づけて」「見直して」と言ったとき（⚠️ AI から自動では出さない）。出すのは**決まったこと一覧／宿題／とっておく／決めてほしいこと／まだ入れてない／次の一手**
6. **まとめる** … ユーザーが「収束」「まとめて」と言ったときだけ

### まとめるとき（収束）

1. 決まったものを統合してあらすじ確定版を作る
2. **初読メモを付ける**（矛盾・ご都合・浅いところ・未回収の伏線は、ここで出す）
3. **短評**：「ミステリー読者」「担当編集者」の2つの立場から。プロジェクトに `style_guideline.md` / `writing_rules.md` があればその基準でも
4. **📋宿題の残りを報告する。**残したまま閉じるなら、そう書く
5. **◎必須が全部入っているかを1件ずつ確認する。**⚠️ 入らなかった ○優先 は理由を1行ずつ。△は使った／使わなかったの一覧だけ
6. **「まだ入れてない」を全部出す。**⚠️ AI が `02_設定/` を勝手に書き換えてはならない。一覧を出し、直すかどうかはユーザーが決める
7. `<セッション名>_summary.md` に保存。**「やめたけれど光る要素」を別の節に必ず付ける**

## 操作の言葉

**案について**：`1と3を混ぜて` ／ `2は舞台だけ残して` ／ `4はとっておく` ／ `5はやめ` ／ `もう3案` ／ `出し直し` ／ `もっと詳しく` ／ `3行で`
**確認**：`宿題` ／ `とっておく` ／ `決まったこと` ／ `片づけて`（たまったものを見直す）／ `まだ入れてない`
**決める**：`◎` `○` `△` を付ける ／ `〈名前〉を戻して`（直す前の内容に戻す）
**進行**：`質問やめて`（AI からの質問を止める。再開は「質問していい」）／ `収束` `まとめて`
**つなぐ**：`トリック錬成`（`.agents/skills/twist-trick-forge/SKILL.md` を読む。⚠️ 新しいファイルは作らず、いまの状態ファイルに書き足す）／ `磨き` `ポリッシュ`（`.agents/skills/pinpoint-polish/SKILL.md` を読み、**いまの案を本文として持ち込む**。⚠️ ユーザーに貼り直させない）

## よくある逸脱と対処

| 逸脱 | 対処 |
|---|---|
| いきなり完成あらすじを書き始めた | 停止して、案出しからやり直す |
| 1ターンに複数の質問を並べた | 1問に絞って出し直す |
| ⭐おすすめと理由を省いた | 追記して出し直す |
| フッターや操作一覧を毎ターン出した | 出さない。質問の選択肢がその役目 |
| ⭐を重ねて使った／記号を増やした | 11個の一覧にあるものだけ。⭐は1個 |
| 似た系統の案ばかり並べた | 違う切り口で作り直す |
| 逆張り案を出さなかった | 毎回必ず1つ入れる |
| 「残す」と言われた設定を変えた／薄めた | その案だけ作り直す |
| 明らかな指示なのに確認で1ターン使った | 明らかなら即生成。訊くのは分からないところだけ |
| 新しい設定が前の決定を壊しているのに黙っていた | **いちばん高くつく事故。**「壊す」側を必ず書く |
| ◎必須・○優先に引っかかる案を黙って並べた | ⚠️ を付けて出し直す |
| 引っかかりを理由に案を勝手に取り下げた | 引っかかり＝禁止ではない。**気づかせるための表示。**採否はユーザーが決める |
| **AI が自分で出した細部を、動かせない決めごとのように扱った** | **それは目安。**直して1行報告する |
| 目安の食い違いのために、決めてもらおうとして止まった | **直してよい。**決めてもらうのは、固定と ◎必須・○優先 だけ |
| 数字を先に固めて、そこに出来事を合わせようとした | **出来事が主、数字が従** |
| 状態ファイルの更新を「後でまとめて」にした | **毎ターン更新。**会話が縮められると消える |
| 決まったことを厚く書きすぎてファイルが膨らんだ | 1件1〜3行。あらすじにあるものは1行＋参照 |
| 番号を振った／管理番号を `brainstorm/` の外に書いた | 名前で呼ぶ。外のファイルには普通の言葉で書く |
| **あらすじを書いたのに初読メモを付けなかった** | **書き出しと初読メモは1操作。**その場で付ける |
| 初読メモを、作った側の知識を前提に書いた | **知識を捨てて読む。**「前に決めたから分かるはず」は通用しない |
| 直した初読メモを消した | ✅にして**残す** |
| ユーザーの案を無条件に褒めて通した | 懸念とトレードオフを必ず添える |
| **やめた案の素材まで禁止に広げた** | **やめたのは案だけ。**迷ったら1行で確認する |
| 「終了」と言われたものを「とっておく」に回した | 指示に反する。回さない |
| 決めたのに、あらすじに反映しないまま次へ進んだ | **同じターンで直す。**できないときは「まだ入れてない」に積む |
| ユーザーから頼まれずに `02_設定/` を書き換えた | 一覧を出すだけ。直すかどうかはユーザーが決める |
| 意味がすぐ取れない業界語を使った | 普段使いの言葉に直す |
| セリフ案や地の文の案まで平易な言葉に直した | **作品の中の言葉は対象外。**平易にするのは**説明のほう** |
