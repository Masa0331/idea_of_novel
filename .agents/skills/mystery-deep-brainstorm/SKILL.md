# ミステリー深掘りブレインストーミング

## 概要

エンタメ要素の多い広義のミステリー小説のための、選択駆動型ブレインストーミングを実施する。

**中核原理：完成案を一発で出すのではなく、「多様な案の提示 → ユーザーによる部分選択 → 嗜好の言語化と確認 → 選択要素を制約とした次世代案の生成」のループでアイデアを煮詰める。**

**部分選択の主役は「丸ごと採用」ではなく「この設定は残して、あとは作り直す」である。** ユーザーは1回の返答で、複数案に対して別々の指示（案2は舞台だけ残して再生成／案1と案3を合成／案4は却下）を同時に出す。これを1ターンで受け取り、次の一覧の枠に割り当てて生成するのがこのスキルの中心動作である（フェーズ2〜4）。

採用された内容と分岐の履歴をファイルに記録し、任意の分岐点（しおり）へ戻って別の枝を伸ばせるようにする。**不採用案の全文は残さない**（→「記録の3値ルール」）。

<HARD-GATE>
フェーズ2〜4のループを最低2周完了し、ユーザーが明示的に「収束」「まとめて」等を指示するまで、完成あらすじを出力してはならない。「テーマが十分具体的だから」「ユーザーが急いでいそうだから」は例外にならない。ルールの文言への違反は、ルールの精神への違反である。
</HARD-GATE>

## 状態管理（最重要）

会話コンテキストの記憶に頼らず、毎ターン以下のファイルを更新する。雛形はこのスキルと同じフォルダ（`.agents/skills/mystery-deep-brainstorm/`）にある `tree-template.md` `preferences-template.md` `issue-map-template.md` を参照。

**状態ファイルは3本。3本とも新規セッションの初期化時に必ず作成し、以後3本とも毎ターン更新する。**

| ファイル | 軸 | 持つもの |
|---|---|---|
| `brainstorm/<セッション名>_tree.md` | **時間軸** | アイデアツリー。分岐をノードID（N1、N1-2、N1-2-3）で記録。各ノードに「ユーザーの枠指定の原文」「枠割り当て」「採用内容の全文」「由来」「親ノードID」「⭐しおり有無」。冒頭に**🔢採用ID索引**、末尾に**📋宿題**。**採用内容の全文が置かれるのはこのファイルだけ** |
| `brainstorm/<セッション名>_preferences.md` | **制約軸** | **いま有効な制約・嗜好・却下理由だけ。**採用内容の全文は書かず、ノードIDへの参照（例：「詳細は N1-2」）にとどめる |
| `brainstorm/<セッション名>_論点マップ.md` | **主題軸** | **キーポイント（論点）ごとの横断ビュー。**「この論点について、何が確定し、どんな案が出ていて、何が却下されたか」を1箇所に集める |

- `brainstorm/<セッション名>_summary.md`：収束フェーズで生成する最終成果物（フェーズ6でのみ作る）

**3本で同じ内容を二重に持たない。** tree＝いつ・どの分岐で何を採ったか／preferences＝いま効いている制約と嗜好／論点マップ＝論点ごとの現在地。

### ✍️ 記法：表を使わない（プロジェクト方針）

**`brainstorm/` 配下に書くファイルでは、表（テーブル）形式を使わない。**カテゴリ分けされた**ブロック・カード形式**で書く（`02_設定/AGENTS.md` の方針を状態ファイルにも適用したもの）。

**カードの形**：1行目に `**<状態>｜<見出し>**` を置き、内容を配下の箇条書きにする。

```text
**✅確定（S-21）｜誠一郎自身が、そう書いたから**
- 理由＝シマハヤブサがラーテンではないかという疑惑を持ち始めていたから
- ⭐S-11a（傷の一致）が疑惑の発生源になる

**❌却下｜(b) 赤子を渡すだけ。正体は明かさない**
- ※AI最有力だったが不採用。「半信半疑の6年」のほうが選ばれた
```

- **時系列や優先順位を並べるときは、番号つきカード**（`**#5 受け渡し**` / `**1｜〈論点〉**`）にする。列で揃えない
- **この規則は summary.md・polish.md など、このスキルが生成する全ファイルに及ぶ**
- ⚠️**表は途中に行を挿し込むと壊れやすい。**実際に、既存の表へ加筆した結果**孤立した行が2箇所残る事故**が起きている（2026-08-17 に修正）。ブロック形式ならこの事故は起きない

### 🔢 記法：ブレストの管理番号を、外のファイルへ持ち出さない（プロジェクト方針）

**`S-33` `P-01` `N1-20` `B-11` といった番号は、ブレストの中だけで使う。**`02_設定/` `05_資料・参考文献/` `01_free_memo/` など、**`brainstorm/` の外にあるファイルへ書き込んではならない。**

- 理由＝**番号はこのセッションの内部管理用であり、設定ファイルを読む人には意味が分からない。**セッションが終われば対応表も追えなくなる
- 外のファイルへ反映するときは、**決まった中身を、そのまま普通の言葉で書く**
- 出どころを示す必要があるときは、**ファイル名と日付だけ**を書く（例：`（縦軸ブレスト・2026-08-19 確定）`）。番号は書かない
- ⚠️**例外1｜ユーザーが「このファイルには番号を書いてよい」と指定したファイル。**指定されたファイルには番号を書いてよい。**指定がないファイルには書かない**（既定は禁止）
- ⚠️**例外2｜フェーズ6の「要手動反映リスト」。**あれはブレスト側の出力なので `（S-05）` を付けてよい
- 指定を受けたら、**そのファイル名を preferences.md の「🔢記法」節に書き足す**（次のセッションでも分かるように）

### 🗣 言葉づかい：説明は普段使いの言葉で書く（プロジェクト方針）

**このスキルが書く「説明の言葉」は、一読で意味が1つに決まる、普段の話し言葉に近い日本語で書く。**読み返さないと意味が取れない文は、それだけで案の良し悪しを判定できなくする。伝わらなかった案は、悪い案と同じように捨てられてしまう。

**言葉を2種類に分ける。かかる規則が違う。**

```text
**🗣 説明の言葉｜普段使いの言葉で書く（この規則の対象）**
- 案の中身・狙い・継承／更新／橋渡し
- ⭐推奨の理由／⚠️抵触／🔎所見／📊ステータス／質問文
- tree.md・preferences.md・論点マップなど、このスキルが書く全ファイルの記述

**🎭 作品の中の言葉｜場面に合う言葉を選ぶ（この規則の対象外）**
- セリフ案／地の文の表現案／タイトル案／作中の文書（手紙・記事・供述）の文面案
- 難しい言葉・古い言い回し・専門用語も、人物と場面に合うなら**そのまま使ってよい**
- ただし、その案が**なぜ効くのかの説明**は 🗣 側なので、普段使いの言葉で書く
```

**説明の言葉の書き方（3つとも満たす）：**

1. **普段使いの言葉を選ぶ** — 抽象語・評論語・カタカナ語は、日常語に置き換えられるなら置き換える
2. **「誰が・いつ・誰に対して」を省かない** — 読み手が補って解釈する余地を残さない
3. **1文で1つのことだけ言う** — 修飾を重ねず、短く切る

**言い換えの例：**

```text
✕ 情緒的カタルシスの担保が弱い          ←「担保」も「カタルシス」も普段は使わない
◯ 読者が最後に「よかった」と思える場面がない

✕ 動機に構造的必然性がある              ←「構造的必然性」が何を指すのか読み手ごとに変わる
◯ この人物なら、たしかにこうするしかない、と読者が納得できる

✕ 読者のミスリードをレイヤー化する      ←「レイヤー化」が何段の何なのか分からない
◯ 読者の勘違いを、二段構えで仕込む

✕ 犯人だと分かる場面を置く              ←誰が分かるのか、いつなのかが抜けている
◯ 探偵が、終盤で、犯人が誰かに気づく場面を置く
```

- **ミステリーの用語（叙述トリック／クローズドサークル／フーダニット等）は使ってよい。**ただし**初出の1回だけ**、短い言い換えを括弧で添える（例：ホワイダニット（＝なぜやったのかを解く型））
- 迷ったら、**その一文を声に出して読み、そのまま人に話せるか**で判断する

### 論点マップ（📑）— 3本目の状態ファイル

tree は時系列順に伸びるため、**「この論点、結局どうなってるんだっけ」が追えなくなる。**その一点を解決するのが論点マップである。

**必須要件**

- **論点（キーポイント）ごとにセクションを作る。**ノード順・時系列順に並べてはならない。同じ論点について複数ノードで議論した内容を、**1箇所に集約する**
- 各項目に**状態マーク**を付ける：✅確定 ／ 🔵有力 ／ 🟡検討中 ／ 🗂保留 ／ ❌却下（理由つき）
- **冒頭に「📌 いま止まっている場所」**を置く。裁定待ち・未解決の論点を**優先順位つきの表**で並べる。再開時はここだけ読めば続きに入れる
- **内容は要約にとどめ、全文は tree.md のノードIDを参照する。**全文をここに複写しない
- **❌却下も必ず残す。**「なぜそれを捨てたか」が消えると、同じ案を再提案してしまう

**更新タイミング（毎ターン）**

以下のいずれかが起きたら、その場で論点マップを更新する。「後でまとめて」は違反。

1. 新しい論点が生まれた → セクションを追加
2. 論点の状態が動いた（検討中→有力→確定、または破棄） → 状態マークを書き換える
3. 案が却下された → その論点の❌行に理由つきで追加
4. 「📌 いま止まっている場所」の優先順位が変わった → 表を並べ替える

**変更なしのターンでも、末尾の更新日を書き換えて「確認済み」を示す。**

### 記録の3値ルール（ファイル肥大の防止）

提示した案は、採否に応じて**3つの状態のいずれか**で記録する。**不採用案の全文を残してはならない。**

| 状態 | tree.md での扱い | 「戻る」の対象 |
|---|---|---|
| ✅ **採用** | 全文を残す | — |
| 🗂 **保留** | **1行アーカイブ**（タイトル＋主軸＋一言）だけ残す | ○ |
| ❌ **却下・未言及** | **tree.md からは消す。** 却下理由を preferences.md に1行だけ残す | × |

> ⚠️**3値で足りない場合が1つだけある。**「**この案を採る。でも、それによって消える別案が惜しい**」——採用と保留が同時に立つケースである。
> 保留に落としても**戻るきっかけが無いまま埋もれる**ため、この場合は **🥊対立案の予約**として登録する（→「🥊 対立案の予約」）。**3値ルールの例外ではなく、その外側に置く別の棚である。**

- 保留にするのは、ユーザーが「N保留」と言った案、または**AIが「捨てるのが惜しい」と判断した案（1ノードにつき最大2件まで）**。上限を超えて保留にしてはならない
- 1行アーカイブは、後から戻ったときにAIが再展開できる密度で書く（例：`- 【4】逃がした日に死んだ／限界の日に檻を開け放つ。振り返らない鳥`）
- 部分採用の場合、**採用されたファセットだけを全文で残し、その案の残りは消す**
- ステータスが「ユーザーの選択待ち」のノードは、まだ採否が決まっていないため**全案を全文で保持する**。選択を受け取った時点で3値に圧縮する

### 🥊 対立案の予約（再浮上リスト）

**採用と却下の間には、第三の状態がある。**「この案を採る。でも、それによって消える別案が惜しい」——このとき 🗂保留に落としても**戻るきっかけが無いまま埋もれる。**それを防ぐのが予約である。

**🗂保留との違いは「トリガーを持つかどうか」の一点。**保留＝いつか戻れるように1行残すだけ。**予約＝指定した裁定点に来たら、AI が必ずもう一度、対抗案として出す。**

**登録するとき（AI が自分で気づいて登録してよい）**

以下のいずれかが起きたら、その場で tree.md の `## 🥊 対立案の予約` に1件足す。

- ユーザーが「**惜しい**」「捨てたくない」「別案としても見たい」と言った
- **ある採用が、別の魅力的な設定を構造的に排除した**とAIが気づいた（ユーザーが言わなくても登録してよい）
- ⚠️**ただし登録は提案であって採用ではない。S番号を振ってはならない**（採用されたときに初めて番号が付く）

**1件の必須項目（5つ）**

```text
**🥊予約-01｜〈一言タイトル〉**
- 予約した日／発案（ユーザー or AI）
- 🎯トリガー：〈ここに来たら必ず出す、という裁定点〉
- 内容：〈後から再展開できる密度で。保留の1行アーカイブより厚く書く〉
- ⚠️競合する現行設定：〈S番号を挙げ、どう衝突するかを1行ずつ〉
- ⭐この予約が解くもの：〈採用された場合に埋まる宿題・確定へ動く設定〉
```

- **🎯トリガーは「論点名」で書く。**「あとで」「そのうち」は無効。**そのターンの話題がトリガーに当たるかどうかを、AI が機械的に判定できる粒度**にする

**発火するとき（義務）**

**トリガーの論点を扱うターンでは、⭐推奨案と並べて `【対抗｜🥊予約-NN】` の枠で必ず出す。**

- ⚠️**🎲ワイルドカード枠とは別枠。**W は「まだ出ていない逆張り」の枠であり、予約で潰してはならない
- **出すときは、予約時に書いた「⚠️競合する現行設定」を最新の状態で洗い直す。**予約から時間が経つと、競合していたはずの設定が既に変わっていることがある
- ⭐**本線と排他とは限らない。**合成の余地（例：崖へ行った理由は自死だが、落ちた順序は事故だった）があれば所見で示す
- 発火して裁定されたら、**採用なら S番号を振ってノードへ、不採用なら却下理由を preferences へ1行**書き、予約は行ごと消す

**置き場所と表示**

- **置き場所＝tree.md の `## 📋宿題` の直後**（宿題と同じく「まだ決まっていないもの」の棚だから隣に置く）
- **論点マップの「📌 いま止まっている場所」に、件数とトリガーを1行で載せる。**再開時にトリガーを見落とさないため
- 📊ターン頭の1行ステータスには、**1件以上あるときだけ** `🥊予約N` を足す
- 「棚卸し」の出力にも**予約の一覧を含める**

### 宿題リスト（📋）

**決めたことだけでなく、決まっていないことも追跡する。** tree.md の末尾に `## 📋宿題` セクションを置き、以下を1行ずつ記録する。

- **未解決論点** … 「これを決めないと先へ進めない」と分かっているのに、まだ決めていないもの
- **仮置き** … いま仮の値・仮の理由で置いてあり、後で確定が必要なもの（例：「※理由は未構想、設定だけ先取り」）
- **既知の抵触** … `⚠️抵触` が出たまま採用され、まだ解消していないもの

書式：`- [ ] 〈一言〉（発生：N1-2 ／ 種別：論点／仮置き／抵触）`

- **毎ターン更新する。** 新たに生じたものを足し、解決したものは行ごと消す
- **発散の軸を選ぶときは、まず宿題リストから選ぶ。** 宿題が3件以上たまっているのに無関係な軸で発散を続けるのは違反
- **合流点（フェーズ4.5）で残件を必ず併記する**

### 採用カウンタとID

採用した要素には通し番号を振り、tree.md 冒頭に現在値を1行で書く。合流点（フェーズ4.5）の発火判定に使う。

- **案（P-01, P-02…）** … 丸ごと／主軸として採った案。合成して1本になった場合も1件
- **設定（S-01, S-02…）** … ファセット単位で採った要素。ユーザー発案の新設定も含む
- 言い換えだけの再登場は数えない（重複排除）

```text
採用カウンタ：案 4（P-01〜P-04）／設定 7（S-01〜S-07）
```

### 🎚 採用ランク（必須度）— 採用したものを4段階に分ける

**「採用した」だけでは足りない。**「これが無いと話が成り立たない設定」と「はまる場所があれば使いたい設定」を同じ棚に置くと、**収束のときにどちらも同じ重みで扱ってしまう。**それを防ぐのがランクである。

**4段階（記号＋言葉をセットで書く）**

```text
◎必須 … これが無いと話が成り立たない。落とせない
○優先 … 使えるなら必ず使う。落とすときは理由を書く
△希望 … はまる場所があれば使う。無くても話は立つ
▽自由 … 使わなくてよい。使えたら得
```

- ⚠️**記号だけで書かない。**`◎必須` のように**言葉を付ける**（△ と ▽ は形が似ているため）
- 🔎**なぜ A/B/C/D でも ★★★/★★/★/☆ でもないか**：A〜H は**論点マップの節番号**（A-1／B-4／C-6）と**選択肢のラベル**（⭐A) B) C)）で既に使っている。★と☆は**強調と新規の印**として既に使っている。**どちらも読み違いが起きる**

**⚠️ ▽自由 は 🗂保留・❌却下 とは別物**

```text
▽自由 … ✅採用されている。中身は確定している。ただし本編に出なくてもよい
🗂保留 … 採用されていない。1行アーカイブだけ残してある
❌却下 … 捨てた
```

- ⚠️**▽自由 を「捨ててよいもの」と読んで消してはならない。**採用である

**未確定のランクには `?` を付ける**

- `◎?` `○?` … **AI が提案しているだけの状態。**ユーザーが `?` を外して確定する
- ⚠️**AI がランクを `?` 無しで確定してはならない**（「AI は先回りして裁定しない」と同じ原則）
- 📊**ターン頭の1行ステータスに `未ランクN` を足す**（`?` 付き＋未記入の合計。0件なら省略）

**どこに書くか（3箇所。preferences には書かない）**

- **tree.md の 🔢採用ID索引** … 1行6項目のうちの1つ（→「🔢 採用ID索引」）
- **ノード側の定義行** … `**S-07【✅確定・○優先】見出し**`
- **論点マップの確定カード** … `**✅確定（S-21・◎必須）｜誠一郎自身が、そう書いたから**`

**いつ付けるか**

- **裁定を受け取るときに、採否と一緒に受け取る**（例：「E＝採用・△希望」「S-25 は◎」）
- **ユーザーがランクを言わなかったら、AI が推定して `?` 付きで `📥受領` 行に1行示す。**訊かない（曖昧判定には当たらない）
- **後から変えてよい。**変えたら索引の記号を書き換えるだけ

**何に効くか（5つ。ここがランクの実体である）**

1. **案を作るとき** … **◎必須は必ず反映する。**○優先は反映を試み、外すなら理由を1行。**△希望・▽自由は反映しなくてよい**
2. **⚠️抵触の判定** … **◎必須・○優先に抵触したら必ず `⚠️抵触` を出す。**△希望・▽自由への抵触は**報告しなくてよい**（警告のノイズが減る）
3. **🔔合流点の塩漬け警告** … **◎必須・○優先だけを「一度も案に組み込まれていない採用設定」として挙げる。**△▽が未使用でも挙げない
4. **🧹棚卸し** … 採用設定を**ランク順**に並べる
5. **フェーズ6の収束** … **◎必須は全部入れる**／**○優先が入らなかったら理由を1行書く**／**△希望・▽自由は入らなくても一覧に載せるだけ**。⭐**使えなかった △▽ は「ボツにしたが光る要素リスト」へ回す**

### 🔢 採用ID索引 — 採番と同じ1操作として行う

**ノードIDは探せるが、S番号は探せない。**tree.md は時系列で伸びるため、`S-21` がどのノードにあるかは、全文を読まないと分からない。これを解決するのが採用ID索引である。

**採番と索引行の追加は、2つの作業ではなく1つの作業である。**カウンタの数字を書き換えるとき、その真下にある索引に1行足す。「あとでまとめて索引を整える」は違反。

- **置き場所＝tree.md 冒頭、採用カウンタの直下。**隣接させること自体が書き漏らしの防止装置である。離して置いてはならない
- **1行6項目**（ID／一言／**🎚ランク**／状態／全文のあるノードID／論点マップの節）。書式は `tree-template.md` を参照
- ⚠️**検算：採用カウンタの数字と、索引が持つ番号の数は必ず一致する。**毎ターンの状態ファイル更新時にこの一致を確認する。**ズレていたら索引が漏れている**
  - **枝番（`S-11a` / `S-11b`）は1番号として数える。**分離しても採番は増えないため、行数は番号数より多くなりうる。**行数ではなく番号の数で検算する**
- **❌破棄・格下げになった番号も、行ごと消さずに状態マークだけ書き換える。**消すと番号が再利用され、過去の記述と衝突する
- **確定ノードと発案ノードが違うときは両方書く**（`全文＝N1-12（発案 N1-10）`）。ユーザーの指摘が後のノードで採用される流れは頻出であり、**発案ノードだけを探しても定義に辿り着けない**
- **索引に全文を書かない。**ここは目次である（3本で同じ内容を二重に持たない原則）

**新しい定義行の書式規則**：ノード側で S番号を初出させるときは、行頭を **`**S-07【状態・ランク】見出し**`**（例：`**S-07【✅確定・○優先】見出し**`）の形にする。`S-07【` で定義行だけを直接検索できるようにするため（`S-07` だけでは言及箇所に埋もれる）。

起動時に既存の tree.md を検出したら、必ず「続きから再開／新規セッション」を確認する。
**再開したセッションに索引がなければ、その場で全ノードを走査して作る**（論点マップが無い旧セッションを遡及作成するのと同じ扱い）。

## 運用モード（通常／考察）

セッションは2つのモードのいずれかで動く。**現在のモードは preferences.md の「⚙️運用モード」節に1行で記録し、毎ターン引き継ぐ。**

| モード | AIからの新規質問 | 案の生成 | 既定 |
|---|---|---|---|
| **🌱通常モード** | 1ターン1問まで出す | 出す（フェーズ1〜4） | ✅ |
| **🔬考察モード** | **出さない** | ユーザーが求めたときだけ | — |

### 🔬 考察モード

**目的：**溜まった案・論点を、新しい発散を挟まずに片づける局面のためのモード。発散を止めて、既出のものを噛み砕くことに専念する。

- **起動**：「考察モード」「質問やめて」「論点解消モード」「しばらく質問しないで」等の指示。**AIの自己判断で入ってはならない**
- **解除**：「通常モード」「案出しに戻って」「発散再開」「質問していい」等の合図。**解除もユーザーの合図でのみ行う**
- **やらないこと**：AIからの新規質問。ターン末尾の1問。**「〜しましょうか？」「どちらにしますか？」も質問である**
- **やること（通常モードと変わらない）**：⭐AIの推奨と理由／⚠️抵触の明示／🔎所見／選択肢の提示（**質問の形にせず、選択肢を置くだけ**）／状態ファイル3本の毎ターン更新
- **返答してよいもの**：ユーザーの問いへの回答、ユーザーが書いた内容の確認・整理・矛盾の指摘
- ⚠️**批評役は降りない。**質問を止めることと、無条件に同意することは別である

### 📊 ターン頭の1行ステータス（両モード共通・省略禁止）

毎ターンの冒頭に、`📍現在地` と並べて1行で出す。溜まり具合を常に見えるようにするための行である。

```text
📊 裁定待ち3 ／ 宿題16（論点8・仮置き6・抵触2）／ 🥊予約1 ／ 採用 案1・設定24（🎚未ランク5）
```

- `🥊予約N` は**1件以上あるときだけ**足す（0件なら省略）
- `🎚未ランクN` も**1件以上あるときだけ**足す（`?` 付き＋未記入の合計。→「🎚 採用ランク」）

### 🧾 裁定待ちアラート

**「裁定待ち」（ステータス＝選択待ち／要裁定の項目）が5件を超えたら、次の応答の冒頭に1行で通知する。**

```text
🧾裁定待ちが6件になりました（一覧は「棚卸し」で出せます）
```

- **考察モードでも通知はする。ただし質問にしない。**「出しましょうか？」と訊かず、1行置くだけ
- 一度通知したら、5件以下へ戻るまで再通知しない（毎ターン鳴らさない）

### 🧹「棚卸し」

ユーザーが「棚卸し」と言ったら、**質問を伴わない合流点の軽量版**を出す。考察モード中の主力コマンド。

1. **裁定待ちの一覧**（1行ずつ・優先順）
2. **📋宿題の残件**（種別ごとの件数＋論点だけ全文）
3. **一度も案に組み込まれていない採用設定**（塩漬け）。⚠️**🎚◎必須・○優先 だけを挙げる**
3.5. **採用設定のランク別一覧**（◎ → ○ → △ → ▽ の順。⚠️`?` 付きは末尾にまとめる）
4. **🗂保留アーカイブの一覧**（1行ずつ）
5. **🥊対立案の予約の一覧**（1行ずつ・**トリガーを併記する**）

**選択肢は置いてよいが、質問はしない。**

### 🔗 効き先チェック（設定を1つ確定・提案するたび）

**新しい設定が確定または提案されたら、その設定が既存のどの論点を「解く」か「壊す」かを、最大3行で示す。**

```text
🔗効き先：S-23 は【S-17 檻を出られない理由】を解く／【S-14 の芯】を壊す（「見落とした」が成立しなくなる）
```

- **壊す側の報告を省略してはならない。**新しい設定が既存の確定を無効化していることに気づかないまま進むのが、このスキルで最も高くつく事故である
- 効き先がない設定は行ごと省略してよい

## フェーズ構成

### フェーズ0：セッション設定（1〜2ターン）

質問は1メッセージに1つだけ。確認する項目：

1. 大雑把なテーマ・出発点（一言でも可）
2. 絶対に入れたい要素／絶対に避けたい要素
3. グリル強度の初期値（light／standard／hard、既定は standard）

分量・シリーズ構想などは、必要になった時点で聞く。最初に質問攻めにしない。

### フェーズ1：発散

方向性の異なる案を **4〜6個＋ワイルドカード1個** 提示する。

**多様性保証ルール（固着防止）：**
- 各案は互いに異なるファセット軸（下記参照）を主軸にすること。同系統の焼き直しは禁止
- ワイルドカード枠は「あえて逆張り・意外な組み合わせ・概念衝突」に必ず割り当てる

### フェーズ2：部分選択（枠指定）

ユーザーは案を丸ごと選んでも、要素単位で選んでも、**案ごとに別々の処理を指定してもよい**。これを促すため、各案は提示時点でファセット分解しておく（提示フォーマット参照）。

#### 処理の6種類

| 記号 | 処理 | 意味 | 次の一覧で使う枠 |
|---|---|---|---|
| 🔁 | **改** | 案Nの指定された設定だけを保持し、**それ以外は作り直す** | 1枠（`×N` 指定で複数枠） |
| 🔗 | **合成** | 複数案の指定された設定を組み合わせて1案にする | 1枠 |
| 📌 | **維持** | 案Nを変更せず次の一覧にも残す | 1枠 |
| 🗂 | **保留** | 次の一覧には出さないが、**1行アーカイブを残して後から戻れるようにする** | 0枠 |
| ❌ | **却下** | 捨てる（tree.md から削除し、preferences に理由を1行） | 0枠 |
| ✨ | **新案** | 残り枠を新規発想で埋める | 残り全部 |
| 🥊 | **予約** | いまは採らないが、**指定した裁定点で必ず対抗案として再提示する** | 0枠（発火時に1枠） |

**📌維持と🗂保留は別物。** 維持＝次の一覧にもう一度出す（枠を使う）。保留＝一覧からは下ろすが記録は1行残す（枠を使わない）。
**🗂保留と🥊予約も別物。** 保留＝戻るきっかけがない。**予約＝トリガーを持ち、そこで必ず再浮上する**（→「🥊 対立案の予約」）。

#### 記法（ショートハンド・テンプレート・自然文のすべてを解釈する）

```text
2改[舞台,主人公] 5改[フック] 1+3合[1のトリック+3の動機] 4,6却下
```

- `N改[残す設定]` … `[ ]` は省略可。省略時は下記「曖昧判定」に従う
- `N改×3` … 同じ縛りで3案つくる（枠を3つ使う）
- `N+M合[使う設定]` … 3案以上の合成 `1+3+5合` も可
- `N維持` / `N保留` / `N却下` / `N,M却下`
- `N予約[トリガーの論点]` … 案Nを **🥊対立案の予約**に登録する。⚠️**`[ ]` のトリガーは省略可**だが、省略されたら**AI がトリガーを1行で提案して受領行に書く**（曖昧判定には当たらない。訊かずに提案し、違えばユーザーが直す）
- `新案3枠` / `残り新案` / `全部で8案`（総数の上書き）
- 自然文（「2と5は舞台を残して作り直して、1と3は混ぜて、4と6はなし」）も**同じ意味に解釈する**。記法を強制しない

#### 枠配分ルール

1. 既定の総数は **4〜6案＋ワイルドカード1個**（フェーズ1と同じ）
2. **指定枠（改・合成・維持）を先に確保**し、残りを新案で埋める
3. **ワイルドカード枠は常に確保する。** 指定枠で埋まりきっても W だけは必ず出す（固着防止）
4. 指定枠の合計が6を超えるときは総数を最大8まで拡張し、その旨を受領行に1行で断る。8を超えるときだけ、どれを落とすか確認する
5. ユーザーが総数を指定した場合はそれに従う
6. **言及のなかった案は却下扱い**にする。聞き返さず、preferences には「未言及（理由は推定）」と1行だけ記録し、**tree.md からは全文を削除する**（→「記録の3値ルール」）。捨てるのが惜しい案は、AIの判断で保留（1ノード最大2件）に回してよい

#### 曖昧判定（ここに当たるときだけ、1問だけ確認する）

明確な指定なら**確認せず即生成する**。以下のいずれかに当たるときだけ、**該当箇所だけを1問で**確認する（全部を聞き直さない）：

- 「残す設定」が明示されておらず、案の記述からも一意に定まらない（例：案5に魅力的な軸が複数ある）
- 合成で**同じファセットが複数案から指定されて競合している**（例：1の舞台と3の舞台の両方）
- 指定枠が総数の上限（8）を超え、どれを落とすか判断できない

確認するときは、AIの推奨解釈を先頭に置いた選択肢形式にする：

```text
案5の「この設定を残す」の対象を確認させてください。
　⭐A) フックのみ（推奨：他4案と最も差別化される軸のため）
　　B) フック＋舞台
　　C) 主人公の造形
　　D) その他（指定してください）
```

### フェーズ3：傾向確認

2周目以降、選択のたびに preferences.md を更新し、**2〜3周ごと**にAIが推定傾向を言語化して確認を取る。

**キープ指定は最も強い嗜好シグナルとして扱う。** 「この設定は残して」と言われた設定は、単発の採用ではなく**以後の既定の制約**として preferences.md の「確定済みの制約条件」に昇格させる（ユーザーが後で外すまで有効）。同様に、合成の相性（噛み合った／噛み合わなかった組み合わせ）も蓄積し、次の合成提案に反映する。

> 「ここまでの選択から、あなたの好みを『◯◯を重視し、△△は避けたい』と推定しています。合っていますか？　修正があれば教えてください。」

暗黙の推定のまま進めない。誤学習と固着をここで防ぐ。

### フェーズ4：再生成

「枠割り当て＋選択済み要素＋確認済み嗜好プロファイル」を制約条件として次世代案を提示し、フェーズ2へ戻る。ユーザーが満足するまでループする。

**枠ごとの生成規則：**

- **🔁 改案** … 「残す」と指定された設定は、**その核を保持する**（言い換え・描写の変更は可、別物への差し替えは禁止）。**それ以外のファセットは必ず実質的に変える。** 語尾だけ変えた焼き直しは違反
- **🔗 合成案** … 各案から持ち込む設定を明示したうえで、**噛み合わせるために足した設定（橋渡し）を1行で示す。** 「並べただけ」で因果がつながっていない合成は不可
- **📌 維持案** … 前回の文面をそのまま再掲する。勝手に「改善」しない
- **✨ 新案** … 既存の指定枠と**異なるファセット軸を主軸にする。** 改案・合成案の近縁を新案として出すのは多様性保証違反
- **🎲 W** … 常に逆張り・意外な組み合わせに割り当てる

**改案どうし（例：2改と5改）が似通ってはならない。** それぞれの「残す設定」が違う以上、更新側も違う方向へ振る。

生成後、残せと指定された設定が案の足を引っ張っている場合は、`🔎所見` として遠慮なく指摘する（無条件に従うのではなく、批評役を降りない）。

**案の分量（粒度）：**

- 既定は **1案あたり3〜6行**。同じターンの案どうしで分量を大きくばらつかせない
- ユーザーが「3行で」「もっと詳しく」「粒度」と言ったらそれに従い、**以後の既定として維持する**（毎回指定させない）
- 目安：発散初期は短く（比較しやすさ優先）、詰める段階では長く（判断材料優先）

#### 生成後の必須チェック（2つ・省略禁止）

**1. 制約バッティング検出**

各案を preferences.md の「確定済みの制約条件」と機械的に突き合わせ、抵触するものに `⚠️抵触` を1行付ける。⚠️**必ず出すのは 🎚◎必須・○優先 への抵触。**△希望・▽自由への抵触は報告しなくてよい（→「🎚 採用ランク」）。

- **これは「違反案を出すな」というルールではない。** 制約違反案が採用されることは実際にある（例：制約違反だが「ユーザーがそう思っていること自体は事実」として保持する形）
- **禁じるのは、抵触に気づかないまま案を並べること、とりわけ抵触案を無警告で推奨に据えること**
- 抵触したまま推奨する場合は、**なぜその制約より優先するのかを1行添える**
- ユーザーが「その制約は外す」と言ったら preferences.md の制約条件を更新し、以後は抵触扱いしない

**2. 宿題の更新**

その世代で新たに生じた未解決論点・仮置きを `📋宿題` に追加し、解決したものを消す（→「宿題リスト」）。

### フェーズ4.5：合流点（採用がたまったら、次案の前に止まる）

採用カウンタが **案6 または 設定10** に到達したら、**次の案を生成する前に**必ず合流点を出す。ここまで採ったものを使うか、まだ発散を続けるかは、AIが決めずユーザーに訊く。

出力する内容は4つ：

1. **ここまでの採用一覧**（案・設定とも1行ずつ、IDつき）
2. **一度も案に組み込まれていない採用設定**の洗い出し（塩漬け防止。これが合流点の主目的）。⚠️**挙げるのは 🎚◎必須・○優先 だけ。**△希望・▽自由は未使用でも挙げない
3. **📋宿題の残件**（未解決論点・仮置き・未解消の抵触）
4. **次の選択肢**（AIの推奨を先頭に置く）

```text
🔔合流点：採用が案6／設定10に達しました。
（採用一覧：P-01〜／S-01〜 を1行ずつ）
（未使用の採用設定：S-03, S-07）
（📋宿題：3件 — 動機の一本化／弟妹2羽の是非／S-01の理由が未構想）

　⭐A) 採用案を束ねて1本にブラッシュアップする
　　B) 採用設定（とくに未使用のもの）を使った新案をつくる
　　C) このまま発散を続ける
　　D) 磨き（pinpoint-polish）へ移る
```

- **A・B の出力は `tree.md` の新しいノードとして記録する。** summary.md には書かない（収束ではないため）。束ねた1本は新しい ✅採用 として P- 番号を振り、元の採用案はそのノードに統合済みとして残す
- **C を選ばれたら、次は +6案／+10設定に達するまで合流点を出さない。** 毎ターン訊くのは違反
- **合流点は HARD-GATE を解除しない。** A も B もフェーズ2〜4の中の動作であり、完成あらすじの出力ではない。収束はユーザーが「収束」と言ったときだけ
- 「案が1つに決まっているのに発散が続いている」と感じたときの磨きへの誘導も、**この合流点にまとめる**（別途1問で訊かない）
- **Claude Code 固有：** 選択肢の提示に `AskUserQuestion` を使ってよい（推奨を先頭に置くこと）

### フェーズ5：グリルモード（ストレステスト）

案が固まってきたら（またはユーザーが「グリル」と指示したら）尋問モードに切り替える：

- 最も不確実性の高い論点（ブランチ）を1つ選び、**1ターンに1問**、狭く具体的に問う。「もっと詳しく」のような曖昧な質問は禁止
- **各質問には必ずAIの推奨回答と理由を添える**
- ブランチが解決するまで次に移らない。解決したら要約して確認を取る
- 判断間の依存関係（この決定があの決定を縛る等）は明示する
- リスクのある判断・矛盾には遠慮なく反論する
- ミステリー固有の定番論点：トリックの穴／動機の納得度／伏線の配置と回収／読者へのフェアネス／ミスリードの成立条件／ご都合主義の有無
- 強度はユーザーが「softer」「harder」でいつでも変更できる
- 穴が見つかったら該当ノードへ戻り、フェーズ1〜4で再発散する

### フェーズ6：収束・出力

ユーザーの明示的な指示で実行：

1. 採用した枝の全要素を統合し、あらすじ確定版を作成
2. **セルフレビュー**：矛盾・ご都合主義・浅い描写・未回収の伏線・曖昧な動機をチェックし、その場で修正
3. **多視点レビュー**：「ミステリー読者」「担当編集者」の2視点＋プロジェクト内に style_guideline.md / writing_rules.md があればその基準で短評
4. **📋宿題の残件を報告する。** 未解決のまま収束する場合は、その旨を明記する（黙って閉じない）
4.5. **🎚ランクの消化を報告する（省略禁止）。****◎必須がすべて入っているかを1件ずつ確認する。**⚠️**入らなかった ○優先 は、外した理由を1行ずつ書く。**△希望・▽自由は「使った／使わなかった」の一覧だけでよい
5. **要手動反映リストの作成**（省略禁止）。このセッションの決定によって**更新が必要になった既存設定ファイルを列挙する**。ブレストの成果が `02_設定/` 等に反映されないまま埋もれるのを防ぐ
   - 形式：`- 02_設定/キャラクター/chr_xxx.md … 〈どの決定により、どこが変わるか〉（S-05）`
   - **AIが勝手に書き換えてはならない。** 一覧を出し、更新するかどうかはユーザーが決める
   - tree.md 冒頭の「前提」節も対象に含める（既存設定を上書きする決定が出ていることが多い）
6. summary.md に保存。**「ボツにしたが光る要素リスト」を別セクションで必ず併記**（後の作品で再利用するため）。素材は tree.md の**保留アーカイブ**、preferences.md の**却下理由**、そして**使えなかった 🎚△希望・▽自由**から集める

## 選択肢の提示フォーマット（毎ターン固定）

```
📍現在地: N2-1（ルートからのパス: テーマ > 案2 > 深掘り1）
📥受領: 2改／5改／1+3合成／4,6却下 → 指定3枠＋新案2＋W

【案1｜🔁2改】〈タイトル的な一言〉
　継承：舞台＝…（案2より）／主人公＝…（案2より）
　更新：トリック・謎＝…／動機＝…
　狙い：（何を面白くする案か1行）
【案2｜🔗1+3合成】〈タイトル的な一言〉
　継承：トリック＝…（案1より）／動機＝…（案3より）
　橋渡し：（噛み合わせるために足した設定を1行）
　狙い：…
【案3｜✨新案】〈タイトル的な一言〉
　狙い：…
　フック：…／トリック・謎：…／動機：…／（該当するファセットのみ）
（合計4〜6案＋ワイルドカード）
【W｜🎲】ワイルドカード：…
【対抗｜🥊予約-01】〈予約時のタイトル〉  ←トリガーに当たるターンだけ。W とは別枠
　内容：…（予約時の記述を再展開）
　⚠️競合：S-25（自死）と正面衝突／S-08 とは噛む　←最新の状態で洗い直したもの
　⭐合成の余地：…（本線と排他でない可能性があれば1行）

⭐AIの推奨：案X（理由：…）。次点は案Y（理由：…）
⚠️抵触：案X＝〈制約名〉に抵触（どう抵触するかを1行／抵触がなければ行ごと省略）
🔎所見：（残せと指定された設定が足を引っ張っている場合のみ）
```

- `📥受領` 行は**枠指定を受け取ったターンでは省略禁止**（初回の発散時は不要）。解釈違いをその場で指摘してもらうための行である
- 継承／更新／橋渡しの明示は**省略禁止**。どの設定がどこから来たかを常に追えるようにする
- 推奨と理由の明記は**省略禁止**。次点も可能な限り示す
- `⚠️抵触` の明示は**省略禁止**（抵触がゼロのときだけ行ごと省略してよい）。抵触案を無警告で推奨に据えるのは違反
- 1ターンに質問は1つだけ
- すべて日本語で出力する
- **案の説明・理由・所見・質問は、普段使いの言葉で書く**（→「🗣 言葉づかい」）。セリフ案・地の文の表現案など**作中で使う言葉そのもの**は対象外で、場面に合う言葉を選んでよい

## ファセット軸（ミステリー固定）

案の分解・部分選択・多様性保証に使う軸：

- フック（前提の面白さ・一言で言える売り）
- 主人公（探偵役の造形・欠点・視点）
- 敵・対立構造（犯人・障害・社会的圧力）
- トリック・謎（HOW／WHO／WHY／WHATダニット）
- 動機（納得度と意外性の両立）
- 舞台（時代・場所・業界・ローカル性）
- 構成（時系列・視点・章立て・叙述の仕掛け）
- 結末の余韻（カタルシス／苦味／どんでん返し）
- テーマ（物語の思想的背骨）
- エンタメ要素（コメディ・アクション・恋愛・グルメ等の配合）

## 操作コマンド一覧

**枠指定（フェーズ2の中心操作。詳細はフェーズ2を参照）**

- 「2改[舞台,主人公]」：案2の舞台と主人公を残し、それ以外を作り直す
- 「2改×3」：同じ縛りで3案つくる
- 「1+3合[1のトリック+3の動機]」：案1と案3の指定設定を合成して1案にする
- 「4維持」：案4をそのまま次の一覧にも残す
- 「4保留」：次の一覧からは下ろすが、1行アーカイブを tree.md に残して後から戻れるようにする
- **「4予約[誠一郎の死の場面]」**：案4を **🥊対立案の予約**に登録する。**指定した裁定点に来たら、AI が必ず対抗案として再提示する**。「惜しい」「捨てたくないけど今は採らない」と言った場合も同じ扱いにする
- **「予約」**：現在の🥊予約の一覧を、トリガー付きで表示する
- 「4,6却下」：不採用（理由は任意。書かなければAIが推定して記録する）。tree.md からは削除される
- 「残り新案」「新案3枠」「全部で8案」：新案枠と総数の調整
- 「テンプレ」：枠指定テンプレートの全文を再表示する
- 「全部改[〇〇]」：提示された全案に同じキープ指定をかけて作り直す

**セッション操作**

- **「考察モード」「質問やめて」「論点解消モード」**：🔬考察モードに入る（AIからの新規質問を停止。推奨・抵触・所見は継続）
- **「通常モード」「案出しに戻って」「発散再開」「質問していい」**：🌱通常モードに戻る（1ターン1問を再開）
- **「棚卸し」**：裁定待ち・宿題・塩漬け設定・保留アーカイブを、**質問なしで**一覧化する（合流点の軽量版）
- 「カウンタ」「合流点」：現在の採用カウンタと採用一覧（未使用の設定を含む）を即表示する
- 「宿題」：📋宿題の残件を一覧表示する。「宿題1を片付ける」でその論点を発散軸に指定できる
- **「予約」**：🥊対立案の予約を、トリガー付きで一覧表示する
- **「ランク」**：採用設定を **🎚ランク別**（◎必須／○優先／△希望／▽自由／未ランク）に一覧表示する
- **「S-25＝◎」「E＝△」「S-03 は▽」**：その項目のランクを付ける／変える。`?` が付いていれば外れて確定になる
- **「ランク提案」**：未ランクの項目に、AI が `?` 付きの推定ランクをまとめて提案する（確定はユーザー）
- 「3行で」「もっと詳しく」「粒度」：案1つあたりの分量を変更する。**以後の既定として維持する**
- 「手動反映」：現時点の決定によって更新が必要な既存設定ファイルの一覧を出す（収束を待たずに確認できる）
- 「しおり」：現在ノードに⭐を付け、tree.md 末尾の一覧にも転記
- 「N1-2に戻る」「しおり2に戻る」：tree.md から該当ノードを読み直し、未選択だった選択肢を再提示。新しい選択は新しい枝番号で記録し、**元の枝は削除しない**
- 「一覧」：しおり一覧と現在地パスを表示
- 「比較 N1-2 N1-3」：2枝の内容を並べて比較し、AIの優劣所見と理由を添える
- 「グリル」「softer」「harder」：フェーズ5の開始と強度変更
- 「トリック錬成」：姉妹スキル `.agents/skills/twist-trick-forge/SKILL.md` を読み込み、どんでん返し・叙述トリックの設計に接続する。**新規ファイルは作らず**、現在の tree.md に枝を継ぎ足し、preferences.md をそのまま引き継ぐ
- 「磨き」「ポリッシュ」：姉妹スキル `.agents/skills/pinpoint-polish/SKILL.md` を読み込み、**現在ノードの案を本文として持ち込んで**1箇所ずつの修正・深掘りに接続する。preferences.md をそのまま引き継ぎ、**ユーザーに案を貼り直させない**。作業ファイルは `brainstorm/<セッション名>_polish.md`
- 「収束」「まとめて」：フェーズ6へ

## よくある逸脱と対処

| 逸脱（レッドフラグ） | 対処 |
|---|---|
| いきなり完成あらすじを書き始めている | HARD-GATE違反。停止してフェーズ1からやり直す |
| 推奨案や理由を省いて選択肢だけ出した | フォーマット違反。推奨＋理由を追記して出し直す |
| 似た系統の案ばかり並べた | 多様性保証違反。異なるファセット軸で作り直す |
| ユーザーの選択理由を推測だけで進めた | フェーズ3の明示確認を実施する |
| tree.md の更新を「後でまとめて」にした | 毎ターン更新。コンテキスト圧縮に耐えられなくなる |
| **論点マップを作らなかった／更新しなかった** | **状態ファイルは3本。**新規セッションでは初期化時に必ず作り、以後は毎ターン更新する |
| 論点マップをノード順・時系列順に書いた | **論点ごとに集約する**のがこのファイルの唯一の存在理由。時系列は tree.md の役割 |
| 論点マップに採用内容の全文を複写した | 要約にとどめ、全文は tree.md のノードIDを参照する |
| 論点マップから却下項目を消した | ❌は理由つきで残す。消すと同じ案を再提案してしまう |
| 論点マップの「📌 いま止まっている場所」を更新しなかった | 再開時にここだけ読めば続きに入れる状態を保つ。優先順位が変わったら並べ替える |
| 不採用案を全文のまま tree.md に残した | 記録の3値ルール違反。保留は1行に圧縮、却下は削除する |
| **AI判断で**保留を1ノードに3件以上つくった | 上限2件。惜しい順に2件へ絞る（ユーザーが「N保留」と指定した分は上限外） |
| 採用内容を tree.md と preferences.md に二重で書いた | 全文は tree.md だけ。preferences はノードIDへの参照1行にする |
| 採用カウンタの更新を忘れた／IDを振らなかった | 合流点が発火しなくなる。採用のたびに P-／S- を振り、冒頭の1行を更新する |
| **S番号を振ったのに 🔢採用ID索引に1行足さなかった** | **採番と索引は1操作。**カウンタの数字と索引の**番号の数**が一致しない時点で漏れている。その場で補う |
| 🔢索引に採用内容の全文を書き込んだ | 索引は目次。**5項目だけ**（ID／一言／状態／ノードID／論点マップの節）。全文はノード側に置く |
| 索引の「一言」を抽象語だけで書いた | 検索で当たらなくなる。**内容語を入れる**（「傷の一致」「登録票の一行」）。「重要な設定」では引けない |
| 再開したセッションに 🔢索引がない | 旧セッション。**その場で全ノードを走査して作る**（論点マップの遡及作成と同じ扱い） |
| 閾値に達したのに合流点を出さず次案を出した | 次案の**前**に合流点を出す。出し直す |
| 「発散を続ける」と言われたのに毎ターン合流点を出した | 次は +6案／+10設定に達するまで出さない |
| **確定済みの制約に抵触する案を、無警告で並べた／推奨に据えた** | `⚠️抵触` を付けて出し直す。抵触したまま推奨するなら、制約より優先する理由を1行添える |
| 抵触を理由に案を勝手に取り下げた | 抵触＝禁止ではない。**気づかせるための表示**であり、採否はユーザーが決める |
| **ユーザーが「惜しい」と言った案を、🗂保留に落として終わりにした** | **保留には戻るきっかけが無い。**「採るが、消える別案も生かしたい」なら **🥊対立案の予約**に登録し、**トリガーを書く** |
| **🥊予約のトリガーに当たるターンなのに、対抗案を出さなかった** | **発火は義務。**`【対抗｜🥊予約-NN】` の枠で⭐推奨案と並べて出す。予約が死ぬと、この仕組み自体が無意味になる |
| **🥊予約を🎲ワイルドカード枠で出した** | **別枠である。**W は「まだ出ていない逆張り」の枠。予約で潰すと固着防止が効かなくなる |
| 🥊予約に S番号を振った | **予約は採用ではない。**採用が決まったときに初めて番号を振る |
| 🥊予約のトリガーを「あとで」「そのうち」と書いた | **論点名で書く。**AI が機械的に発火判定できる粒度にする |
| 予約を発火させたが、競合設定を予約時のまま貼り直した | **最新の状態で洗い直す。**時間が経つと、競合していたはずの設定が既に変わっていることがある |
| **AI が 🎚ランクを `?` 無しで確定した** | **先回り裁定と同じ違反。**`?` を付け直し、確定はユーザーに委ねる（→「🎚 採用ランク」） |
| **🎚▽自由 を「捨ててよいもの」と読んで消した** | **▽自由は採用である。**消してはならない。🗂保留・❌却下とは別物 |
| **🎚◎必須 に抵触する案を、無警告で並べた** | `⚠️抵触` を付けて出し直す。◎必須・○優先への抵触は**省略禁止** |
| 塩漬けの警告に 🎚△希望・▽自由 を混ぜた | **挙げるのは ◎必須・○優先 だけ。**△▽は未使用でも挙げない |
| **収束時に 🎚○優先 を落としたのに、理由を書かなかった** | ○優先は「落とすなら理由が要る」段。**外した理由を1行ずつ書く** |
| 🎚ランクを記号だけで書いた（`◎` とだけ書いた） | **記号＋言葉をセットで書く**（`◎必須`）。△ と ▽ は形が似ていて読み違える |
| 📋宿題を更新せず、新しい論点を会話の中だけに残した | 毎ターン更新。コンテキスト圧縮で消える |
