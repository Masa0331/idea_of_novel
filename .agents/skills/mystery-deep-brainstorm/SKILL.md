# ミステリー深掘りブレインストーミング

## 概要

エンタメ要素の多い広義のミステリー小説のための、選択駆動型ブレインストーミングを実施する。

**中核原理：完成案を一発で出すのではなく、「多様な案の提示 → ユーザーによる部分選択 → 嗜好の言語化と確認 → 選択要素を制約とした次世代案の生成」のループでアイデアを煮詰める。**

**部分選択の主役は「丸ごと採用」ではなく「この設定は残して、あとは作り直す」である。** ユーザーは1回の返答で、複数案に対して別々の指示（案2は舞台だけ残して再生成／案1と案3を合成／案4は却下）を同時に出す。これを1ターンで受け取り、次の一覧の枠に割り当てて生成するのがこのスキルの中心動作である（フェーズ2〜4）。

<HARD-GATE>
フェーズ2〜4のループを最低2周完了し、ユーザーが明示的に「収束」「まとめて」等を指示するまで、完成あらすじを出力してはならない。「テーマが十分具体的だから」「ユーザーが急いでいそうだから」は例外にならない。ルールの文言への違反は、ルールの精神への違反である。
</HARD-GATE>

### 使う記号（これだけ。増やさない）

```text
状態   ✅確定  🔵有力  🟡検討中  🗂保留  ❌却下
ランク ◎必須  ○優先  △希望  ▽自由        （必須度。`?` はAIの提案段階）
出力   📍現在地  📊ステータス  📥受領  ⭐AIの推奨  ⚠️注意・違反  🔎所見
その他 🎯トリガー（保留を再浮上させる裁定点）  📋宿題  〔注N〕初読メモ
```

- **見出しや強調に絵文字を足さない。**上の記号は意味を持つものだけである

## 状態管理（最重要）

会話コンテキストの記憶に頼らず、**毎ターン3本すべてを更新する。**雛形はこのスキルと同じフォルダにある `tree-template.md` `preferences-template.md` `issue-map-template.md`。

| ファイル | 軸 | 持つもの |
|---|---|---|
| `brainstorm/<セッション名>_tree.md` | **時間軸** | ノードID（N1、N1-2）ごとの記録。枠指定の原文／枠割り当て／**採用内容の全文**／由来／親ノード／しおり。冒頭に**採用カウンタと採用ID索引**、末尾に**📋宿題**と**🗂保留** |
| `brainstorm/<セッション名>_preferences.md` | **制約軸** | **いま有効な制約・嗜好・却下理由だけ。**全文は書かず、ノードIDで参照する |
| `brainstorm/<セッション名>_論点マップ.md` | **主題軸** | **論点ごとの横断ビュー。**「この論点は何が確定し、どんな案があり、何を却下したか」 |

- `_summary.md` は収束フェーズ（6）でだけ作る
- **3本で同じ内容を二重に持たない。**採用内容の全文が置かれるのは tree.md だけ
- 新規セッションでは**3本とも初期化時に作る。**再開時に欠けていたら、その場で全ノードを走査して作る

### 記法（3つの規則）

**1｜`brainstorm/` 内では表を使わない**

カテゴリ分けしたブロック・カード形式で書く。カードの形は1行目に `**<状態>｜<見出し>**`、内容は配下の箇条書き。

```text
**✅確定（S-21・◎必須）｜誠一郎自身が、そう書いたから**
- 理由＝シマハヤブサがラーテンではないかという疑惑を持ち始めていたから

**❌却下｜(b) 赤子を渡すだけ。正体は明かさない**
- ※AI最有力だったが不採用。「半信半疑の6年」のほうが選ばれた
```

- 時系列・優先順位は**番号つきカード**（`**#5 受け渡し**` / `**1｜〈論点〉**`）にする
- **この規則は summary.md・polish.md など、このスキルが生成する全ファイルに及ぶ**
- ⚠️**表は途中に行を挿し込むと壊れる。**実際に孤立行が2箇所残る事故が起きている（2026-08-17 修正）

**2｜管理番号を `brainstorm/` の外へ持ち出さない**

`S-33` `P-01` `N1-20` `B-11` などの番号は、`02_設定/` `05_資料・参考文献/` `01_free_memo/` に書き込まない。

- 理由＝**番号は内部管理用で、設定ファイルを読む人には意味が分からない。**セッションが終われば対応表も追えなくなる
- 外のファイルへ反映するときは、**決まった中身をそのまま普通の言葉で書く**
- 出どころが要るときは**ファイル名と日付だけ**（例：「縦軸ブレスト・2026-08-19 確定」）
- ⚠️**例外は2つ**：①ユーザーが「このファイルには番号を書いてよい」と指定したファイル ②フェーズ6の「要手動反映リスト」（ブレスト側の出力なので番号可）
- 指定を受けたら、そのファイル名を preferences.md に書き足す

**3｜説明は普段使いの言葉で書く**

一読で意味が1つに決まる、話し言葉に近い日本語で書く。読み返さないと意味が取れない文は、それだけで案の良し悪しを判定できなくする。**伝わらなかった案は、悪い案と同じように捨てられる。**

⚠️**言葉を2種類に分ける。かかる規則が違う。**

- **説明の言葉（この規則の対象）** … 案の中身・狙い・継承／更新／橋渡し・⭐推奨の理由・⚠️抵触・🔎所見・📊ステータス・質問文・状態ファイル3本の記述
- **作品の中の言葉（対象外）** … セリフ案・地の文の表現案・タイトル案・作中の文書（手紙・記事・供述）。**難しい言葉も古い言い回しも、人物と場面に合うならそのまま使ってよい。**平易にするのは、その案の**説明のほう**

書き方（3つとも満たす）：①抽象語・評論語・カタカナ語は日常語に置き換える ②「誰が・いつ・誰に対して」を省かない ③1文で1つのことだけ言う。

```text
✕ 情緒的カタルシスの担保が弱い     ◯ 読者が最後に「よかった」と思える場面がない
✕ 動機に構造的必然性がある         ◯ この人物なら、たしかにこうするしかない、と読者が納得できる
✕ 読者のミスリードをレイヤー化する ◯ 読者の勘違いを、二段構えで仕込む
✕ 犯人だと分かる場面を置く         ◯ 探偵が、終盤で、犯人が誰かに気づく場面を置く
```

- ミステリー用語（叙述トリック／クローズドサークル／フーダニット等）は使ってよい。ただし**初出の1回だけ**短い言い換えを括弧で添える
- 迷ったら、**その一文を声に出して読み、そのまま人に話せるか**で判断する

### 論点マップ

tree は時系列で伸びるため「この論点、結局どうなってるんだっけ」が追えなくなる。その一点だけを解決するファイルである。

- **論点ごとにセクションを作る。**ノード順・時系列順に並べてはならない。複数ノードにまたがる議論を**1箇所に集約する**
- 各項目に状態マーク（✅🔵🟡🗂❌）を付ける。✅にはランク（◎○△▽）も添える
- **冒頭に「📌 いま止まっている場所」**を置き、裁定待ちを優先順に並べる。**再開時はここだけ読めば続きに入れる**
- **内容は要約。全文は tree.md のノードIDを参照する**
- **❌却下は理由つきで必ず残す。**消すと同じ案を再提案してしまう
- ⚠️**却下の書き分け**：論点に紐づく却下は**論点マップ**へ／論点が立つ前の却下・未言及は**preferences**へ。両方に書かない

**更新は毎ターン。**新しい論点が生まれた／状態が動いた／案が却下された／📌の優先順位が変わった、のいずれかが起きたらその場で直す。変更が無いターンでも更新日だけは書き換える。

### アイデアの置き場所（採用・保留・却下の3つ）

提示した案は3つのいずれかに置く。**不採用案の全文を残してはならない。**

| 置き場所 | tree.md での扱い | 戻れるか |
|---|---|---|
| **✅採用** | 全文を残し、P-／S- 番号を振る | — |
| **🗂保留** | **1行アーカイブ**（タイトル＋主軸＋一言）だけ残す | ○ |
| **❌却下・未言及** | **tree.md から消す。**理由を preferences に1行 | × |

- 保留にするのは、ユーザーが「N保留」と言った案、または**AIが「捨てるのが惜しい」と判断した案（1ノードにつき最大2件）**
- 1行アーカイブは、後から戻ったとき AI が再展開できる密度で書く（例：`【4】逃がした日に死んだ／限界の日に檻を開け放つ。振り返らない鳥`）
- 部分採用のときは、**採用されたファセットだけ全文で残し、その案の残りは消す**
- ステータスが「選択待ち」のノードは、まだ採否が決まっていないので**全案を全文で保持する**。選択を受け取った時点で圧縮する

**🎯トリガー付きの保留（省略できない仕組み）**

**「この案を採る。でも、それによって消える別案が惜しい」——このとき、ただの保留に落とすと戻るきっかけが無いまま埋もれる。**それを防ぐのが 🎯トリガーである。

- **🎯トリガーのある保留は、その論点を扱うターンで、AI が必ず対抗案として出す義務がある**
- 🎯トリガーの無い保留は、ただの控え。戻るきっかけは無い
- **ユーザーが「惜しい」「捨てたくない」「別案としても見たい」と言ったら、必ず 🎯を付ける**
- **ある採用が別の魅力的な設定を構造的に排除した**と AI が気づいたときは、AI の判断で 🎯を付けてよい
- ⚠️**保留は採用ではない。S番号を振ってはならない**（採用されたときに初めて番号が付く）
- **🎯付きは、AI判断の上限2件の外**（数に入れない）

置き場所は tree.md の `## 🗂保留` 節（`## 📋宿題` の直後。どちらも「まだ決まっていないもの」の棚だから隣に置く）。

```text
**🗂保留-01｜〈一言タイトル〉**  🎯〈トリガーの論点名〉
- 日付／発案（ユーザー or AI）
- 内容：〈後から再展開できる密度で。トリガー無しの1行アーカイブより厚く書く〉
- ⚠️競合：〈S番号を挙げ、どう衝突するかを1行ずつ〉
- ⭐これが解くもの：〈採用された場合に埋まる宿題・確定へ動く設定〉
```

- **🎯トリガーは論点名で書く。**「あとで」「そのうち」は無効。**そのターンの話題がトリガーに当たるかを AI が機械的に判定できる粒度**にする
- 発火するときは `【対抗｜🗂保留-01】` の枠で⭐推奨案と並べて出す。⚠️**W（ワイルドカード）とは別枠。**W は「まだ出ていない逆張り」の枠であり、保留で潰してはならない
- 出す前に **⚠️競合を最新の状態で洗い直す。**時間が経つと、競合していたはずの設定が既に変わっていることがある
- ⭐**本線と排他とは限らない。**合成の余地があれば所見で示す
- 裁定されたら、採用なら S番号を振ってノードへ／不採用なら理由を preferences へ1行書き、**行ごと消す**
- 論点マップの「📌 いま止まっている場所」に、**件数とトリガーを1行で載せる**

> ⚠️**旧セッションの互換**：`## 🥊 対立案の予約` 節がある古い tree.md は、**そのまま「🎯トリガー付きの保留」として読む。**節名だけ揃えればよい。

### 採用ランク（必須度）

**「採用した」だけでは足りない。**「これが無いと話が成り立たない設定」と「はまる場所があれば使いたい設定」を同じ棚に置くと、**収束のときにどちらも同じ重みで扱ってしまう。**

```text
◎必須 … これが無いと話が成り立たない。落とせない
○優先 … 使えるなら必ず使う。落とすときは理由を書く
△希望 … はまる場所があれば使う。無くても話は立つ
▽自由 … 使わなくてよい。使えたら得
```

- ⚠️**記号だけで書かない。**`◎必須` のように言葉を付ける（△ と ▽ は形が似ている）
- ⚠️**`▽自由` は「採用」である。**🗂保留（採用されていない）・❌却下（捨てた）とは別物。**消してはならない**
- 🔎 A/B/C/D を使わないのは、**A〜H が論点マップの節番号と選択肢のラベルで既に使われている**ため。★★★を使わないのは、**★が「新規・重要」の印として既に使われている**ため

**未確定のランクには `?` を付ける**

- `◎?` `○?` … **AI が提案しているだけの状態。**ユーザーが `?` を外して確定する
- ⚠️**AI がランクを `?` 無しで確定してはならない**（「AI は先回りして裁定しない」と同じ原則）

**付け方**

- **裁定を受け取るときに、採否と一緒に受け取る**（例：「E＝採用・△希望」「S-25 は◎」）
- **ユーザーがランクを言わなかったら、AI が推定して `?` 付きで `📥受領` 行に1行示す。**訊かない（曖昧判定には当たらない）
- 後から変えてよい。変えたら索引の記号を書き換えるだけ

**何に効くか（5つ。ここがランクの実体である）**

1. **案を作るとき** … ◎必須は必ず反映／○優先は反映を試み、外すなら理由を1行／**△希望・▽自由は反映しなくてよい**
2. **⚠️抵触の判定** … **◎必須・○優先に抵触したら必ず出す。**△希望・▽自由への抵触は報告しなくてよい（警告のノイズが減る）
3. **合流点の塩漬け警告** … **◎必須・○優先だけを挙げる。**△▽が未使用でも挙げない
4. **フェーズ6の収束** … ◎必須は全部入れる／**○優先が入らなかったら理由を1行**／△▽は一覧に載せるだけ。⭐**使えなかった △▽ は「ボツにしたが光る要素リスト」へ回す**
5. **書く場所は3つだけ** … tree.md の採用ID索引／ノード側の定義行（`**S-07【✅確定・○優先】見出し**`）／論点マップの確定カード。**preferences には書かない**

### 採用カウンタと採用ID索引

採用した要素には通し番号を振り、tree.md 冒頭に現在値を1行で書く。合流点の発火判定に使う。

- **案（P-01, P-02…）** … 丸ごと／主軸として採った案。合成して1本になった場合も1件
- **設定（S-01, S-02…）** … ファセット単位で採った要素。ユーザー発案の新設定も含む
- 言い換えだけの再登場は数えない

```text
採用カウンタ：案 4（P-01〜P-04）／設定 7（S-01〜S-07）
```

**索引は、採番と同じ1操作として書く。**tree.md は時系列で伸びるため、`S-21` がどのノードにあるかは全文を読まないと分からない。それを解決するのが索引である。

- **置き場所＝採用カウンタの直下。**隣接させること自体が書き漏らしの防止装置である
- **1行6項目**：`- **S-07** 〈一言〉 … 〈ランク〉／〈状態〉／全文＝**N1-2**（発案 **N1-1**）／論点マップ **B-3**
- **一言には内容語を入れる**（「傷の一致」「登録票の一行」）。抽象語だけだと検索で当たらない
- **確定ノードと発案ノードが違うときは両方書く。**ユーザーの指摘が後のノードで採用される流れは頻出で、発案ノードだけでは定義に辿り着けない
- **❌破棄・格下げになった番号も行ごと消さず、状態マークだけ書き換える。**消すと番号が再利用され、過去の記述と衝突する
- **索引に全文を書かない。**ここは目次である
- ⚠️**検算：採用カウンタの数字＝索引が持つ番号の数。**毎ターン確認する。ズレていたら索引が漏れている（枝番 `S-11a`/`S-11b` は**1番号**として数える。行数ではなく番号の数で検算する）
- ノード側で S番号を初出させるときは行頭を **`**S-07【✅確定・○優先】見出し**`** の形にする。`S-07【` で定義行だけを直接検索できるようにするため

### 宿題リスト

**決めたことだけでなく、決まっていないことも追跡する。** tree.md の末尾に `## 📋宿題` を置き、1行ずつ記録する。

- **未解決論点** … これを決めないと先へ進めないのに、まだ決めていないもの
- **仮置き** … 仮の値・仮の理由で置いてあり、後で確定が必要なもの
- **既知の抵触** … `⚠️抵触` が出たまま採用され、まだ解消していないもの

書式：`- [ ] 〈一言〉（発生：N1-2 ／ 種別：論点／仮置き／抵触）`

- **毎ターン更新する。**新たに生じたものを足し、**解決したものは行ごと消す**
- **発散の軸を選ぶときは、まず宿題リストから選ぶ。**宿題が3件以上たまっているのに無関係な軸で発散を続けるのは違反
- 合流点で残件を必ず併記する

## 進め方（毎ターン）

### 運用モード（通常／考察）

**現在のモードは preferences.md の「運用モード」節に1行で記録し、毎ターン引き継ぐ。**

| モード | AIからの新規質問 | 案の生成 | 既定 |
|---|---|---|---|
| **通常モード** | 1ターン1問まで出す | 出す（フェーズ1〜4） | ✅ |
| **考察モード** | **出さない** | ユーザーが求めたときだけ | — |

**考察モード**は、溜まった案・論点を、新しい発散を挟まずに片づける局面のためのモード。

- **起動**：「考察モード」「質問やめて」「論点解消モード」等の指示。**AIの自己判断で入ってはならない**
- **解除**：「通常モード」「案出しに戻って」「発散再開」「質問していい」等の合図。**解除もユーザーの合図でのみ**
- **やらないこと**：AIからの新規質問。ターン末尾の1問。⚠️**「〜しましょうか？」「どちらにしますか？」も質問である**
- **通常モードと変わらないこと**：⭐推奨と理由／⚠️抵触／🔎所見／選択肢の提示（**質問の形にせず、置くだけ**）／状態ファイル3本の毎ターン更新
- **返してよいもの**：ユーザーの問いへの回答、ユーザーが書いた内容の確認・整理・矛盾の指摘
- ⚠️**批評役は降りない。**質問を止めることと、無条件に同意することは別である
- **進行の主導権はユーザーにある**

### ターン頭の2行（両モード共通・省略禁止）

```text
📍現在地: N2-1（ルートからのパス: テーマ > 案2 > 深掘り1）
📊 裁定待ち3 ／ 宿題16（論点8・仮置き6・抵触2）／ 保留2（🎯1）／ 採用 案1・設定24（未ランク5）
```

- **0件の項目は書かない**（保留0件なら `保留` ごと省略）
- ⚠️**裁定待ちが6件以上になったら数字の前に `⚠️` を付ける**（`裁定待ち⚠️6`）。**これがアラート。別行にしない**
- 溜まり具合を常に見えるようにするための行である

### 効き先チェック（設定を1つ確定・提案するたび）

新しい設定が、既存のどの論点を「解く」か「壊す」かを、**最大3行で**示す。

```text
効き先：S-23 は【S-17 檻を出られない理由】を解く／【S-14 の芯】を壊す（「見落とした」が成立しなくなる）
```

- ⚠️**壊す側の報告を省略してはならない。**新しい設定が既存の確定を無効化していることに気づかないまま進むのが、**このスキルで最も高くつく事故**である
- 効き先がない設定は行ごと省略してよい

### 初読メモ（あらすじを書き出したら必ず付ける）

**あらすじ・プロット・ストーリー的なまとめを書き出したら、その場で「初めて読んだ人が引っかかる場所」に注を付ける。**

⚠️**作った側の知識を、いったん全部捨てて読む。**ここまでの議論を知らない人が、**その原稿だけ**を読んだときに何を思うか——見るのはそれだけである。「前に決めたから分かるはず」は通用しない。

**3種類**

- **疑問** … 「なんで？」と思う（説明が無い／順番が飛んでいる／根拠が示されていない）
- **引っかかり** … 説明はあるが腑に落ちない（その人物がそうするとは思えない／前の章と食い違って見える）
- **ご都合** … 都合よく運びすぎている（偶然が重なる／タイミングが良すぎる／知りすぎ・知らなさすぎ）

**書き方**：本文には `〔注1〕` だけ置き、注釈は**その章の直後**にまとめる。読みを止めないため。

```text
**〔注3〕どうやって檻から連れ出したのか**　ご都合
- 初読者：「調査員が閉館後の猛禽舎に一人で入って、鳥を持ち出せるのか」と思う
- ⭐処方：鍵を持っている理由を1行だけ先に置く（S-06 が使える）
- 🟡未処置
```

**ルール**

- **数を絞る。1章あたり最大3件。**初読で**確実に止まる**ところだけ。全部に付けると読めなくなる
- **状態は3つ**：🟡**未処置** ／ ✅**処置済み**（どう直したかを1行）／ 🗂**あえて残す**（残す理由を1行）
- ⭐**「あえて残す」は逃げではない。**先の章で明かす謎なら、**引っかかること自体が正しい**。ただし**どこで回収するかを書く**
- ⚠️**注は消さない。**処置しても ✅ にして残す（同じ指摘を繰り返さないため）
- ⚠️**🟡未処置の注は📋宿題に1行足す**
- **⭐処方は必ず添える。**指摘だけして終わりにしない

**⚠️ 似た3つとの違い（混ぜない）**

- **⚠️抵触** … 決めた制約に触れていないか（**ルール方向**）
- **効き先チェック** … 新しい設定が既存の確定を壊していないか（**因果方向**）
- **初読メモ** … **何も知らない読者がどう読むか**（**読者方向**）

## フェーズ構成

### フェーズ0：セッション設定（1〜2ターン）

質問は1メッセージに1つだけ。①大雑把なテーマ・出発点 ②絶対に入れたい要素／避けたい要素 ③グリル強度（light／standard／hard、既定 standard）。

分量・シリーズ構想などは必要になった時点で聞く。最初に質問攻めにしない。

### フェーズ1：発散

方向性の異なる案を **4〜6個＋ワイルドカード（W）1個**提示する。

- 各案は互いに**異なるファセット軸**を主軸にする。同系統の焼き直しは禁止
- **W は「あえて逆張り・意外な組み合わせ・概念衝突」に必ず割り当てる**

### フェーズ2：部分選択（枠指定）

ユーザーは案を丸ごと選んでも、要素単位で選んでも、**案ごとに別々の処理を指定してもよい。**これを促すため、各案は提示時点でファセット分解しておく。

**処理の6種類**

| 処理 | 意味 | 次の一覧で使う枠 |
|---|---|---|
| **改** | 案Nの指定された設定だけを保持し、**それ以外は作り直す** | 1枠（`×N` で複数枠） |
| **合成** | 複数案の指定された設定を組み合わせて1案にする | 1枠 |
| **維持** | 案Nを変更せず次の一覧にも残す | 1枠 |
| **保留** | 一覧からは下ろすが、1行アーカイブを残す。**🎯トリガーを付ければ、その論点で必ず再浮上する** | 0枠（🎯発火時に1枠） |
| **却下** | 捨てる（tree.md から削除し、preferences に理由を1行） | 0枠 |
| **新案** | 残り枠を新規発想で埋める | 残り全部 |

⚠️**維持と保留は別物。**維持＝次の一覧にもう一度出す（枠を使う）／保留＝一覧からは下ろすが記録は残す（枠を使わない）。

**記法（ショートハンド・テンプレート・自然文のすべてを解釈する）**

```text
2改[舞台,主人公] 5改[フック] 1+3合[1のトリック+3の動機] 4保留[🎯死の場面] 6却下
```

- `N改[残す設定]` … `[ ]` は省略可（省略時は下の「曖昧判定」に従う）
- `N改×3` … 同じ縛りで3案つくる
- `N+M合[使う設定]` … 3案以上の合成 `1+3+5合` も可
- `N維持` / `N却下` / `N,M却下`
- `N保留[🎯トリガーの論点]` … 🎯は省略可。⚠️**省略されたら AI がトリガーを1行で提案して受領行に書く**（訊かない。違えばユーザーが直す）。**旧記法 `N予約[...]` も同じ意味に解釈する**
- `新案3枠` / `残り新案` / `全部で8案`
- **自然文でも同じ意味に解釈する。**記法を強制しない

**枠配分ルール**

1. 既定の総数は **4〜6案＋W1個**
2. **指定枠（改・合成・維持）を先に確保**し、残りを新案で埋める
3. ⚠️**W枠は常に確保する。**指定枠で埋まりきっても W だけは必ず出す（固着防止）
4. 指定枠の合計が6を超えるときは総数を最大8まで広げ、受領行に1行で断る。8を超えるときだけ、どれを落とすか確認する
5. ユーザーが総数を指定した場合はそれに従う
6. **言及のなかった案は却下扱い。**聞き返さず preferences に「未言及（理由は推定）」と1行だけ残し、tree.md からは全文を削除する。惜しい案は AI 判断で保留に回してよい

**曖昧判定（ここに当たるときだけ、1問だけ確認する）**

明確な指定なら**確認せず即生成する。**以下のいずれかに当たるときだけ、**該当箇所だけを1問で**確認する：

- 「残す設定」が明示されておらず、案の記述からも一意に定まらない
- 合成で**同じファセットが複数案から指定されて競合している**
- 指定枠が上限（8）を超え、どれを落とすか判断できない

確認は、AIの推奨解釈を先頭に置いた選択肢形式にする。

### フェーズ3：傾向確認

2周目以降、選択のたびに preferences.md を更新し、**2〜3周ごと**に AI が推定傾向を言語化して確認を取る。

- ⚠️**キープ指定は最も強い嗜好シグナル。**「この設定は残して」と言われた設定は、単発の採用ではなく**以後の既定の制約**として preferences の「確定済みの制約条件」へ昇格させる（ユーザーが外すまで有効）
- 合成の相性（噛み合った／噛み合わなかった組み合わせ）も蓄積し、次の合成提案に反映する
- **暗黙の推定のまま進めない。**誤学習と固着をここで防ぐ

### フェーズ4：再生成

「枠割り当て＋選択済み要素＋確認済み嗜好」を制約として次世代案を提示し、フェーズ2へ戻る。

**枠ごとの生成規則**

- **改案** … 「残す」と指定された設定は**核を保持する**（言い換え・描写の変更は可、別物への差し替えは禁止）。**それ以外のファセットは必ず実質的に変える。**語尾だけ変えた焼き直しは違反
- **合成案** … 各案から持ち込む設定を明示し、**噛み合わせるために足した設定（橋渡し）を1行で示す。**「並べただけ」で因果がつながっていない合成は不可
- **維持案** … 前回の文面をそのまま再掲する。勝手に「改善」しない
- **新案** … 指定枠と**異なるファセット軸を主軸にする**
- **W** … 常に逆張り・意外な組み合わせに割り当てる
- ⚠️**改案どうしが似通ってはならない。**「残す設定」が違う以上、更新側も違う方向へ振る

生成後、残せと指定された設定が案の足を引っ張っている場合は `🔎所見` として遠慮なく指摘する（無条件に従わない。批評役を降りない）。

**分量**：既定は1案あたり3〜6行。同じターンの案どうしで大きくばらつかせない。ユーザーが「3行で」「もっと詳しく」と言ったらそれに従い、**以後の既定として維持する**（毎回指定させない）。

**生成後の必須チェック（2つ・省略禁止）**

1. **制約バッティング検出** … 各案を preferences の「確定済みの制約条件」と機械的に突き合わせ、抵触するものに `⚠️抵触` を1行付ける。**必ず出すのは ◎必須・○優先 への抵触**（△▽への抵触は報告不要）
   - ⚠️**これは「違反案を出すな」ではない。**制約違反案が採用されることは実際にある
   - ⚠️**禁じるのは、抵触に気づかないまま並べること、とりわけ抵触案を無警告で推奨に据えること**
   - 抵触したまま推奨するなら、**なぜその制約より優先するのかを1行添える**
2. **宿題の更新** … その世代で生じた未解決論点・仮置きを追加し、解決したものを消す

### フェーズ4.5：合流点（「棚卸し」と同じもの）

**発火は2通り。**

1. **自動** … 採用カウンタが **案6 または 設定10** 増えるたび、**次の案を生成する前に**必ず出す
2. **手動** … ユーザーが「棚卸し」「合流点」「カウンタ」と言ったとき

**出す内容（6つ）**

1. **ここまでの採用一覧**（ID・ランク付きで1行ずつ）
2. **一度も案に組み込まれていない採用設定**（塩漬け防止。⚠️**◎必須・○優先だけを挙げる**）
3. **📋宿題の残件**（種別ごとの件数＋論点だけ全文）
4. **🗂保留の一覧**（1行ずつ・**🎯トリガーを併記する**）
5. **裁定待ちの一覧**（1行ずつ・優先順）
6. **次の選択肢**（⭐推奨を先頭に置く）

```text
合流点：採用が案6／設定10に達しました。
（採用一覧／未使用の◎○設定／宿題／保留／裁定待ち）

　⭐A) 採用案を束ねて1本にブラッシュアップする
　　B) 採用設定（とくに未使用のもの）を使った新案をつくる
　　C) このまま発散を続ける
　　D) 磨き（pinpoint-polish）へ移る
```

- ⚠️**モードで違うのは 6 だけ。**通常モード＝質問にしてよい／考察モード＝**選択肢を置くだけで質問にしない**
- **A・B の出力は tree.md の新しいノードとして記録する**（summary.md には書かない）。束ねた1本は新しい P- 番号を振り、元の採用案は統合済みとして残す
- **C を選ばれたら、次は +6案／+10設定に達するまで自動発火しない。**毎ターン訊くのは違反
- ⚠️**合流点は HARD-GATE を解除しない。**A も B もフェーズ2〜4の中の動作である
- 「案が1つに決まっているのに発散が続いている」と感じたときの磨きへの誘導も、**ここにまとめる**（別途1問で訊かない）
- Claude Code では選択肢の提示に `AskUserQuestion` を使ってよい（推奨を先頭に）

### フェーズ5：グリルモード（ストレステスト）

案が固まってきたら（またはユーザーが「グリル」と指示したら）尋問モードに切り替える。

- 最も不確実性の高い論点を1つ選び、**1ターンに1問**、狭く具体的に問う。「もっと詳しく」のような曖昧な質問は禁止
- **各質問には必ず AI の推奨回答と理由を添える**
- その論点が解決するまで次に移らない。解決したら要約して確認を取る
- 判断間の依存関係は明示する。リスクのある判断・矛盾には遠慮なく反論する
- ミステリー固有の定番論点：トリックの穴／動機の納得度／伏線の配置と回収／読者へのフェアネス／ミスリードの成立条件／ご都合主義の有無
- 強度は「softer」「harder」でいつでも変更できる
- 穴が見つかったら該当ノードへ戻り、フェーズ1〜4で再発散する

### フェーズ6：収束・出力

ユーザーの明示的な指示でだけ実行する。

1. 採用した枝の全要素を統合し、あらすじ確定版を作成
2. **初読メモを付ける**（→「初読メモ」）。**矛盾・ご都合・浅い描写・未回収の伏線・曖昧な動機は、ここで注として出す。**🟡未処置が残るなら 4 で報告する
3. **多視点レビュー**：「ミステリー読者」「担当編集者」の2視点＋プロジェクト内に style_guideline.md / writing_rules.md があればその基準で短評
4. **📋宿題の残件を報告する。**未解決のまま収束するなら明記する（黙って閉じない）
5. **ランクの消化を報告する（省略禁止）** … **◎必須がすべて入っているかを1件ずつ確認する。**⚠️**入らなかった ○優先 は、外した理由を1行ずつ書く。**△▽は「使った／使わなかった」の一覧だけでよい
6. **要手動反映リストの作成（省略禁止）** … このセッションの決定によって**更新が必要になった既存設定ファイルを列挙する**
   - 形式：`- 02_設定/キャラクター/chr_xxx.md … 〈どの決定により、どこが変わるか〉（S-05）`
   - ⚠️**AI が勝手に書き換えてはならない。**一覧を出し、更新するかどうかはユーザーが決める
   - tree.md 冒頭の「前提」節も対象に含める
7. summary.md に保存。**「ボツにしたが光る要素リスト」を別セクションで必ず併記する。**素材は tree.md の**保留アーカイブ**、preferences の**却下理由**、そして**使えなかった △希望・▽自由**から集める

### 選択肢の末尾に添えるフッター

**全文版を出すのは、①初回の発散時、②ユーザーが「テンプレ」と言ったとき、の2回だけ。**毎ターン出すと画面が埋まる。

```text
選び方：番号のみ（丸ごと採用）／要素単位／下の枠指定テンプレ

─ 枠指定テンプレ（コピーして編集）───────────
改  : ● → 残す「          」
合成: ●+● → 使う「●の      ＋●の      」
維持: ●
保留: ● → 🎯「          」（惜しい案。トリガーを書けば必ず再浮上）
却下: ●,● → 理由「          」
新案: 残り枠すべて
──────────────────────────
1行で書くなら：2改[舞台,主人公] 5改[フック] 1+3合[1のトリック+3の動機] 4保留[🎯死の場面] 6却下
自然文でも通ります（「2と5は舞台を残して作り直し、1と3は混ぜて、4は惜しいので取っておいて、6はなし」）

その他：[全部却下・出し直し] [この方向でさらにN案] [しおり] [比較] [棚卸し] [グリル] [テンプレ]
```

**短縮版（2ターン目以降）：**

```text
選び方：番号／要素単位／枠指定（例：2改[舞台] 1+3合 4保留 6却下）　※全文は「テンプレ」
その他：[出し直し] [さらにN案] [3行で／もっと詳しく] [しおり] [比較] [棚卸し] [宿題] [ランク] [グリル]
```

## ファセット軸（ミステリー固定）

案の分解・部分選択・多様性保証に使う軸：

- **フック**（前提の面白さ・一言で言える売り）
- **主人公**（探偵役の造形・欠点・視点）
- **敵・対立構造**（犯人・障害・社会的圧力）
- **トリック・謎**（HOW／WHO／WHY／WHATダニット）
- **動機**（納得度と意外性の両立）
- **舞台**（時代・場所・業界・ローカル性）
- **構成**（時系列・視点・章立て・叙述の仕掛け）
- **結末の余韻**（カタルシス／苦味／どんでん返し）
- **テーマ**（物語の思想的背骨）
- **エンタメ要素**（コメディ・アクション・恋愛・グルメ等の配合）

## 操作コマンド一覧

**枠指定（フェーズ2の中心操作）**

- `2改[舞台,主人公]` … 案2の舞台と主人公を残し、それ以外を作り直す
- `2改×3` … 同じ縛りで3案つくる
- `1+3合[1のトリック+3の動機]` … 案1と案3の指定設定を合成して1案にする
- `4維持` … 案4をそのまま次の一覧にも残す
- `4保留` … 一覧からは下ろし、1行アーカイブを残す
- `4保留[🎯誠一郎の死の場面]` … **その論点に来たら、AI が必ず対抗案として再提示する。**「惜しい」「捨てたくないけど今は採らない」も同じ扱い（旧記法 `4予約[...]` も可）
- `4,6却下` … 不採用（理由は任意。書かなければ AI が推定して記録する）
- `残り新案` / `新案3枠` / `全部で8案` … 枠と総数の調整
- `全部改[〇〇]` … 全案に同じキープ指定をかけて作り直す
- `テンプレ` … 枠指定テンプレートの全文を再表示

**確認・一覧**

- `棚卸し` / `合流点` / `カウンタ` … 合流点を手動で出す（考察モード中は質問なし）
- `宿題` … 📋宿題の残件を一覧表示。「宿題1を片付ける」でその論点を発散軸に指定できる
- `保留` … 🗂保留の一覧を、🎯トリガー付きで表示する
- `ランク` … 採用設定をランク別（◎○△▽／未ランク）に一覧表示する
- `一覧` … しおり一覧と現在地パスを表示
- `比較 N1-2 N1-3` … 2枝の内容を並べて比較し、AI の優劣所見と理由を添える
- `手動反映` … 現時点の決定によって更新が必要な既存設定ファイルの一覧を出す
- `初読メモ` / `読者の目で見て` … いまのあらすじを、**何も知らない読者として**読み直し、注を付け直す

**裁定・変更**

- `S-25＝◎` / `E＝△` / `S-03 は▽` … ランクを付ける／変える。`?` が付いていれば外れて確定になる
- `ランク提案` … 未ランクの項目に、AI が `?` 付きの推定ランクをまとめて提案する
- `3行で` / `もっと詳しく` / `粒度` … 案1つあたりの分量を変更する（**以後の既定として維持する**）

**セッション操作**

- `考察モード` / `質問やめて` / `論点解消モード` … 考察モードに入る（AIからの新規質問を停止。推奨・抵触・所見は継続）
- `通常モード` / `案出しに戻って` / `発散再開` / `質問していい` … 通常モードに戻る
- `しおり` … 現在ノードに⭐を付け、tree.md 末尾の一覧にも転記
- `N1-2に戻る` / `しおり2に戻る` … 該当ノードを読み直し、未選択だった選択肢を再提示。新しい選択は新しい枝番号で記録し、**元の枝は削除しない**
- `グリル` / `softer` / `harder` … フェーズ5の開始と強度変更
- `トリック錬成` … `.agents/skills/twist-trick-forge/SKILL.md` を読み込む。**新規ファイルは作らず**、現在の tree.md に枝を継ぎ足し、preferences をそのまま引き継ぐ
- `磨き` / `ポリッシュ` … `.agents/skills/pinpoint-polish/SKILL.md` を読み込み、**現在ノードの案を本文として持ち込んで**1箇所ずつの修正に接続する。**ユーザーに案を貼り直させない。**作業ファイルは `brainstorm/<セッション名>_polish.md`
- `収束` / `まとめて` … フェーズ6へ

## よくある逸脱と対処

**進め方**

| 逸脱 | 対処 |
|---|---|
| いきなり完成あらすじを書き始めた | HARD-GATE違反。停止してフェーズ1からやり直す |
| 1ターンに複数の質問を並べた | 1問に絞って出し直す |
| 考察モード中に質問を出した | ⚠️「〜しましょうか？」も質問。**選択肢は置いてよいが、問いの形にしない** |
| AIの自己判断でモードを切り替えた | 切替は**ユーザーの合図でのみ**。preferences の「運用モード」を毎ターン引き継ぐ |
| 考察モードだからと批評をやめ、無条件に通した | 質問を止めることと同意することは別。⭐推奨・⚠️抵触・🔎所見は両モード共通で省略禁止 |
| ユーザーの案を無条件に褒めて通した | 批評役として懸念・トレードオフを必ず添える |
| ユーザーの選択理由を推測だけで進めた | フェーズ3の明示確認を実施する |
| ターン頭の2行（📍📊）を出さなかった | 毎ターン出す。溜まり具合が見えなくなる |
| 裁定待ちが6件以上なのに ⚠️ を付けなかった | 📊行の数字に `⚠️` を付ける。別行のアラートにはしない |

**案の生成**

| 逸脱 | 対処 |
|---|---|
| 似た系統の案ばかり並べた | 多様性保証違反。異なるファセット軸で作り直す |
| 「残す」と指定された設定を変えた／薄めた | 枠指定違反。該当案だけ作り直す |
| 改案が元案とほぼ同じ | 焼き直し。残す設定**以外**を実質的に変えて出し直す |
| 改案どうしが似通った | 「残す設定」が違う以上、更新側も違う方向へ振る |
| 枠指定があったのに新案だけ／指定枠だけ出した | 指定枠→新案→W の順で埋め直す |
| W枠を出さなかった／保留の対抗案でW枠を潰した | **W は別枠。**固着防止が効かなくなる |
| 合成案が「並べただけ」で因果がつながっていない | 橋渡しの設定を足すか、噛み合わないと所見で指摘する |
| 継承／更新／橋渡しの明示がない | フォーマット違反。追記して出し直す |
| 推奨案や理由を省いた | 推奨＋理由を追記して出し直す |
| 指定が明確なのに確認で1ターン使った | 明確なら即生成。確認は曖昧判定に当たる箇所だけ |
| 曖昧なまま推測で生成し、1周まるごと無駄にした | 曖昧判定に当たるなら、該当箇所だけ1問で確認する |
| 同じターンの案で分量が大きくばらついた | 既定は1案3〜6行。粒度指定があればそれに従う |
| 案が1つに決まっているのに発散を続けた | 磨き（pinpoint-polish）への切り替えを1問で提案する |

**状態ファイル**

| 逸脱 | 対処 |
|---|---|
| 更新を「後でまとめて」にした | **毎ターン3本とも更新。**コンテキスト圧縮に耐えられなくなる |
| 論点マップを作らなかった／時系列順に書いた | **状態ファイルは3本。論点ごとに集約する**のが論点マップの唯一の存在理由 |
| 論点マップに全文を複写した／❌却下を消した | 要約にとどめノードIDを参照する。❌は理由つきで残す（同じ案の再提案を防ぐ） |
| 「📌 いま止まっている場所」を更新しなかった | 再開時にここだけ読めば続きに入れる状態を保つ |
| 採用内容を tree と preferences に二重で書いた | 全文は tree だけ。preferences はノードIDへの参照1行 |
| 不採用案を全文のまま tree に残した | 保留は1行に圧縮、却下は削除する |
| AI判断で保留を1ノードに3件以上つくった | 上限2件（ユーザー指定分と🎯付きは上限外） |
| 採用カウンタを更新しなかった／IDを振らなかった | 合流点が発火しなくなる。採用のたびに P-／S- を振る |
| S番号を振ったのに索引に1行足さなかった | **採番と索引は1操作。**カウンタと索引の**番号の数**が一致しない時点で漏れている |
| 索引に全文を書いた／「一言」が抽象語だけ | 索引は目次。6項目だけ。一言には**内容語**を入れる（「重要な設定」では引けない） |
| 再開したセッションに索引・論点マップが無い | 旧セッション。**その場で全ノードを走査して作る** |
| 📋宿題を更新せず、会話の中だけに残した | 毎ターン更新。コンテキスト圧縮で消える |
| 宿題が3件以上あるのに無関係な軸で発散した | 発散軸はまず宿題リストから選ぶ |
| 却下された案を preferences に記録せず捨てた | 却下理由と「光る部分」を必ず残す（フェーズ6で使う） |

**保留・ランク・抵触**

| 逸脱 | 対処 |
|---|---|
| ユーザーが「惜しい」と言った案を、🎯無しの保留にした | **🎯が無いと戻るきっかけが無い。**トリガーを付ける |
| 🎯トリガーに当たるターンなのに対抗案を出さなかった | **発火は義務。**`【対抗｜🗂保留-NN】` の枠で⭐推奨案と並べて出す |
| 🎯トリガーを「あとで」「そのうち」と書いた | **論点名で書く。**AI が機械的に発火判定できる粒度にする |
| 発火時に競合設定を保留時のまま貼り直した | **最新の状態で洗い直す** |
| 保留に S番号を振った | **保留は採用ではない。**採用が決まったときに初めて番号を振る |
| AI がランクを `?` 無しで確定した | **先回り裁定と同じ違反。**`?` を付け直す |
| ▽自由 を「捨ててよいもの」と読んで消した | **▽自由は採用である。**🗂保留・❌却下とは別物 |
| ランクを記号だけで書いた | **記号＋言葉をセット**で書く（`◎必須`）。△ と ▽ は読み違える |
| ◎必須・○優先に抵触する案を無警告で並べた | `⚠️抵触` を付けて出し直す。抵触したまま推奨するなら優先理由を1行 |
| 抵触を理由に案を勝手に取り下げた | 抵触＝禁止ではない。**気づかせるための表示**であり、採否はユーザーが決める |
| 塩漬けの警告に △希望・▽自由 を混ぜた | 挙げるのは **◎必須・○優先だけ** |
| 収束時に ○優先 を落としたのに理由を書かなかった | **外した理由を1行ずつ書く** |
| 新しい設定が既存の確定を壊しているのに報告しなかった | 効き先チェック違反。**「解く」だけでなく「壊す」を必ず書く。最も高くつく事故** |

**合流点・収束**

| 逸脱 | 対処 |
|---|---|
| 閾値に達したのに合流点を出さず次案を出した | 次案の**前**に出す |
| 「発散を続ける」と言われたのに毎ターン合流点を出した | 次は +6案／+10設定に達するまで自動発火しない |
| **あらすじを書き出したのに初読メモを付けなかった** | **書き出しと注は1操作。**その場で付ける（→「初読メモ」） |
| 初読メモを、作った側の知識を前提に書いた | **知識を捨てて読む。**「前に決めたから分かるはず」は通用しない |
| 初読メモを1章に4件以上付けた／指摘だけで⭐処方が無い | 1章最大3件。**確実に止まるところだけ。**処方は必ず添える |
| 処置した注を消した | ✅にして**残す。**消すと同じ指摘を繰り返す |
| 収束時に要手動反映リストを出さなかった | 省略禁止項目。決定が設定ファイルに反映されず埋もれる |
| 要手動反映リストを出さずに既存設定ファイルを書き換えた | 一覧を出すだけ。更新の可否はユーザーが決める |

**記法・言葉**

| 逸脱 | 対処 |
|---|---|
| `brainstorm/` 内に表を書いた | **ブロック・カード形式**へ直す |
| 既存の表に行を挿し込んで孤立行を残した | 表を使っていること自体が原因。その節ごとブロック形式へ変換する |
| 管理番号（S-／P-／N1-／節記号）を `brainstorm/` の外へ書いた | 番号を消し、中身を普通の言葉で書き直す。⚠️ユーザーが番号可と指定したファイルは対象外 |
| 説明を抽象語・評論語・カタカナ語で書いた | 普段使いの言葉へ直す。ミステリー用語は初出に短い言い換えを添える |
| 「分かる」「気づく」を、誰が・いつ抜きで書いた | 主語と時点を補って書き直す |
| セリフ案・地の文の表現案まで平易な言葉に直した | **作中で使う言葉は対象外。**平易にするのは**その案の説明のほう** |
| 見出しや強調に絵文字を足した | 「使う記号」の一覧にあるものだけ使う。増やさない |
