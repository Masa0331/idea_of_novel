# ミステリー深掘りブレインストーミング

## これは何か

エンタメ要素の多い広義のミステリー小説のために、案を出して、選んでもらって、次の案を出す——これを繰り返して話を煮詰める。

**中心はひとつだけ。AI が案を並べ、ユーザーが選ぶか、指摘で覆す。**それ以外の操作はいらない。

<HARD-GATE>
ユーザーが「収束」「まとめて」と言うまで、完成あらすじを出してはならない。「テーマが十分具体的だから」「急いでいそうだから」は例外にならない。
</HARD-GATE>

<HARD-GATE>
AI が思いついた設定を、ユーザーの承認なしに ✅決まったこと・あらすじ・02_設定/ へ書いてはならない。
「話を通すために必要だから」「明らかに良くなるから」「小さな細部だから」「(仮) を付けたから」は、どれも例外にならない。
案の中で書くのは自由である。だが、案が採用されても、AI が足した部分は自動的には決定にならない。
同じ理由で、AI が確認なしに 📋宿題 を増やしてもならない。穴は報告だけにして、宿題に入れるかどうかは訊く。
</HARD-GATE>

## 面白さを先に置く

⭐⭐ **骨格そのものを作る／作り直すのは `/fal-synopsis` の担当である。**
（`.agents/skills/quick-synopsis-forge/SKILL.md`。⭐ **骨が弱いと分かったら、そちらへ戻す**）

⭐ **ここは設定を詰める場所だが、それでも「細かい辻褄より、面白いかどうかが先」は変わらない。**設定はまだ、いくらでも変えられる。

- ⚠️⚠️ **案が前に決めた設定に引っかかっても、案のほうを丸めない。**まず**設定のほうを疑う**（→「前に決めた設定が足かせなら、外せないかを言う」）
- ⭐ **「その設定を変えて、この案を通す」を、質問の選択肢に必ず1つ入れる。**遠慮して黙るほうが損
- ⚠️⚠️ **設定を変えるなら、変わることをはっきり書く。**次の3つを必ず添える
  - **何が変わるか**（前はこう、これからはこう）
  - **それで何が困るか**（書き直しが要る場所・弱くなるところ）
  - **どこが混乱するか**（すでに別のファイルに書いてあるもの・読者が覚えているもの）
- ⭐ **現実と合っているかの確かめは、決めたあとに回す。**案の段階で止めない。決まったら 📋宿題の「確かめる」に1行足すだけ
- ⚠️ ただし、状態ファイルの **「絶対の制約」だけは案の段階でも守る。**そこはユーザーが自分で置いた壁である

⭐ **行き着く先はプロット。**各話のあらすじと、登場人物が何をするかを具体的に書いたものを作り、そこから小説を書く。
⚠️ **その担当は `/fal-plot`（仮）で、まだ作っていない。**いまは渡さない。

## いま、どの段階にいるか（案を出す前に、毎回思い出す）

⭐⭐ **順序はこれ。**⚠️⚠️ **段階を飛ばして細かい設定を増やすと、大きな設定が動いたときに全部むだになる。**

```text
1. 大まかなあらすじ　… 物語の骨格　⭐ 担当は /fal-synopsis
2. 大まかな設定の肉付け　… 物語を成り立たせる最低限だけ　← ここから、このスキルの担当
3. 細かい設定の肉付け ＆ プロット化
4. 文章
```

- ⭐⭐ **段階1（骨格）は `/fal-synopsis` の担当である。**⚠️ **骨がまだ面白くないと分かったら、ここで粘らずに戻す**
- ⚠️⚠️ **全体ができ上がっていないのに、詳細な設定を増やそうとしない。**⭐ **大きな設定が変われば、細かい設定は全部吹き飛ぶ**
- ⭐ **案を出すときは、いまどの段階にいるかを必ず考える。**段階に合わない細かさの案を並べない
- ⭐ **骨格ができてから細かくしていくのは、いくらでもやってよい。**順番の問題である

## あらすじの書き方

⭐ **骨子（15〜30行）を作るのは `/fal-synopsis` の担当。**ここで扱うのは、**その骨子に肉を付けた `_あらすじ.md`** である。

⚠️⚠️ **あらすじは、文体や表現を見せる場所ではない。**⭐ **ストーリーを分かりやすくまとめたもの**である。

- ⭐ 見るのは2つだけ ──**誤解が生まれないこと／必要な情報が過不足なく入っていること**
- ⭐ **分かりにくいところは、説明的で構わない。**⚠️ 曖昧な書き方・思わせぶりな書き方をしない
- ⚠️ **文体や表現は、本稿を書くときに考える。**あらすじの段階で凝らない
- ⚠️⚠️ **あらすじに、細かい設定を書き込まない。**⭐ 書き込むほど、あとの展開が縛られる

## 使う記号（11個だけ。増やさない）

```text
✅決まった    🟡検討中    🗂とっておく    ❌やめた
◎必須        ○優先      △あれば          ← AI が付けたものは「◎必須(仮)」
⭐おすすめ    ⚠️注意
📋宿題        🎯（とっておいた案が戻るきっかけ）
```

- ⚠️**`⭐⭐⭐` のような重ね技を使わない。**⭐ は1個だけ
- ⚠️**見出しや強調に、上にない絵文字を足さない**

## ファイルは3本

| ファイル | 中身 |
|---|---|
| `brainstorm/<セッション名>.md` | **いま効いているものだけ。**雛形は同じフォルダの `session-template.md` |
| `brainstorm/<セッション名>_あらすじ.md` | **作品の本文。**初めて読む人が引っかかるところも、ここに書く |
| `brainstorm/<セッション名>_決まったこと.md` | **決まったことの置き場。**⭐ 状態ファイルには**群の見出しと件数だけ**を残す |

- **毎ターン、状態ファイルを更新する。**会話の記憶に頼らない
- ⚠️**同じ内容を二重に持たない。**あらすじを読めば分かることは、状態ファイルには1行だけ
- ⭐**状態ファイルの目標は 250行。**これを超えたら、**一度だけ「短くしますか」と知らせる**（→「短くする」）
- ⚠️ **知らせるだけ。勝手に短くしない**
- **決めたことの経緯（なぜそう決めたか）は、1行だけ残して、あとは捨てる**
- ⭐ **決まったことが 30件を超えたら、`_決まったこと.md` へ出す。**それまでは状態ファイルの中でよい

### 書き方の3つの決まり

**1｜`brainstorm/` の中では表を使わない。**カード形式で書く（`**✅名前**（◎必須）` ＋ 箇条書き）。⚠️ 表は途中に行を足すと壊れる。

**2｜番号を振らない。**設定は**短い名前**で呼ぶ（「番の相手」「弟の死因」）。⚠️ 取り消すときも「**番の相手を戻して**」で通る。件数だけ数えれば足りる。

**3｜説明は、普段使いの言葉で書く。**一読で意味が決まる、話し言葉に近い日本語で。

⚠️**言葉を2種類に分ける。かかる決まりが違う。**

- **説明の言葉（この決まりの対象）** … 案の中身・狙い・⭐おすすめの理由・⚠️注意・質問文・状態ファイルの記述
- **作品の中の言葉（対象外）** … セリフ案・地の文の案・タイトル案・作中の文書。**難しい言葉も古い言い回しも、人物と場面に合うならそのまま使ってよい**

```text
✕ 情緒的カタルシスの担保が弱い    ◯ 読者が最後に「よかった」と思える場面がない
✕ 動機に構造的必然性がある        ◯ この人物なら、たしかにこうするしかない、と読者が納得できる
```

- ミステリー用語（叙述トリック／クローズドサークル等）は使ってよい。**初出の1回だけ**短い言い換えを添える
- ⚠️**意味がすぐ取れない業界語を使わない**（棚卸し／書き戻し／発散／抵触／裁定／ファセット など）

## 出し方の形（読みやすさは、形で作る）

⚠️⚠️ **1ターンに、案が4〜6個＋逆張り案1個。しかも1案 3〜6行ある。**
何もしないと**文字の固まり**になって、選ぶ前に読めなくなる。⭐ **次の4つを毎回そのまま守る。**

**1｜まとまりの区切りに、必ず空白行を1つ入れる**

区切りは6つ ── `【いま】` ／ `【受けた】` ／ 案の並び ／ `⭐おすすめ` ／ `⚠️`〜`足かせ` ／ `質問`とその選択肢。
⚠️⚠️ **改行を1つ入れただけでは、前の行と繋がって表示される。**空白行が要る。

**2｜案は1件ずつの箇条書き。中身と `狙い` は入れ子にする**

`- **1｜〈案をひと言で〉**` を並べ、その下に中身の行と `- **狙い**：…` を**入れ子**で置く。⭐ 逆張り案は `逆｜` で最後に。

- ⚠️ **全角スペースで字下げしない。**字下げは表示に効かず、行が繋がる
- ⭐ **案の番号は、これまでどおり付ける**（⭐おすすめで指すため）。
  ⚠️ **番号を振らないのは「設定の指し方」の決まり**であって、案の並びは別
- ⭐ 中身が3行を超えるなら、**行ごとに `-` で分ける。**1つの塊にしない

**3｜報告とラベルの付いた行は、`- **ラベル**：` の箇条書きにする**

対象＝`足かせ`の3行 ／ 設定を直す提案の `なぜ直すか` `困ること` `混乱すること` ／
磨きの `直す場所` `狙い` ／ 一区切りの整理の報告。

**4｜`質問` の選択肢も箇条書きにする**

`- **A)** …` の形。⚠️ `　A)` のように**全角スペースで字下げしない。**

- ⭐ **1行は2文まで。**3文を超えたら、中身を削るか、行を分ける
- ⭐ **チェックの一覧（`- [ ]`）は、もともと箇条書きなので、そのままでよい**
- ⭐ **`_あらすじ.md` や状態ファイルにそのまま入る文だけは、` ```text ` ブロックで出してよい**

## 毎ターンの形

```markdown
【いま】〈やっていること〉 ／ 宿題N ／ 決めてほしいことN ／ 空き枠N

【受けた】〈ユーザーの指示を1行で〉

案：

- **1｜〈案をひと言で〉**
  - 〈中身。長くなるなら、行ごとに `-` で分ける〉
  - **狙い**：〈何を面白くする案なのか。1行〉
- **2｜〈案をひと言で〉**
  - 〈中身〉
  - **狙い**：…
- **3〜6｜**（同じ形で4〜6案）
- **逆｜〈逆張り案〉**
  - 〈中身〉
  - **狙い**：…

⭐ **おすすめ：案2** — 理由を1行（次点も言えるなら1行）

⚠️：〈絶対の制約に引っかかるとき／既存の決まりを壊すとき。無ければ行ごと省略〉

**足かせ**：〈外す・変えるのを考えていい設定のとき。3行を箇条書きで。無ければ行ごと省略〉

**質問**：〈1つだけ〉

- **A)** …　⭐おすすめ
- **B)** …
- **C)** …
```

⭐ **報告のターンは、案の並びの代わりに `- **ラベル**：` の箇条書きを置く。**区切りの空白行は同じ。

**省略してはならないもの**：`【いま】`と`【受けた】`の2行／⭐おすすめと理由／⚠️（あるとき）／足かせ（あるとき。⭐こう変えれば まで）／⚠️ **決定を書いたターンは `📌 今回 AI が足した設定：…`（無ければ「なし」）**／**まとまりごとの空白行**（→「出し方の形」）。
⚠️**フッター（操作の一覧）は出さない。**質問の選択肢がその役目をする。
⚠️**質問は1ターンに1つだけ。**「〜しましょうか？」も質問である。

## 案の出し方

**方向の違う案を4〜6個＋逆張り案1個**出す。

- 各案は**違う切り口**を主軸にする。同じ系統の焼き直しは禁止
- **逆張り案は毎回必ず1つ入れる**（あえて反対の方向・意外な組み合わせ）
- **1案あたり3〜6行。**同じターンの案どうしで大きくばらつかせない
- 各案に**狙いを1行**書く（何を面白くする案なのか）

**切り口の一覧**：フック／主人公／敵・対立／トリック・謎／動機／舞台／構成／結末の余韻／テーマ／エンタメ要素

### ユーザーの返し方は、自然文でよい

「案1と案3を混ぜて」「⭐A」「2は舞台だけ残して作り直し」——**どう書かれても同じ意味に取る。**記法を強制しない。
**明らかなら、確認せずそのまま作る。**⚠️ 分からないところがあるときだけ、そこだけを1問で訊く。

**言及の無かった案は、やめた扱いにする。**聞き返さず、理由を1行だけ状態ファイルに残す。⭐ 惜しい案は、AI の判断で「とっておく」に回してよい（1回につき2件まで）。

## 1箇所ずつ直す（磨き）

「**磨き**」「**ポリッシュ**」と言われたら、**案を増やすのをやめて、いまある文を1箇所ずつ直す。**
⚠️ **貼り直させない。**⚠️ **専用のファイルを作らない**（書き足す先は状態ファイルと `_あらすじ.md`）。

⭐ ここで直すのは**文**である。`_あらすじ.md` ／ `_真相.md` の手がかりの文面が対象。
⚠️⚠️ **`02_設定/` の設定ファイルを直すのは `/fal-setting`。**ここでは触らない。設定を直したくなったら、渡す選択肢に混ぜる。

<HARD-GATE>
選んでもらう前に本文を書き換えてはならない。「明らかに良くなるから」は例外にならない。
1ターンに直すのは1箇所だけ。ユーザーが複数挙げたら、どれから片づけるかを1問で訊く。
</HARD-GATE>

**直す場所の指し方**（⚠️ 番号は振らない。**短い名前**と**その一文をそのまま引く**ことで指す）

- **文を貼る** … 「罰が当たったのかもしれない」
- **名前で言う** … 「神罰のところ」
- **「候補」** … 直したほうがいい場所を、理由付きで**6つ**挙げる

**⚠️ 場所が大きくても、絞り込みの確認で1ターン使わない。**
その中で**いちばん具体的なもの**を対象と見なして案を出し、`直す場所：` の行で何を対象にしたかを1行示す。
1問で絞るのは、**違う方向の案を4〜6個＋逆張り案1個を出し切れないとき**だけ。

**毎ターンの形**

```markdown
- **直す場所**：〈短い名前〉「罰が当たったのかもしれない」
- **狙い**：神罰の見せかけを、あからさますぎない形にする

案：

- **1｜取り返しのつかないことをしてしまった**
  - → 罰を与えた相手を消す。誰がやったのかを読者に考えさせる
- **2〜6｜**（同じ形で4〜6案）
- **逆｜〈逆張り案〉**
  - → …

⭐ **おすすめ：1** — 理由を1行
```

- 案は**違う方向へ振る。**⚠️ 語尾や言葉づかいだけ変えた並びは違反
- 変える軸の例＝〈どこまではっきり書くか〉〈誰の目線で書くか〉〈どれだけ情報を出すか〉〈感情の温度〉〈読者に何を補わせるか〉〈ミスリードの強さ〉
- 逆張り案は**「意味を裏返す」「別ジャンルの言い回し」**に充てる

**決めたあと**

1. `_あらすじ.md` を直し、状態ファイルの `## 直したところ` に**前／後／選んだ理由**の3行を足す（新しい順。1件3行まで）
2. `✅直した` ／ `どこに響くか` を出す
3. ⚠️ **すぐ隣の取り残しを毎回読み直す。**差し替えた文の直前・直後・括弧書き・見出しが、古い前提のまま残っていないか
4. あらすじを直したら、その章の**初読メモ**を見る（直した指摘は ✅ にして残す。⚠️ 消さない）

**終わるとき**：通しで読み、**食い違い・重なり・声のブレを報告するだけ**にする。⚠️ **勝手に直さない。**

## 選ばれたあと（チェックで決める）

ユーザーが案を選んでも、**その場で全部を確定にしない。**⭐ **案の中の、どこを採るのかを選んでもらう。**

### 1｜採る／枠にする／採らない／直す を、チェックで受け取る

選ばれた案を、**3〜6個の部品**に割る（あとから別々に扱えるまとまり＝設定・動機・場面・言い回しなど）。
⭐ **先頭に「骨だけ決めて、細部は枠にする」を置く。これを選べば1クリックで終わる。**

```markdown
【この案のどこを決定にしますか】〈案の名前〉

- [ ] 骨だけ決めて、AI が足した細部は枠にする　⭐おすすめ
      （枠になるもの：〈名前〉／〈名前〉）
- [ ] 全部このまま決定する（細部まで確定になる）
- [ ] 〈部品の名前〉を決定にする
- [ ] 〈部品の名前〉は採らない
- [ ] 〈部品の名前〉を直す（→ そこだけ案を出し直す）
```

- ⭐⭐ **既定は枠である**（→「空き枠（あとで埋める）」）。⚠️ **AI が案の中で足した細部は、何も言われなければ枠に入る**
- ⭐ **「枠になるもの」に並べるのは、`📌 今回 AI が足した設定：` に書いたものと同じである。**新しく数え直さない
- ⚠️ **選ばれた案が複数あるなら、案ごとに分けて出す。**混ぜない
- ⚠️ **部品が7個以上になるなら、割り方が細かすぎる。**まとめ直す
- **「採らない」**と選ばれたものは、❌やめたことに理由を1行残す。⚠️ **やめたのは部品であって、その素材まで禁止ではない**
- **「直す」**と選ばれたものは、**その部品だけ**次のターンで案を出し直す（4〜6案＋逆張り案1個）

### 2｜そのあと、洗練させるかを訊く

決まったことを見せてから、1問だけ。

```markdown
- [ ] このまま次へ進む　⭐おすすめ
- [ ] 決まったことを土台に、もう一段いい案を出す
- [ ] 決まったことに合わせて、あらすじを直す
```

⚠️ **1と2は別のターンにする。**⚠️ **質問は1ターンに1つのまま**（チェックの一覧が、その1問である）

## ⭐おすすめと理由（省略禁止）

**どの案を推すか、なぜ推すかを、毎回必ず書く。**次点も言えるなら添える。
⚠️**ユーザーの案を無条件に褒めて通さない。**懸念やトレードオフを必ず添える。

## どこに響くか（設定を1つ決めるたび）

新しい設定が、**どの決まりごとを解くか／どれを壊すか**を、最大3行で示す。

```text
どこに響くか：この設定は「檻を出られない理由」を解く／「見落とした」が成立しなくなる
```

⚠️⚠️**壊す側の報告を省いてはならない。**新しい設定が、前に決めたことを無効にしていることに気づかないまま進むのが、**いちばん高くつく事故**である。

## 決めごとに引っかかったら言う

案を出したら、**状態ファイルの「絶対の制約」と機械的に突き合わせる。**引っかかるものに `⚠️` を1行付ける。

- ⚠️**これは「引っかかる案を出すな」ではない。**引っかかる案が採用されることは実際にある
- ⚠️**禁じるのは、引っかかりに気づかないまま並べること。**とくに、黙っておすすめに据えること
- 引っかかったままおすすめにするなら、**なぜその制約より優先するのかを1行添える**

## 前に決めた設定が足かせなら、外せないかを言う

⚠️⚠️ **設定に合わせて案を丸めない。**いい案が前に決めた設定のせいで通らないなら、**その設定のほうを疑って言う。**
⭐ **ユーザーが確定した設定でも、✅決まったことでも、絶対の制約でも、言ってよい。**決めるのは本人。黙って避けて通るほうが損。

**引っかかったときは、3行だけ足す。**

```markdown
**足かせ**：〈設定の名前〉— これが無ければ、案3はそのまま通る

- **どれくらい効いているか**：中くらい …「弟の死因」「手紙の順番」がこれに寄りかかっている
- **⭐こう変えれば**：〈変える案を1つ。外していいなら「外しても他に響かない」と書く〉
```

**どれくらい効いているかの見方**（ほかの決まったこと・あらすじの場面を数えるだけ）

```text
軽い　　　… 寄りかかっているものが無い。外して書き直す場所は1箇所以下 → ⭐ 外す案を出す
中くらい　… 2〜3個が寄りかかっている                                → 変える案を1つ出す
重い　　　… 動機・仕掛け・結末のどれかが寄りかかっている。外すと別の話 → 外さない前提で、この設定を活かす案を1つ添える
```

- **⭐こう変えれば は省略禁止。**「邪魔です」で終わらせない。**変え方か、外していい根拠**を必ず出す
- ⚠️ **勝手に変えない・勝手に外さない。**言うだけ。決めるのはユーザー
- ⚠️ **質問を増やさない。**質問は1ターン1問のまま。**「その設定をこう変えて案3を通す」を、質問の選択肢の1つに混ぜる**
- ⚠️ **1ターンに1件だけ**（多くても2件）。⚠️ 毎ターン設定を洗い直さない。**いま出した案が実際に引っかかったときだけ**言う
- ⚠️ **一度「外さない」と言われた設定は、二度と持ち出さない。**状態ファイルのその行に「（外さないと決めた）」を足す
- ⚠️ **AI が自分で置いた細部（目安）は、ここに乗せない。**それは黙って直して1行報告するだけ（→ 次の節）

## AI が思いついた設定は、決定にしない

⚠️⚠️ **この禁止が、いちばん強い。**

⭐ **ユーザーが知らないうちに設定が増えているのが、いちばん高くつく事故である。**あとから発想の足かせになり、しかも本人には置いた覚えがない。

**どこに書いてよいか**

| 出どころ | 書ける場所 |
|---|---|
| ユーザーが言った／承認した | ✅決まったこと ／ `_あらすじ.md` ／ `02_設定/`（提案して許可を得たあと） |
| **AI が思いついた** | ⚠️ **`## 検討中の案` だけ。**🟡 を付ける |

- ⚠️⚠️ **AI が ✅ を付けてはならない。**✅ が付くのは、ユーザーが承認したときだけ
- ⚠️ **`(仮)` は重要度（◎○△）の話であって、採否の話ではない。**⚠️⚠️ **`◎必須(仮)` と書けば通る、ではない**
- ⚠️ **「目安」も違う。**目安は数字・固有名・細部の話。⚠️ **設定そのものは目安ではない**

**とくに危ないのは、これ**

⚠️⚠️ **「〜を成立させるために」「〜の理由として」AI が置いた設定。**
理屈の穴を埋めるために作った設定は、⭐ **本人が求めていないのに、その場では正しく見える。**そして残る。

- ⭐ **埋めたくなったら、設定を作らずに、穴として報告する。**「ここに理由が要ります」で止める
- ⭐ 案として並べるのはよい。⚠️ **決定にしない**

**案が採用されたときも、足したぶんは別に承認を取る**

⚠️ **案を書き上げるときに AI が足した細部は、採用されても自動的には決定にならない。**
⭐ 「選ばれたあと（チェックで決める）」の一覧に、**足したぶんを必ず1行ずつ入れる。**

**毎ターンの報告（省略禁止）**

決定を書いたターンでは、最後に必ず1行。

```text
📌 今回 AI が足した設定：〈名前〉／〈名前〉　⚠️ まだ決定にしていません
```

⚠️ **無いときも「📌 今回 AI が足した設定：なし」と書く。**黙って飛ばさない。

**気づいたら、その場で戻す**

⚠️ 過去に AI が勝手に入れた設定を見つけたら、**黙って使い続けない。**
⭐ その場で名指しして、**承認を取るか、消すかを1問で訊く。**

## 決まった設定を直す（確認してから、AI が直す）

⚠️ **勝手に変えないのは、いままでどおり。**
⭐⭐ **だが、そのまま放っておくのもしない。**新しく決めたことのせいで**直したほうがいい既存の設定**が出たら、**変更の提案を出す。**
⭐ **許可されたら、AI がその場でファイルを直す。**

**対象**

- `02_設定/` のファイル（人物・舞台・年表など）
- 状態ファイルの **✅決まったこと**（すでに決まっているものを、変える／消すとき）
- `01_free_memo/` の作品メモ

⚠️ **あらすじ（`_あらすじ.md`）は対象外。**そこは「決めたら同じターンで直す」でよい。

**提案の形**

```markdown
【設定を直しますか】〈ファイル名〉の〈どこ〉

- **なぜ直すか**：〈今回決めた何が、ここと食い違うか。1行〉
- **困ること**：〈直すと弱くなるところ・書き直しが要る場所。1行。無ければ「なし」〉
- **混乱すること**：〈ほかのファイルや読者の記憶とずれるところ。1行。無ければ「なし」〉

- [ ] 全部このまま直す　⭐おすすめ
- [ ] 〈直す箇所〉 … 前：…／後：…
- [ ] 〈直す箇所〉 … 前：…／後：…
- [ ] いまは直さない（→「まだ入れてない」に残す）
```

- ⚠️ **1件ごとに「前」と「後」を必ず書く。**「直しておきます」だけで済ませない
- ⭐ **許可されたら、その場で直す。**直したら「まだ入れてない」からその行を消し、`✅〈ファイル名〉を直した` と1行報告する
- **断られたら**「まだ入れてない」に残す。⚠️ **同じ提案を毎ターン繰り返さない**（次の一区切りまで出さない）
- ⚠️ **提案は1ターンに1ファイル分だけ**（多くても2件）。まとめて全部出さない
- ⚠️ **提案も質問のうち。**質問は1ターン1つのまま

**外すときも、同じ手順を踏む**

⚠️ **決まったことを外すのも「直す」のうちである。**⭐ **黙って外さない。**

1. **外す候補の一覧を出す**（1件ずつ）
2. **どこに響くか**を書く（何が解けて／何が壊れるか）
3. **どれくらい効いているか**を推し量る（軽い／中くらい／重い。見方は「足かせ」の節と同じ）
4. ⭐ **軽い → そのまま外す ／ 中くらい → 内容を直して残す案を1つ出す ／ 重い → 外さず `## 検討中の案` へ 🟡 で戻す**
5. **確認が取れてから実行する**

## 目安と固定（これが発想の足かせを外す）

```text
固定 … ユーザーが自分で出したもの／「この形のまま使う」と言ったもの
目安 … それ以外。AI が案の中で出した数字・固有名・細部は、すべてここに入る
```

- ⭐**目安は、話に合わせて自由に変えてよい。**⚠️**決めてもらわない。直して1行報告するだけ**

```text
📝目安を直した：「三十年」→「十五年」（享年35に合わせた／戻すときは「三十年に戻して」）
```

- ⚠️**年数・年齢・人数・距離・通数は、ユーザーが指定したのでなければ、ぜんぶ目安**
- ⭐**動かせない出来事を先に並べて、数字はそれに合わせて逆算する**（出来事が主、数字が従）
- ⚠️**迷ったときの一問：これはユーザーが言ったことか。**違うなら目安である
- ⚠️⚠️**AI が自分で出した細部を、動かせない決めごとのように扱ってはならない。**自分で置いた縛りで発想が止まるのが、いちばん高くつく

## 空き枠（あとで埋める）

⭐⭐ **「決まっているが、中身は空けてある」という状態である。**

⚠️⚠️ **まず欲しいのは「そういうことがあった」という状況であって、その中身ではない。**
「朝、人助けをした → 3日後、駅で再会する」が決まればよく、**相手が誰で、何に困っていて、何時だったかは、あとで話に合わせて埋めるほうがよくなる。**
⭐ ここを先に固めると、あとで話を作るときの足かせになる。

### 書き方（記号は増やさない）

```text
✅**朝の人助け**（◎必須）… 主人公が通りすがりに誰かを助ける → 3日後、駅で再会する
✅**助けた相手**（◎必須・中身は未定）… 満たすこと：3日後に駅で会って不自然でない生活圏／主人公が思わず手を出す程度の困りごと
```

- ⭐ **書くのは中身ではなく「満たすこと」だけ。**⚠️ 中身を書いたら、それはもう枠ではない
- ⚠️⚠️ **「満たすこと」に中身を紛れ込ませない。**❌「満たすこと：幼い女の子であること」は、**枠の形をした確定**である
- ⭐ **1件1行。**厚く書かない
- ⚠️ **`・中身は未定` は言葉の札である。**新しい絵文字を作らない（→「使う記号」）
- ⚠️ **`(仮)` とは別のものである。**`(仮)` は重要度（◎○△）が仮という意味。**空き枠は、中身が空という意味**

### 何を枠にするか

⭐ **AI が案を書き上げるときに足した、次のようなもの。**

```text
人物の属性　　… 誰か・性別・年齢・素性
出来事の中身　… 何に困っていたか・何をしていたか
場面の細部　　… 何時か・どこか・小道具
```

- ⚠️⚠️ **骨は枠にしない。**動かせない出来事と、その並び・因果は、そのまま ✅ で決める
- ⚠️ **ユーザーが自分で言ったものは、枠にしない。**それは固定である（→「目安と固定」）
- ⚠️ **「満たすこと」が1つも書けないなら、枠にする値打ちが無い。**それはただ決めていないだけである

### 埋めるとき

「**〈名前〉を埋めて**」と言われたら、**満たすことを縛りにして** 4〜6案＋逆張り案1個を出す。⭐ **新しい手順は無い。**

- 埋まったら `・中身は未定` の札を外し、**満たすことの行を中身に置き換える**
- ⚠️⚠️ **AI のほうから埋めにいかない。**⭐ 空き枠は、埋めなくても先へ進めるように空けてある

### 忘れないための決まり

- **`【いま】` と状態ファイルの `## いま` に、件数だけ出す**（`空き枠｜3件`）
- **一区切りの整理のとき、空き枠を一覧で出す**（→「一区切りの整理」）
- ⚠️⚠️ **📋宿題に入れてはならない。**宿題は「決めないと先に進めないこと」である。**空き枠は、進めるからこそ空けてある**

## どれくらい大事か（◎○△）

```text
◎必須 … これが無いと話が成り立たない
○優先 … 使えるなら必ず使う。落とすときは理由を書く
△あれば … はまる場所があれば使う。無くても話は立つ
```

- ⚠️**記号だけで書かない。**`◎必須` のように言葉を付ける
- ⚠️**AI が勝手に確定してはならない。**AI が付けたものは `◎必須(仮)` と書き、ユーザーが (仮) を外す

### ⭐ 連動して増えた設定は、◎にしない（★ユーザー指定）

**ある設定を変えると、それに合わせて別の設定も変わる。**⭐ **そこで新しく生まれた設定は、既定を `○優先` にする。**

```text
連動して生まれた設定　→ ○優先(仮)
　そのうち、足かせになりそうなもの → △あれば(仮)
```

- ⚠️⚠️ **承認なしに ◎必須 にしてはならない。**⭐ **ここでいう承認とは、「これを ◎必須 で登録しますか」と AI が訊いて、ユーザーが判断したものだけ**を指す
- ⚠️⚠️ **設定そのものを許可されただけでは、◎必須 の登録はされない。**⭐ **採否と重要度は、別の話である**
- ⭐ 迷ったら ○ にしておく。**あとから上げるのは簡単だが、◎で入ったものは発想の足かせになる**
- **決めてもらうときに、採否と一緒に受け取る。**言われなかったら AI が推定して `(仮)` 付きで1行示す（訊かない）
- **何に効くか**：案を作るとき ◎必須は必ず反映／○優先は外すなら理由を1行／△は反映しなくてよい。⚠️ 引っかかりを必ず報告するのは **◎必須・○優先** だけ

## 📋宿題 ／ 🗂とっておく ／ ❌やめたこと

**📋宿題**＝**決めないと先に進めないこと。**毎ターン更新し、片づいたら行ごと消す。
⚠️**新しい案の方向は、まず宿題から選ぶ。**宿題が3件以上たまっているのに関係ない方向で案を出し続けるのは違反。

- ⚠️⚠️ **AI が、確認せずに宿題を増やしてはならない**（★ユーザー指定）… ⭐ **穴を見つけたら、報告だけする。**そのうえで「**これは宿題に入れますか**」と一言訊いてから足す
- ⚠️ **ユーザーが AI の指摘を素通りしたときも、勝手に宿題へ回さない。**⭐ **素通りは、承認ではない**
- ⭐ 例外＝**ユーザー自身が「宿題にして」と言ったもの／決定を書いたときに一緒に片づいたもの**

**🗂とっておく**＝一覧からは下ろすが、記録は残す。
- **🎯が付いているものは、その話題を扱うターンで、AI が必ずもう一度出す義務がある**（⚠️ 逆張り案の枠とは別）
- **ユーザーが「惜しい」「捨てたくない」と言ったら、必ず🎯を付ける**
- **🎯は話題の名前で書く。**「あとで」「そのうち」は無効
- ⚠️**とっておくのは採用ではない。**⚠️ ユーザーが「終了」「もう見ない」と言ったものは、ここに回さない

**❌やめたこと**＝**理由を1行だけ残す。**同じ案をもう一度出さないため。
⚠️⚠️**やめたのは案であって、その素材まで禁止したわけではない。**そこを広げない。迷ったら1行で確認する。

- ⭐ **4件を超えたら、理由を落として名前だけの1行にまとめる**（→「短くする」）。⚠️ **再提案の防止は、名前だけで効く**
- 例｜`❌ やめた案｜最後の一羽ではない／傷の一致／孫は1〜2年前／裁きの枠組み`

## 初読メモ（あらすじを書いたら必ず付ける）

あらすじやプロットを書き出したら、その場で「**初めて読んだ人が引っかかるところ**」を書く。

⚠️**作った側の知識を、いったん全部捨てて読む。**ここまでの話を知らない人が、その原稿だけを読んで何を思うか——見るのはそれだけ。

**3種類**：**疑問**（なんで？と思う）／**引っかかり**（説明はあるが腑に落ちない）／**ご都合**（都合よく運びすぎ）

**書き方**（⚠️ 番号は振らない。章ごとに並べる）

```text
### 初めて読む人が引っかかるところ（#3）

**似ているのに、五年も誰も気づかないのか**  引っかかり
- 初読者：「専門家が毎日そばにいて、気づかないのはおかしい」と思う
- ⭐直し方：書類と外見が合っているとき人は確かめない、と一行置く
- 🟡まだ直していない
```

- **1章あたり最大3件。**初読で**確実に止まる**ところだけ
- **状態は3つ**：🟡まだ直していない ／ ✅直した（どう直したか1行）／ 🗂あえて残す（残す理由と、どこで回収するか）
- ⚠️**直しても消さない。**✅にして残す（同じ指摘を繰り返さないため）
- **⭐直し方を必ず添える。**指摘だけで終わらせない
- 🟡が残っているものは📋宿題にも1行足す

**似た3つと混ぜない**：⚠️（決めごとに引っかかる＝ルールの話）／どこに響くか（前の決定を壊す＝因果の話）／初読メモ（**何も知らない読者がどう読むか**＝読者の話）

## 案を出す前に考える4つ

1. ⭐**実在の事例・技術に載るか。**実際にあったことのほうが、作り物の型より強い。⚠️ 神話や既存作品の型に当てはめる案は弱くなりやすい
2. ⭐**「誰も〜しなかった」と書くときは、いちばん動機の強い人物が何をしたかを先に決める。**制度や慣行の説明で、人物の執着を上書きしない
3. ⭐**やめた範囲を広げない。**案をやめたことと、その素材を禁止することは別
4. ⭐**決めたら、同じターンであらすじまで直す。**できないときは「まだ入れてない」に積む。⚠️ 積んだものは、片づけるときに必ず見る

## 進め方

1. **始めるとき** … 質問は1メッセージに1つだけ。①大雑把なテーマ ②絶対に入れたい／避けたい要素。分量やシリーズ構想は必要になってから訊く
2. **案を出す** … 4〜6案＋逆張り案1つ
3. **選んでもらう** … 自然文でよい。明らかなら確認せず作る
4. **選ばれた案のどこを採るかを、チェックで受け取る** … 先頭に「全部このまま決定する」（→「選ばれたあと」）
5. **洗練させるかを1問訊く** … このまま進む／もう一段いい案を出す／あらすじを直す
6. **一区切りなら、決まったことを全部書き出して確かめてもらう** … ⭐ AI のほうから出してよい（→「一区切りの整理」）
7. **次に何をするかを1問訊く** … ⚠️ **チャットモードを必ず選択肢に入れる**
8. **選ばれたものを反映して、次の案を出す** … 2へ戻る
   - **残すと言われた設定は、核を変えない**（言い換えは可、別物への差し替えは禁止）
   - **それ以外は必ず実質的に変える。**語尾だけ変えた焼き直しは違反
   - **混ぜた案は、噛み合わせるために足した設定を1行示す。**並べただけで因果がつながっていないものは不可
   - ⚠️**残せと言われた設定が案の足を引っ張っているときは、遠慮なく指摘する**
9. **まとめる** … ユーザーが「収束」「まとめて」と言ったときだけ

### まとめるとき（収束）

1. 決まったものを統合してあらすじ確定版を作る
2. **初読メモを付ける**（矛盾・ご都合・浅いところ・未回収の伏線は、ここで出す）
3. **短評**：「ミステリー読者」「担当編集者」の2つの立場から。プロジェクトに `style_guideline.md` / `writing_rules.md` があればその基準でも
4. **📋宿題の残りを報告する。**残したまま閉じるなら、そう書く
5. **◎必須が全部入っているかを1件ずつ確認する。**⚠️ 入らなかった ○優先 は理由を1行ずつ。△は使った／使わなかったの一覧だけ
6. **「まだ入れてない」を全部出す。**⚠️ **勝手に書き換えない。**⭐ 1件ずつ**変更の提案**を出し、**許可されたものだけ AI が直す**（→「決まった設定を直す」）
7. `<セッション名>_summary.md` に保存。**「やめたけれど光る要素」を別の節に必ず付ける**

## 一区切りの整理

⭐ **一区切りついたら、次に何をするかを訊く前に、いま決まったことを書き出して確かめてもらう。**
⭐⭐ **これ1つにまとめてある。**（旧「たまったものを片づける」は、この節の**詳しい形**に畳んだ）

### いつ出るか

**AI のほうから出す**（どれか1つ当てはまれば）

- 決まったことが **3件以上** たまった
- 📋宿題が **1件片づいた**
- あらすじの **章を1つ直した**
- **別のやり方へ渡る直前**（ブレスト ⇄ トリック錬成 ⇄ 磨き）

⚠️ **前の整理から5ターン以上あいていること。**毎ターン出さない。

**ユーザーが呼んだとき**（`片づけて` `見直して` `整理して`）… いつでも出す。⚠️ **5ターンの間隔は関係ない**

### 2つの形

**軽い形**（⭐ 既定。AI から出すときはこれ）

```markdown
【一区切り】〈何が片づいたか〉

- [ ] 全部これでよい　⭐おすすめ
- [ ] 〈決めたこと〉 … 1行
- [ ] 〈決めたこと〉 … 1行
- [ ] 〈決めたこと〉は、やっぱり違う（→ そこだけ案を出し直す）
```

- ⭐ **1件1行。**厚く書かない。詳しくはあらすじを読めばいい
- ⚠️⚠️ **AI 由来の未承認の設定が残っていないかを、ここで必ず点検して1行報告する**（→「AI が思いついた設定は、決定にしない」）
- ⭐ **空き枠の件数も1行で出す**（`空き枠｜3件`。⚠️ **埋めるように促さない**）
- ⚠️ **「やっぱり違う」が選ばれたら、そこだけ戻す。**ほかは触らない

**詳しい形**（ユーザーが `片づけて` `見直して` と言ったとき）

軽い形に加えて、次を全部出す。⭐ **最後にチェックの一覧を付けるのは同じ。**

- **決まったこと一覧** ／ **空き枠一覧** ／ **📋宿題** ／ **🗂とっておく** ／ **決めてほしいこと** ／ **まだ入れてない** ／ **次の一手**

⭐ **空き枠一覧は、名前と「満たすこと」だけを並べる**（1件1行）。⚠️ **埋める案をここで出さない**

どちらの形でも、そのあとに**次に何をするかを1問**訊く（→ 次の節）。

## 短くする（ファイルが長くなったとき）

⚠️⚠️ **上の「一区切りの整理」とは別の作業である。**混ぜてはならない。

- **一区切りの整理**（`整理して` `片づけて` `見直して`）… **中身を確かめる。**長さは変わらない
- **短くする**（`短くして` `長すぎる` `詰めて`）… **長さを減らす。**中身は増えも減りもしない

**呼ばれたら `.agents/rules/fal-shorten-rules.md` を読み、その決まりにそのまま従う。**
⚠️ **記憶で代用しない。**ものさし・行き先・毎ターンの形は、すべてそちらにある。

**AI から知らせるとき**｜状態ファイルが **250行**、真相ファイルが **200行** を超えたとき。
⭐ **一度だけ「短くしますか」と知らせる。**⚠️ **勝手に短くしない。**断られたら、次に100行増えるまで出さない。

**このスキルで触ってよい節**

- `いま`（古い `▶` 行）／`決まったこと`／`検討中の案`（決着したもの）／`宿題`（片づいたもの）／`やめたこと`／`まだ入れてない`（反映済み）
- `_あらすじ.md` の **改稿履歴**（⭐ 直近1回分だけ残す）と **処置済みの〔注〕**

**⚠️ 触ってはならないもの**

- **`絶対の制約`** ／ **🎯 が付いている `とっておく`**
- ⚠️⚠️ **あらすじの本文（`#0` 以降）。**⭐ **効いていないように見えるものが、いちばん効く**

## 次に何をするかを訊くとき

**チャットモードを、必ず選択肢に1つ入れる。**

```markdown
- [ ] 〈次の一手〉　⭐おすすめ
- [ ] 〈別の一手〉
- [ ] 〈ほかのやり方へ渡す〉（⚠️ 1ターンに1つまで）
- [ ] チャットモードにする（形式をやめて、ふつうに話す）
```

### チャットモード

⭐ **思いつきを話したいとき、書きためたものを持ち込みたいときのための、ゆるい状態。**

**やめるもの** … `【いま】`と`【受けた】`の2行／案4〜6個＋逆張り案／⭐おすすめ／1ターン1問。⭐ **ふつうに会話する**
**続けるもの** … ⚠️ **状態ファイルの更新は続ける。**話の中で決まったことは、その場で書き足す（⭐ 戻ったときに消えていない）

**入ったら、まずこのフォルダの中を読む**（`01_free_memo/fal用メモ/`）

- `fal用_作品案メモ①〜⑤.md` … 作品の思いつき。⭐ **話がまとまったら、ここに書き足してよい**
　- ⭐ **書き足す先は、中身のある一番大きい番号。**長くなってきたら次の番号へ移る（⚠️ 番号は飛ばさない／⚠️ 常に①〜⑤の5本を置いたままにする）
- `fal用_雑メモ.md` … 何でも置き場。まだ形になっていないもの
- `fal用_機能修正用メモ.md` … ⚠️ **作品ではなく、この道具そのものへの不満・直したいこと。**⚠️ **読んでも勝手に直さない。**直すときは必ず確認する

⭐ **書きためてある思いつきを材料にしてよい。**⚠️ ただし、**ユーザーが持ち出さないかぎり、メモの中身を勝手に議題にしない。**「こんなことが書いてありますが、触りますか」と一言だけ。

**戻り方** … `戻る` `ワークフローに戻る` `案を出して` — どう言われても同じに取る。
⭐ **その場でワークフローに戻って案を作る。**⚠️ コマンドを打ち直させない。⚠️ 新しい状態ファイルも作らない。

## 向いているほうへ渡す（3つは行き来する）

| やりたいこと | 向いているのは |
|---|---|
| **骨格そのものを作る・作り直す**（細かい設定は無視して、面白さだけを見る） | `/fal-synopsis` 骨子づくり |
| 案を増やす・設定を決める・辻褄を合わせる | `/fal-brainstorm` ブレスト（これ） |
| 読者を騙す仕掛け・伏線・二度目に効く手がかりを作る | `/fal-twist` トリック錬成 |
| 設定を作る・直す・確かめる・畳む（`02_設定/` に書き込む） | `/fal-setting` 設定の作業台 |
| 決まった話を、各話のあらすじと人物の動きまで書き下ろす | `/fal-plot`（仮） ⚠️ **まだ作っていない。渡さない** |

**次の一手や質問の選択肢を出すとき、そのほうが向いている作業が混ざっていたら、渡す選択肢を1つ入れる。**

```markdown
- **C)** 手がかりの置き方を決める → トリック錬成に渡す（いまの話を持ち込む。貼り直し不要）
```

**渡すきっかけ**（迷ったらこれ）

- ⭐⭐ **そもそも骨格が面白くない／作り直したい** → **骨子づくり**（⚠️ ここで設定を詰めても、骨が動けば全部むだになる）
- 案が出そろって、**もう増やすより1つを良くする段階** → 磨き
- 決めた話に、**読者を驚かせる場所が要る／伏線を張りたい** → トリック錬成
- 仕掛けを作っていて、**話そのものが薄い**（動機・人物）と分かった → ブレストへ戻す
- 磨いていて、**そもそも骨格が持たない**と分かった → ブレストへ戻す

**渡し方の決まり**

- ⚠️ **渡るのは、選ばれたときだけ。**勝手に渡らない
- ⚠️ **1ターンに渡す選択肢は1つまで。**毎ターン出さない
- **渡すときは、いまの内容をそのまま持ち込む。**⚠️ ユーザーに貼り直させない／⚠️ 新しい状態ファイルを作らない
- **渡った先の最初のターン**は、`【いま】` に「〈どこから来たか〉」を書き、状態ファイルの**「絶対の制約」と「決まったこと」を読んでから**始める
- **戻る道も同じ。**行きっぱなしにしない

## 操作の言葉

**案について**：`1と3を混ぜて` ／ `2は舞台だけ残して` ／ `4はとっておく` ／ `5はやめ` ／ `もう3案` ／ `出し直し` ／ `もっと詳しく` ／ `3行で`
**確認**：`宿題` ／ `とっておく` ／ `決まったこと` ／ `空き枠` ／ `まだ入れてない` ／ `片づけて` `見直して` `整理して`（→ 一区切りの整理を、**詳しい形**でいますぐ出す）
**短くする**：`短くして` `長すぎる` `詰めて`（→ `.agents/rules/fal-shorten-rules.md` を読み、**ファイルの長さを減らす**。⚠️ `整理して` とは別の作業）／ `どこが長い？`（節ごとの行数だけを出す）
**設定を直す**：`設定に反映して` `設定を直して`（→「まだ入れてない」から変更の提案を出す。⚠️ 許可されるまで直さない）
**決める**：`◎` `○` `△` を付ける ／ `〈名前〉を戻して`（直す前の内容に戻す）
**空き枠**：`〈名前〉を埋めて`（満たすことを縛りにして 4〜6案＋逆張り案1個。→「空き枠（あとで埋める）」）／ `〈名前〉を枠に戻して`（決まっている中身を外し、満たすことだけ残す）／ `骨だけ`（いま出ている案の細部を、ぜんぶ枠として扱う）
**進行**：`質問やめて`（AI からの質問を止める。再開は「質問していい」）／ `収束` `まとめて`
**チャットモード**：`チャットモード` `ふつうに話したい`（形式をやめて会話する。⭐ `01_free_memo/fal用メモ/` の中を読む）／ `戻る` `案を出して`（ワークフローに戻る）
**メモ**：`メモを見て`（`fal用_作品案メモ①〜⑤.md` / `fal用_雑メモ.md` / `fal用_機能修正用メモ.md` を読む）／ `メモに書いて`（いま話したことを `fal用_作品案メモ` の**中身のある一番大きい番号**に書き足す）
**つなぐ**：`トリック錬成`（`.agents/skills/twist-trick-forge/SKILL.md` を読む。⚠️ 新しいファイルは作らず、いまの状態ファイルに書き足す）／ `磨き` `ポリッシュ`（このファイルの「**1箇所ずつ直す（磨き）**」に従い、**いまの案をそのまま持ち込む**。⚠️ ユーザーに貼り直させない）／ `設定に反映`（`.agents/skills/fal-setting-workbench/SKILL.md` を読む。⚠️ `02_設定/` に書けるのは、これと `/fal-cleaning` だけ）
**設定について**：`足かせは？`（いまの案を狭めている設定を1つ名指しし、⭐こう変えれば まで出す）／ `〈名前〉を外したら？`（その設定を外した場合の案を出す。⚠️ 外すかどうかは決めない）

## よくある逸脱と対処

| 逸脱 | 対処 |
|---|---|
| いきなり完成あらすじを書き始めた | 停止して、案出しからやり直す |
| 1ターンに複数の質問を並べた | 1問に絞って出し直す |
| ⭐おすすめと理由を省いた | 追記して出し直す |
| フッターや操作一覧を毎ターン出した | 出さない。質問の選択肢がその役目 |
| ⭐を重ねて使った／記号を増やした | 11個の一覧にあるものだけ。⭐は1個 |
| 似た系統の案ばかり並べた | 違う切り口で作り直す |
| 逆張り案を出さなかった | 毎回必ず1つ入れる |
| 「残す」と言われた設定を変えた／薄めた | その案だけ作り直す |
| 明らかな指示なのに確認で1ターン使った | 明らかなら即生成。訊くのは分からないところだけ |
| 新しい設定が前の決定を壊しているのに黙っていた | **いちばん高くつく事故。**「壊す」側を必ず書く |
| ◎必須・○優先に引っかかる案を黙って並べた | ⚠️ を付けて出し直す |
| 引っかかりを理由に案を勝手に取り下げた | 引っかかり＝禁止ではない。**気づかせるための表示。**採否はユーザーが決める |
| **AI が自分で出した細部を、動かせない決めごとのように扱った** | **それは目安。**直して1行報告する |
| **AI が足した人物の属性・困りごとの中身を、そのまま ✅ で確定した** | **既定は枠。**`・中身は未定` を付け、満たすことだけ残して確認を取り直す |
| 空き枠を 📋宿題 に入れた | **入れない。**宿題は先に進めないこと。空き枠は進めるからこそ空けてある |
| 訊かれてもいないのに空き枠を埋めにいった | **埋めるのはユーザーが言ったときだけ。**件数の報告で止める |
| 「満たすこと」を書かずに枠だけ作った | それはただ決めていないだけ。**満たすことが書けないなら枠にしない** |
| 目安の食い違いのために、決めてもらおうとして止まった | **直してよい。**決めてもらうのは、固定と ◎必須・○優先 だけ |
| 数字を先に固めて、そこに出来事を合わせようとした | **出来事が主、数字が従** |
| 状態ファイルの更新を「後でまとめて」にした | **毎ターン更新。**会話が縮められると消える |
| 決まったことを厚く書きすぎてファイルが膨らんだ | 1件1〜3行。あらすじにあるものは1行＋参照 |
| 番号を振った／管理番号を `brainstorm/` の外に書いた | 名前で呼ぶ。外のファイルには普通の言葉で書く |
| **あらすじを書いたのに初読メモを付けなかった** | **書き出しと初読メモは1操作。**その場で付ける |
| 初読メモを、作った側の知識を前提に書いた | **知識を捨てて読む。**「前に決めたから分かるはず」は通用しない |
| 直した初読メモを消した | ✅にして**残す** |
| ユーザーの案を無条件に褒めて通した | 懸念とトレードオフを必ず添える |
| **やめた案の素材まで禁止に広げた** | **やめたのは案だけ。**迷ったら1行で確認する |
| 「終了」と言われたものを「とっておく」に回した | 指示に反する。回さない |
| 決めたのに、あらすじに反映しないまま次へ進んだ | **同じターンで直す。**できないときは「まだ入れてない」に積む |
| ユーザーに確認せずに `02_設定/` を書き換えた | **前／後・なぜ直すか・困ること・混乱することを添えて提案する。**許可されたら直す |
| 直したほうがいい設定に気づいたのに、「まだ入れてない」に積んだだけで提案しなかった | **積みっぱなしにしない。**一区切りのときに提案を出す |
| 断られた設定の変更を、毎ターン蒸し返した | **次の一区切りまで出さない** |
| **決まったことを、影響を確かめずに外した** | **外すのも「直す」のうち。**どこに響くか＋どれくらい効いているかを出してから、確認を取る |
| 設定を直すとき、「前」と「後」を書かなかった | 1件ごとに必ず書く。「直しておきます」で済ませない |
| 意味がすぐ取れない業界語を使った | 普段使いの言葉に直す |
| セリフ案や地の文の案まで平易な言葉に直した | **作品の中の言葉は対象外。**平易にするのは**説明のほう** |
| **設定に引っかかるからと、案を丸めて弱くした** | **丸める前に足かせとして言う。**変え方か、外していい根拠までがセット |
| 足かせを言ったが、⭐こう変えれば を書かなかった | 指摘だけで終わらせない。追記して出し直す |
| ユーザーが確定した設定だからと、黙って避けて通った | **確定でも言ってよい。**外すかどうかを決めるのは本人 |
| 足かせを言うために質問を2つに増やした | 質問は1ターン1問。**選択肢に混ぜる** |
| 一度「外さない」と言われた設定を、また持ち出した | 二度と持ち出さない。その行に「（外さないと決めた）」を足す |
| ほかのやり方のほうが向いているのに、この中だけで続けた | 渡す選択肢を1つ入れる（⚠️ 勝手に渡らない） |
| 渡すときに、ユーザーに案を貼り直させた | 持ち込む。⚠️ 新しい状態ファイルも作らない |
| **案が選ばれた瞬間に、中身を全部確定にした** | **どこを採るかをチェックで訊く。**先頭に「全部このまま決定する」を置く |
| チェックの一覧に「全部このまま決定する」を置かなかった | **1クリックで終われなくなる。**必ず先頭に置く |
| 部品の割り方が細かすぎて、選択肢が7個以上になった | まとめ直す。3〜6個に収める |
| 複数の案の部品を、1つの一覧に混ぜた | 案ごとに分ける |
