# ワークフローの使い方まとめ

本プロジェクトには、小説執筆やプロット作成を効率化・高度化するための **4つの専用ワークフロー（スラッシュコマンド）** が用意されています。
それぞれの使用目的、正確な挙動、有効活用の方法を以下にまとめます。

### 📌 全体像（4つの役割分担）

- **`/brainstorm`** … 話の骨格をゼロから練る　➔ **発想**
- **`/twist`** … どんでん返し・叙述トリックを設計し、フェアネスを検証する　➔ **仕掛け設計**
- **`/prompt`** … プロンプト集から最適なテンプレートを選んで実行する　➔ **日常の単発作業**
- **`/refill-free_memos`** … 白紙のフリーメモを補充する　➔ **環境整備**

前の3つは「**発想 ➔ 仕掛け設計 ➔ 単発の加工・検証**」という制作パイプラインを分担しており、役割が重複しないよう設計されています。最後の1つだけは執筆内容に関与しない、環境メンテナンス用のコマンドです。

---

## 0. 使う前に知っておくこと

### 🖥️ 動く環境

**Antigravity・Claude Code のどちらでも、4つすべてが同じコマンド名で利用できます。**

手順書の実体は `.agents/workflows/` にあり、Claude Code 側の `.claude/commands/` にはそれを参照するだけの薄い橋渡しファイルが置かれています。したがって、

- **手順を変更したいときは `.agents/` 側だけを直せば、両環境に反映されます**（唯一の情報源を1箇所に保つ設計）。
- `.claude/commands/` 側を編集する必要があるのは、Claude Code 固有の事情（使用ツールの指定など）を足すときだけです。

### ⚙️ 3つの対話型ワークフローに共通する仕様

`/brainstorm` `/twist` `/prompt` の3つには、共通の作法が組み込まれています。

- **質問は1ターンに1つだけ**。一度に質問攻めにされないよう設計されています。
- **選択肢には必ず「⭐AIの推奨＋その理由＋次点」が付く**。迷ったら推奨に乗れば進めます。
- **出力はすべて日本語**。ターミナル操作が必要な場合はUTF-8強制が前置されます。
- **回答は表（テーブル）ではなくブロック・カード形式**（`02_設定/AGENTS.md` の方針）。

### 🚧 「HARD-GATE」＝わざと止まる仕組み

3つの対話型ワークフローには、AIが早合点して完成品を出してしまうのを防ぐ安全装置（HARD-GATE）が入っています。**すぐに結論が出てこないのは不具合ではなく仕様です。**

- `/brainstorm` … 発散〜再生成のループを**最低2周**し、かつユーザーが「収束」と言うまで完成あらすじを出しません。
- `/twist` … 三層設計とフェアネス監査を終えるまで、トリックを「完成」として提示しません。
- `/prompt` … `[ ]` の穴埋めと対象ファイルの確定を終え、**完成プロンプト全文を提示して承認を得るまで**実行しません。

急ぎたいときは、後述の操作コマンド（「収束」「そのまま実行」など）で明示的に短縮を指示します。

## 1. `/brainstorm` （ミステリー深掘りブレスト）

- **使用目的:** エンタメ系ミステリーのあらすじやプロットを深く練り上げるための、本格的なブレインストーミングセッションを開始します。
- **使い方:** チャット欄で `/brainstorm` と入力して起動します（引数は不要）。
  - `brainstorm/` フォルダに過去のセッションが残っていれば、起動時に「**続きから再開／新規セッション**」を1問だけ確認されます。

### 🔄 進み方（6フェーズ）

1. **セッション設定** … 大雑把なテーマ／絶対に入れたい・避けたい要素／グリル強度（light・standard・hard、既定は standard）を確認。
2. **発散** … 方向性の異なる案を **4〜6個＋ワイルドカード1個** 提示。各案は「フック・主人公・トリック・動機・舞台・構成…」といったファセット（要素）に分解された状態で出てきます。
3. **部分選択** … 案を丸ごと選んでも、**要素単位で選んでもOK**。「2のトリック＋4の動機＋1の舞台」のような指定ができます。
4. **傾向確認** … 2〜3周ごとに、AIが推定したあなたの好み（「◯◯を重視し、△△は避けたい」）を言語化して確認してきます。ここで誤解を訂正できるので、**違うと感じたら遠慮なく修正してください**。
5. **再生成** … 選択済み要素＋確認済みの嗜好を制約として、次世代の案を提示。以降3〜5を満足するまでループ。
6. **グリルモード（ストレステスト）** … 案が固まってきたら尋問モードへ。トリックの穴／動機の納得度／伏線の配置と回収／読者へのフェアネス／ご都合主義の有無を、1ターン1問で突いてきます。
7. **収束・出力** … 「収束」「まとめて」と指示すると、あらすじ確定版を作成。セルフレビュー＋「ミステリー読者」「担当編集者」の多視点レビューを経て保存されます。

### 📁 作られるファイル

セッション中は**毎ターン**、以下が自動更新されます（会話が長くなって文脈が圧縮されても内容を失わないための仕組み）。

- `brainstorm/<セッション名>_tree.md` … アイデアツリー。全分岐をノードID（N1、N1-2…）で記録
- `brainstorm/<セッション名>_preferences.md` … 嗜好プロファイル（採用／却下した要素の蓄積）
- `brainstorm/<セッション名>_summary.md` … 収束フェーズで生成される最終成果物

> 💡 収束時には「**ボツにしたが光る要素リスト**」が必ず併記されます。今回使わなかった案も、後の作品のためにここに貯まっていきます。

### 🎮 会話中に使える操作コマンド

- **「しおり」** … 現在地に⭐を付けて後から戻れるようにする
- **「N1-2に戻る」「しおり2に戻る」** … 過去の分岐点に戻り、選ばなかった選択肢を再提示させる（**元の枝は削除されない**ので、戻っても今の枝は失われません）
- **「一覧」** … しおり一覧と現在地を表示
- **「比較 N1-2 N1-3」** … 2つの枝を並べて比較し、優劣の所見をもらう
- **「グリル」／「softer」「harder」** … 尋問モードの開始と強度変更
- **「収束」「まとめて」** … 最終出力へ

### ✨ 有効活用の仕方

- **ゼロからのアイデア出し:** 新しい小説のコンセプトや設定を固めたい時に最適です。1ターン1問のペースで質問が来るため、対話を通じて自然とアイデアが引き出されます。
- **長期間のプロット構築:** 状態がすべてファイルに保存されるため、日をまたいでも「続きから」再開でき、文脈を見失いません。
- **枝分かれを恐れず試せる:** 分岐は消されずツリーに残るので、「Aの路線も捨てがたい」と思ったら、しおりを打って別路線を試し、後から比較できます。
- **そのままトリック設計へ移行できる:** 骨格が固まったら、セッションを閉じずに「**トリック錬成**」と伝えるだけで `/twist` に接続できます（➔ 詳細は「2. `/twist`」の「🔗 `/brainstorm` との連携」）。

## 2. `/twist` （どんでん返し・叙述トリック錬成）

- **使用目的:** ミステリーの醍醐味である「どんでん返し」や「叙述トリック」の設計・強化・検証に特化したセッションを開始します。
- **使い方:** チャット欄で `/twist` と入力して起動します。
  - `brainstorm/` に既存セッションがあれば、「**既存のブレストに接続する／単体でトリック設計を始める**」を1問だけ確認されます。接続した場合は、そこまでのプロット文脈と嗜好をそのまま引き継ぎます。

### 🔄 進み方（6フェーズ・真相からの逆算）

1. **前提確認** … 既存プロットの有無／騙しの規模（ラスト一撃の大逆転か、中盤の中規模ツイスト連打か）／絶対に守りたい制約。
2. **「読者の思い込み」の棚卸し** … トリックの土台は読者が無意識に置く前提です。裏切れる思い込みを4〜6個＋ワイルドカードで洗い出します（例：「語り手は真実を語っている」「この二人は別人だ」）。**どの思い込みを裏切るかが決まるまで、型選びには進みません。**
3. **型の選択** … 型カタログ（どんでん返し系・叙述トリック系・支援技法）から適合する型を3〜5個提示。ここで「**叙述トリックは文章媒体特有の技法**（映像化すると成立しないものが多い）」という媒体適性の確認が入ります。
4. **三層の逆算設計** … 「**真相層**（実際に何が起きたか）➔ **表層**（読者に見せる物語。どこを書かないか）➔ **誤導層**（どこへ注意を逸らすか）」の順に、真相側から組み立てます。
5. **伏線・手がかり設計** … 各手がかりについて「初読時の見え方／再読時の意味／配置位置／カムフラージュ方法」を対応表に落とします。
6. **フェアネス監査** … 手がかりの後出しがないか、再読しても矛盾しないか、驚きだけで納得が置き去りになっていないか、既視感はないか、トリック都合でキャラが壊れていないかを尋問。
7. **出力** … 真相シート＋伏線対応表＋監査結果を完成させます。

### 🚫 設計上の禁じ手（監査で弾かれるもの）

- **地の文で嘘を書くこと** … 真実だけを不完全・多義的に配置して、読者が勝手に誤読する形にします（信頼できない語り手を意図的に使う場合のみ、その旨を明記して例外扱い）。
- **手がかりが1個だけ／直前配置だけ** … 「後出し伏線」として却下されます。**最低3個・分散配置**が原則。
- **二重読みが成立しない手がかり** … 再読時に意味が反転しないものは、そもそも伏線と認められません。

### 📁 作られるファイル

- `brainstorm/<セッション名>_twist_sheet.md` … **真相シート＋伏線対応表＋監査結果**（このワークフロー固有の成果物）
- `/brainstorm` から接続した場合は、既存の `tree.md` に枝を継ぎ足し、完成した真相シートへの参照を該当ノードに書き戻します（新規ファイルは作りません）。

### 🎮 固有の操作コマンド

`/brainstorm` 共通のコマンド（しおり／戻る／一覧／比較／softer・harder／収束）に加えて、

- **「再読テスト」** … 現時点の設計で再読シミュレーションだけを即実行
- **「型カタログ」** … トリックの型一覧を表示
- **「禁じ手チェック」** … 地の文の虚偽・後出し伏線・二重読み不成立の3点を即時確認

### 🔗 `/brainstorm` との連携（このワークフロー最大の強み）

`/twist` は `/brainstorm` の**姉妹ワークフロー**として作られており、ファイル形式（tree.md／preferences.md）・選択肢フォーマット・しおり運用をすべて共有しています。そのため「あらすじ作りの続きとして、そのままトリック設計に入る」ことができます。

#### ① 接続する2つのルート

**ルートA：ブレストの途中から呼び出す（同一セッションで継続）**

`/brainstorm` で対話している最中に、そのまま次のように伝えます。

```text
トリック錬成
```

セッションを中断せず、その場でトリック設計モードに切り替わります。話の流れが途切れないので、「この案、仕掛け次第で化けそう」と感じた瞬間に踏み込めるのが利点です。

> 💡 この呼び出し方は `/brainstorm` `/twist` 双方の手順書に操作コマンドとして登録済みです。万一反応しない場合は、ルートBか、次のように明示的に指示してください。
> `.agents/skills/twist-trick-forge/SKILL.md に従って、このセッションに接続してトリック設計を始めてください`

**ルートB：後日 `/twist` を起動して接続する**

日を改める場合はこちらです。`/twist` を起動すると `brainstorm/` 内の `*_tree.md` が検出され、

> 「既存のブレストセッションに接続しますか？　それとも単体でトリック設計を始めますか？」

と1問だけ聞かれるので、**「接続する」** を選びます。複数セッションがある場合は、どのセッションかを伝えてください。

#### ② 接続すると何が引き継がれるか

- **プロットの現在地** … `tree.md` を読み込み、どの枝のどの案まで決まっているかを把握した状態で始まります。あらすじを説明し直す必要はありません。
- **あなたの好み** … `preferences.md` の嗜好プロファイル（採用／却下してきた要素の傾向）を引き継ぐため、提示される型や案が最初からあなた寄りになります。
- **しおり・分岐** … ブレスト側で打ったしおりや分岐にそのまま戻れます。

そのうえで、フェーズ0の残り（**騙しの規模**＝ラスト一撃か中盤ツイスト連打か、**絶対に守りたい制約**＝「この人物は犯人にしない」等）だけを確認して本題に入ります。

#### ③ 接続中のファイルの扱い

- **新しい `tree.md` は作られません。** 既存の `tree.md` に、トリック設計の分岐が**枝として継ぎ足されます**。
- トリック固有の成果物として `brainstorm/<セッション名>_twist_sheet.md`（真相シート＋伏線対応表＋監査結果）が追加されます。
- 完成時には、`tree.md` の該当ノードに **`twist_sheet.md` への参照が書き戻されます**。これにより、後からしおりでその地点に戻り、**別のトリック案を第2案として試す**ことができます。

> 💡 もし接続したのに新しいセッション名でファイルを作り始めたら、「既存の `<セッション名>_tree.md` に枝を継ぎ足してください」と指示して修正させてください。

#### ④ 切り替えるベストタイミング

- **接続に向くタイミング:** 犯人・動機・舞台といった**骨格が一通り決まった後**。フェーズ1で「読者の思い込み」を棚卸しするには、裏切る対象となるプロットが必要なためです。
- **早すぎる場合:** テーマしか決まっていない段階では、まず `/brainstorm` を2〜3周させて骨格を固めるほうが結果的に早く進みます。
- **戻ってよい:** トリック設計の途中で「この仕掛けを成立させるには動機を変えたい」と気づいたら、**`/brainstorm` 側の該当ノードに戻って再発散**できます。行き来は前提の設計です。

#### ⑤ 典型的な往復の流れ（例）

1. `/brainstorm` … フェーズ1〜4を2周し、犯人と動機の候補が固まる ➔ 「**しおり**」を打つ
2. そのまま「**トリック錬成**」 ➔ 読者の思い込みを棚卸し ➔ 型を選択 ➔ 三層設計
3. フェアネス監査で「動機がトリック都合で不自然」と指摘される ➔ 「**しおり1に戻る**」で 1. の地点へ
4. `/brainstorm` 側で動機だけ再発散し、新しい枝として採用
5. 再度トリック設計に戻り、監査を通す ➔ `twist_sheet.md` 完成、`tree.md` に参照が書き戻される
6. 最後に `/brainstorm` で「**収束**」 ➔ トリックを織り込んだあらすじ確定版を `summary.md` に出力

#### ⑥ 単体起動を選ぶべきケース

以下の場合は接続せず「単体でトリック設計を始める」を選びます。

- 既存プロットと無関係に、**トリックのアイデアだけを試作**したいとき
- 別作品・短編用の仕掛けを考えたいとき（既存セッションの嗜好や制約に引きずられないため）
- すでに完成した仕掛けを持ち込んで、**監査だけ**を受けたいとき

### ✨ 有効活用の仕方

- **トリックの壁打ち:** 読者を騙す巧妙なトリックを作りたい時や、ラストの展開にインパクトを持たせたい時に、専門的な観点から詰められます。
- **`/brainstorm` との連携:** 上記のとおり、「基本的なあらすじができた後に、トリック部分だけを重点的に強化・検証する」というシームレスな使い方が非常に強力です。
- **完成済みトリックの検査にも使える:** ゼロから作るだけでなく、すでにある仕掛けを持ち込んで「再読テスト」「禁じ手チェック」だけ回す、という使い方も有効です。

## 3. `/prompt` （プロンプト・ディスパッチャー）

- **使用目的:** プロンプト集（`01_free_memo/プロンプト集.md`）の中から、現在の目的に最適なテンプレートをAIが自動で選び、`[ ]` を埋めて実行してくれます。
- **使い方:** やりたいことを一言添えて起動します。

  ```text
  /prompt 第5章の伏線が回収できてるか見て
  ```

  引数なし（`/prompt` だけ）でも起動でき、その場合は「今日は何をしますか？」と、よく使う入口を添えて1問だけ尋ねられます。

### 🔄 動作の流れ

1. **プロンプト集を読み直す** … 記憶ではなく毎回ファイルを読むため、**編集した内容が即座に反映されます**。
2. **テンプレート選定** … 依頼を「工程」に分類し、⭐推奨＋理由＋次点の形で提示。
3. **対象の特定** … 参照・編集するファイルのパスを明示して確認（IDEで開いているファイルが第一候補になります）。
4. **パラメータ補完** … `[ ]` を埋めます。AIが推定できる箇所は勝手に埋め、**推定した箇所は「（推定）」と明示**されます。質問は本当に判断できないものだけ、1ターン1問。
5. **部品スニペットの付与** … 「推測と創作を分けて書く」「ボツ案も列挙する」などの共通条件を文脈に応じて最大3つまで追加（表を使わないルールは常時付与）。
6. **完成プロンプトの提示と承認** … 全文が ```text ブロックで提示され、`[このまま実行]` `[ここを直したい]` `[別のテンプレートにする]` を選びます。
7. **実行 ➔ フィードバック** … 実行後、「このテンプレートを追加してはどうか」「この条件行を足してはどうか」という**プロンプト集への追記提案**が出ます。

### 🎮 操作コマンド

- **「別のテンプレート」** … 選定をやり直し、次点以下を提示させる
- **「プロンプトだけ」** … 実行せず、完成プロンプトの提示で停止（**他のAIツールに貼り付けたいとき**に便利）
- **「そのまま実行」** … 承認ステップを省略して即実行（提示自体は必ず行われます）
- **「一覧」** … プロンプト集のクイックインデックスを表示
- **「追記して」** … 追記提案をプロンプト集に反映

### ✨ 有効活用の仕方

- **日常タスクの効率化:** 文章の校正、設定の整理、特定要素のチェックなど、「プロンプトを探してコピペする」手間を省きたい単発タスクに最適です。
- **自動ナビゲーション:** 依頼内容が重厚なプロット作成やトリック設計に該当する場合は、AIが `/brainstorm` や `/twist` への切り替えを1問で提案してくれます（勝手には切り替わりません）。判断基準は「**複数ターンで分岐を記録しながら煮詰める作業なら委譲、1〜2ターンで完結するならこのまま実行**」。
- **使うほど育つ:** プロンプト集にテンプレートを追加すれば、そのぶん `/prompt` の対応範囲がそのまま広がります。**章番号の変更・章の並べ替え・名称変更をしてもメンテ不要**（AIは番号ではなく内容で照合するため）。
  - ⚠️ **唯一メンテが必要なのは、`01_free_memo/プロンプト集.md` を移動・改名したとき**です。その場合は `.agents/skills/prompt-dispatcher/SKILL.md` と `.agents/workflows/workflow-prompt.md` の2箇所を修正してください。

## 4. `/refill-free_memos` （フリーメモ補充）

- **使用目的:** `01_free_memo` フォルダの `free_memo_01.md` 〜 `free_memo_10.md` のうち、**存在しない番号のファイルを自動生成**し、白紙メモのストックを常に10個に保ちます。
- **使い方:** チャット欄で `/refill-free_memos` と入力して起動します。
  コマンドを使わず、PowerShell で直接スクリプトを叩いても結果は同じです。

  ```powershell
  [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $env:PYTHONUTF8=1; python .agents/scripts/refill_free_memos.py
  ```

  ※ PowerShell と Python が前提です。文字化け防止のため、UTF-8指定を必ず前置してください。
  ※ カレントディレクトリはプロジェクトルート（`idea_of_novel/`）にしてください。

### ⚠️ 正確な挙動（誤解しやすいポイント）

このスクリプトは **メモの「中身」を一切見ません**。判定しているのは**ファイル名の有無だけ**です。

- `free_memo_01.md` 〜 `free_memo_10.md` のうち、**存在しない番号だけ**を新規作成します。
- **既存ファイルは絶対に上書きしません。** 何度実行しても安全です（書きかけのメモが消える心配はありません）。
- 対象は **01〜10 の固定範囲**。11個目以降は作られません。
- 作成されるファイルには、「このメモはアイデアであって決定事項ではない」旨のAI向け注意書きが最初から入っています。

### 📝 正しい運用（ここが肝心）

上記のとおり**ファイル名の有無で判定する**ため、メモを使ったら**リネームするか、別フォルダへ移動する**のが正しい使い方です。

- ✅ `free_memo_03.md` に書いた内容が固まった ➔ `01_free_memo/その他/○○について.md` などへ**改名・移動** ➔ `/refill-free_memos` で 03 が補充される
- ❌ `free_memo_03.md` という名前のまま中身だけ書き込む ➔ ファイルは存在するので**補充対象にならず**、白紙ストックが減ったままになる

### ✨ 有効活用の仕方

- **執筆環境の整備:** アイデア出しでフリーメモを消費した後に実行することで、常に10個の白紙メモをストックしておけます。手作業でファイルを作る煩わしさがなくなります。
- **定期実行が向いています:** 上書きの危険がないので、「作業の区切りごとにとりあえず叩く」運用で問題ありません。

- **「新しい話を考えたい」「あらすじをゼロから練りたい」** ➔ `/brainstorm`

- **迷ったらまず `/prompt`:** 依頼が重ければ AI 側が `/brainstorm` `/twist` を提案してくれるため、入口として使って問題ありません。
