## 🧭 0. このファイルの使い方

### 記法ルール

- `[ ]` … **必ず自分の言葉に置き換える箇所**です。例：`[数：例「5個」]` → `5個`
- `※` … AIへの補足指示。不要なら消してかまいません。
- `【 】` … プロンプト内のブロック見出し。AIが指示の構造を把握しやすくなるため、**消さずに残すことを推奨**します。

### 使い方の3ステップ

1. インデックスから目的に近いテンプレートを探す
2. `[ ]` を埋める（迷ったら埋めずに投げて、AIに「不足情報を質問して」と言うのも有効）
3. 参照させたいファイルを**明示的に指定**する（例：`@02_設定/キャラクター/chr_a01_時風隼（探偵）.md を踏まえて`）

### 🚀 探すのが面倒なときは `/fal-prompt`

上記の1〜3をAIに肩代わりさせるコマンドを用意しています。

```text
/fal-prompt 第5章の伏線が回収できてるか見て
```

やりたいことを一言添えて起動すると、AIがこのファイルから最適なテンプレートを選び、`[ ]` を埋め、
完成したプロンプトを提示したうえで実行します（→ 詳細は 12章「案A」）。

`/fal-prompt` は起動のたびにこのファイルを読み直すため、**テンプレートを自由に加筆・改編して構いません**。
ただしこのファイル自体を移動・改名する場合のみ、スキル側の修正が必要です（→ 12章「メンテナンス」）。

### プロンプトの基本骨格（5点セット）

長く書けば良いわけではありませんが、質の高い回答には次の5要素がそろっている傾向があります。
このファイルのテンプレートは、すべてこの骨格に沿って作られています。

1. **役割**：誰として答えるか（例：プロのミステリー編集者として）
2. **目的**：何のための作業か（例：矛盾を潰して初稿に進めるため）
3. **入力**：何を見て考えるか（対象ファイル・前提設定）
4. **制約**：やること／やらないこと（例：要約しない、3案出す、既存設定を変えない）
5. **出力形式**：どんな形で返すか（例：カード形式の箇条書き、案ごとに見出しを立てる）

## 💡 1. プロンプトを効果的にするコツ (Tips)

### 1-1. 最新のプロンプトの考え方：「指示」から「仕様書」へ

AIに漠然と「面白い展開を考えて」と指示する時代は終わりました。現在はプロンプトを「仕様書（スペック）」あるいは「契約」として捉えるのがベストプラクティスです。
質の高い回答には、次の要素が明確に定義されている必要があります。

1. **役割（Role）**：誰として答えるか（例：プロのミステリー編集者、レッドチームのレビュアー）
2. **目的（Objective）**：何のための作業か（例：矛盾を潰すため、読者の先入観を利用するため）
3. **入力（Context）**：何を見て考えるか（対象ファイル・前提設定。※後述のコンテキスト管理が重要）
4. **制約（Constraints）**：**やること／やらないこと**（例：要約しない、陳腐な展開は避ける）
5. **出力形式（Output Format）**：どんな形で返すか（例：カード形式、見出しを立てる、騙し度を％で表記する）

### 1-2. 精度を上げるテクニック（プロンプトチェーンとコンテキスト）

- **プロンプトチェーン（反復と壁打ち）**
  一度の指示で完璧なものを出させようとしないでください。「まずは広く浅くアイデアを出す」→「その中から一つを選び深掘りする」→「論理破綻がないか検証させる」と、工程を分割して対話を重ねる（チェーンする）のが最も高品質な出力に繋がります。
- **コンテキストエンジニアリング（情報の絞り込み）**
  AIにすべての設定ファイルを一度に読ませると、重要な制約が見落とされます。必要な情報だけを抜粋・要約して渡すことが重要です（→ 2章の「コンテキスト抽出プロンプト」を活用）。
- **肯定形で制約を書く（ネガティブプロンプトの工夫）**
  「〇〇しないで」より「使い古された展開だと判断した場合は、その理由を書いたうえで別案に差し替えて」のように、「代わりにどうするか」をセットで書くほうが機能します。
- **お手本を1つ渡す（少数例の提示）**
  「こういう書き味にしてほしい」という既存の自作テキストや好きな作品の一節を添えると、抽象的な形容詞より遥かに効きます。

### 1-3. やりがちなNG

- **抽象的な形容詞だけで頼む**（「もっと面白く」「エモく」）→ 何を変えるかを具体化する
- **1回の指示に複数の目的を詰め込む** → 工程を分割する（アイデア出しと推敲を分ける）
- **AIの最初の案をそのまま採用する** → 最初の案は「たたき台」。必ず1回は深掘りか差し替えを要求する

### 1-4. コピペ用「部品」スニペット集

どのテンプレートにも足せる汎用の追加条件です。必要なものを末尾に貼り付けてください。

```text
※不足している前提情報があれば、作業を始める前に私に質問してください。
```
```text
※出力後、自分の回答を批判的に読み直し、条件違反・矛盾・冗長箇所があれば指摘し修正版を示してください。
```
```text
※各案には ⭐推奨案 を1つ選び、その理由と、次点の案も添えてください。
```
```text
※提案の中に、小説執筆で実際に採用する際のデメリット、反対意見、読者が不満を抱くリスク、注意点などがあれば、必ず併記してください。
```
```text
※明らかな間違いや軽微な修正は、私が確認しなくても一括で変更・統合して構いません。
```
```text
※回答は表（テーブル）形式を使わず、カテゴリ分けされたブロック・カード形式で書いてください。
```

## 📂 2. ファイルの整理・統合・レイアウト調整

テキストデータの整理や、設定資料としてのフォーマット統一を行うためのプロンプトです。

### 📄 新規セッション用：コンテキスト抽出テンプレート

**使う場面**：新しいタスク（シーン執筆など）を始める際、AIのコンテキスト窓を溢れさせないよう、必要な設定だけを既存ファイルから抽出させたいとき。

```text
これから[目的：例「第5章の執筆」]を行います。
現在の設定ファイル群（@[フォルダパス]）の中から、この目的に必要な設定（登場人物の現在の状況、伏線、舞台設定）だけを抽出し、要約した「コンテキスト・シート」を作成してください。
・不要な情報（過去に解決済みの事件、この章に登場しない人物の裏設定など）は削ぎ落としてください。
・ここで作成したシートを、以降のプロンプトの前提知識として固定します。
```

### 📄 汎用：ファイル整理・統合テンプレート

**使う場面**：バラバラに書き溜めたメモや、重複した内容を、要約せずに1つの資料へまとめたいとき。

```text
以下のファイル（またはテキスト）内容を、[目的：例「小説執筆の基本資料とする」]ために整理・統合してください。

【整理の条件】
・文章の要約や削除は行わず、元の記述や必要な説明を最大限残すこと。
・重複する内容や似通った意見は1つにまとめ、最も適切な表現を採用すること。
・マークダウン形式を使用し、内容に応じて見出し（カテゴリー・サブカテゴリー）を作成し、読みやすくグループ化すること。
・統合によって生じた設定の矛盾や、どちらを採用すべきか迷うデメリット・注意点があれば必ず明記すること。
```

### ✂️ ファイル分割・ナレッジ整理テンプレート

**使う場面**：1つのメモが肥大化して探しにくくなったとき。資料をAIに読ませやすい単位へ再編したいとき。

```text
この[ファイル]が肥大化して探しにくくなっています。ナレッジベースとして扱いやすい形に再編する案を提示してください。

【条件】
・内容を「絶対に削除しない」こと。情報の欠落がないか自己検証を行うこと。
・意味のまとまりごとに[数：例「3〜5」]ファイルへ分割する案を作ること。
・分割によって情報が分断され、参照しにくくなるデメリットがある場合は指摘すること。
※実際のファイル作成は、私が案を承認してから実行してください。
```

### 🔗 設定変更の波及反映テンプレート

**使う場面**：ある設定を変更したあと、他のファイルに残った古い記述を洗い出したいとき。

```text
[変更内容：例「キャラクターAの年齢を17歳から19歳に変更した」]という設定変更を行いました。
この変更の影響を受ける記述を、[対象範囲：例「02_設定 フォルダ以下のすべてのファイル」]から洗い出してください。

【出力してほしいもの】
・矛盾が生じる箇所の一覧（ファイル名・該当箇所の引用・なぜ矛盾するか）
・それぞれの修正案
・直接の矛盾ではないが、変更後は不自然に感じられる箇所（例：言動の幼さ、周囲の扱い）
※修正の実行は、私が一覧を確認してから指示します。
```

## ✍️ 3. 設定や文章のブラッシュアップ・補強

既存のアイデアの矛盾点を潰したり、説明を肉付けしてクオリティを上げるプロンプトです。

### 🔍 レッドチーム検証（悪魔の代弁者）テンプレート

**使う場面**：設定の穴やご都合主義を、極めて厳しく洗い出してほしいとき。

```text
この[対象：例「プロット」「設定ファイル」]に対し、「レッドチーム（脆弱性攻撃チーム）」として容赦なく論理破綻やご都合主義を突いてください。

【評価の視点】
・[悪魔の代弁者] 批判的な読者の視点で、「なぜ〇〇しなかったのか」「この物理法則はおかしい」というツッコミどころを徹底的に探す。
・[キャラクター行動原理] 登場人物の性格や能力から見て、この決断が不自然（キャラブレ）でないかを監査する。

【出力条件】
・不自然な点、矛盾点があれば、その理由とともに修正案を提示すること。
・修正案を採用した場合に生じる別の矛盾やデメリットも必ず併記すること。
・明らかな間違いや軽微な修正は、私が確認しなくても一括で変更・統合して構いません。
```

### 📖 説明の補強・充実化（ネガティブ制約付き Show, Don't Tell）

**使う場面**：設定やシーンの記述が薄く、「説明くさい」文章を解像度の高い描写に引き上げたいとき。

```text
[指定箇所] の説明的な記述を、読者が情景や感情をありありと想像できる「描写（Show）」に変換・充実させてください。

【厳格な禁止事項（ネガティブプロンプト）】
・「悲しい」「嬉しい」「怒った」などの**感情を表す形容詞・直接的な言葉を一切使用しないでください**。
・代わりに、視線、呼吸、温度、周囲の環境音などの五感と身体的反応で表現してください。

【出力条件】
・加筆した箇所が元の記述と区別できるよう、[方法：例「加筆部分の冒頭に（加筆）と付ける」]こと。
・修正案は、方向性を変えたものを[数：例「3パターン」]提示し、それぞれの狙いを添えること。
・各表現が読者に与える印象の違いと、小説内で使う際の注意点（くどくなる等）を明記すること。
・⭐推奨案を1つ選び、理由を添えること。
```

### 🧪 専門用語・難解概念の「三段階」噛み砕き

**使う場面**：作中に出す科学・医学・哲学の概念を、読者に伝わる形へ翻訳したいとき。

```text
[概念：例「二重共感問題」「決定論」]について、以下の3段階で説明してください。

1. 専門的に正確な説明（学術的な定義）
2. 予備知識のない読者にも直感的に伝わる、日常的な比喩を用いた説明
3. 上記2を、作中の[誰：例「探偵の時風隼」]が[誰に：例「助手の亜紀人」]に語る形の会話文にした場合の例（[キャラクターの口調・性格]を反映すること）

・説明が長くなりすぎて物語が止まらないよう、会話文は[目安：例「200字以内」]に収めること。
・この概念を物語のトリックや動機に組み込む際、よくある誤解や、俗流解釈（陳腐化）に陥りやすい落とし穴があれば事前に指摘すること。
```

## 🎭 4. ストーリー展開・アイデア考案（ブレスト）

アイデア出しは最重要工程です。AIに広く浅い選択肢を出させるフェーズと、ピンポイントで深く考察させるフェーズを使い分け、段階的に（プロンプトチェーンで）進めるのがコツです。

### 🌊 4-1. 広く浅いアイデア出し（ブレインストーミング初期）

**使う場面**：まだ方向性が決まっておらず、とにかく発想の幅を広げて多数の選択肢を見たいとき。

```text
[前提となる設定・お題] をベースに、[求める内容：例「密室トリックの構成」]について、まずは広く浅く、可能な限り多様な方向性のアイデアを【5個】提案してください。

【条件】
・5個の案は、それぞれ「アプローチの軸（物理的、心理的、時間差、第三者の介入など）」を意図的にずらして重複を避けること。
・各案には「メリット」と、小説として成立させる際の「デメリットや読者が不満を抱くリスク」を必ず併記すること。
・各案のミステリーとしての「騙し度（意外性）」を 0〜100% で自己評価し、添えること。
・この段階では詳細なプロットは不要です。概要だけを簡潔に提示してください。
・最後に、あなたがプロの編集者として最も推したい⭐推奨案を1つ選び、その理由を教えてください。
```

### 🎯 4-2. ピンポイントで深い考察（アイデアの深掘り）

**使う場面**：4-1で出たアイデアの1つを選び、詳細なプロットやトリックのロジックを詰めたいとき。

```text
先ほど提案されたアイデアのうち、[選んだ案：例「案3の時間差トリック」]を採用します。
これについて、以下のステップ・バイ・ステップで深くピンポイントな考察を行い、詳細な構成案を作成してください。

【思考ステップ】
1. **多層的な構造化**: このトリックを「①第一の解釈（読者が最初にする自然な誤認）」「②ミスリード（怪しい人物などへの疑い）」「③真の真相」の3層構造に分解して設計する。
2. **条件の重ね掛け**: 物理的なトリックだけでなく、読者の心理的な先入観（バイアス）を利用する要素を組み合わせる。
3. **伏線の配置**: 真相に至るための決定的な証拠を、物語の序盤・中盤にどう（不自然でなく）配置するか具体案を出す。

【出力条件】
・このトリックを実行する上での最大の「論理的弱点・物理的矛盾のリスク」を指摘し、それをカバーするアイデアも提示すること。
・⭐このトリックを最も効果的に見せるための推奨される演出（視点人物の選び方など）を提案すること。
```

### 🗣️ 4-3. 逆質問（壁打ち）による解像度アップ

**使う場面**：漠然としたアイデアを対話で具体化し、AIに選択肢を出させながら臨機応変に発想を広げたいとき。

```text
[テーマやあらすじ]についてアイデアを練りたいです。
設定の穴を潰し、より深い展開を作るために、私に対して「プロのミステリー編集者」の視点から、1つずつ深掘りする質問を投げかけてください。

【壁打ちのルール】
・質問は必ず1ターンに1つだけにしてください。
・私が回答に詰まったときのために、各質問には「発想のヒントになるようなバリエーション豊かな回答例・選択肢」を必ず【3つ】提示し、さらにあなたの⭐推奨案を示してください。
・私が答えたら、その回答を踏まえて次の質問をする、という対話形式で進めましょう。
・[強度：例「遠慮なく厳しく突っ込んでください」/「まずは優しめに、発想を広げる方向で」]
```

### 🔀 4-4. 発想の強制ずらし（マンネリ打破）

**使う場面**：自分の案がどれも似通ってしまい、発想の枠を壊したいとき。

```text
現在、[題材：例「動機」]について次の案を考えていますが、発想が似通っています。
【現在の案】
[案を列挙]
```

## 🃏 5. 読者を騙す仕掛けの設計（バイアス・叙述トリック・どんでん返し）

読者の**先入観・認知バイアスを積極的に利用**し、トリックやどんでん返しを設計・検証するプロンプト群です。

### 📌 この章の位置づけ（他資料との使い分け）

仕掛けづくりの資料は複数あります。目的で使い分けてください。

- **発想の方法論そのものを知りたい／AIが陳腐な案しか出さない**
  → `01_free_memo/ギミック・どんでん返し/「超ド級のトリック」を発案するための方法論.md`
  （矛盾ペア・遠距離類推・確率併記・レッドチーム検証など、手順の解説と根拠）
- **腰を据えて1つの仕掛けを完成まで設計したい**
  → `/fal-twist`（三層設計とフェアネス監査を強制する対話セッション）
- **どんな「型」があるか一覧したい**
  → `.agents/skills/twist-trick-forge/trick-catalog.md`
- **この章**：上記を単発で使えるプロンプトに落としたもの。とりわけ、**「型」ではなく「読者の認知」から入る**設計を扱います。

### 🧭 5-0. 三つの大原則

どのテンプレートを使うときも、この3点を外すと仕掛けが崩れます。

- **嘘は書かない。**
  地の文で明示的な虚偽を書いた時点で、読者は「騙された」ではなく「だまし討ちされた」と感じます。真実だけを、**不完全に・多義的に**配置します。
- **騙すのは「書いたこと」ではなく「読者が自分で補完したこと」。**
  読者が勝手に埋めた空白こそが仕掛けの土台です。だから**何を書かないか**の設計が本体になります。
- **驚き × 納得 × 遡及的必然性。**
  驚きだけなら「ご都合」、納得だけなら「予定調和」。読み返したとき「それ以外あり得なかった」と感じて初めて完成します。

### 🎯 5-1. 読者バイアスの積極利用（棚卸しと逆算）

**使う場面**：読者が無意識に置く前提やバイアスを洗い出し、それを逆手にとった仕掛けを作るとき。

```text
以下のプロット（またはあらすじ）を読み、読者の「先入観・認知バイアス」を積極的に利用して騙すための設計を行ってください。

【プロット】
[貼り付け、またはファイル参照]

【出力してほしい内容】
1. 読者が無意識に前提として置いてしまうこと（例：「語り手はこの場に居合わせている」）を洗い出す。
2. その前提を生む認知の働き（例：配列＝時系列という思い込み）を解説する。
3. そのバイアスを「あえて強化するようなミスリードの記述」の具体例を提案する。
4. その前提が実は偽だった（裏切られた）場合に成立するトリック案を複数提示する。

【条件】
・各案について、読者が騙される確率「騙し度（％）」を自己評価すること。
・このバイアスを利用する際の「アンフェアだと読者に批判されるデメリット・リスク」と、それを防ぐ（フェアネスを保つ）ための注意点を必ず明記すること。
・⭐最も裏切り甲斐がある推奨案を1つ選ぶこと。
```

### ⚖️ 5-2. トリックの「論理破綻・物理的矛盾」セルフ監査（強制検証）

```text
【検証ステップ】
1. **物理的検証**: 時間的余裕、空間的距離、必要な筋力・道具、痕跡の有無など、物理的に不可能・不自然な点はないか？

【出力条件】
```

### 📕 付録 5-A：読者バイアス・カタログ

5-1 / 5-2 で「裏切る前提」を選ぶための一覧です。**型ではなく認知の分類**なので、同じ項目からでも実装は無限に作れます。
【擦り切れ】印は既に使い倒された領域。使うなら、その型自体ではなく「なぜ隠せたか」の必然性で差をつけてください。

**A. 補完バイアス（書かれていない属性を標準値で埋める）**

- A1 既定値の補完：明示されない属性を「多数派の標準」で補完する（性別・年齢・容姿・健康状態）【擦り切れ】
- A2 人間性の補完：語る主体は人間だと仮定する（動物・AI・幼児・機械・死者）
- A3 生存の補完：語っている以上、その時点で生きていると仮定する
- A4 舞台の補完：特記がなければ現代・日本・地上・現実だと仮定する
- A5 単数の補完：同じ呼称は同一人物、違う呼称は別人物だと仮定する

**B. 構造バイアス（本という形式そのものに由来）**

- B1 配列＝時系列：並んでいる順に起きたと仮定する
- B2 隣接＝因果：近くに書かれた出来事のあいだに因果を読む
- B3 見出しの信頼：章タイトル・日付・話者表記・小見出しは正しいと仮定する
- B4 地の文の信頼：会話は嘘でも地の文は真実だと仮定する（**ここを裏切るのは禁じ手**）
- B5 分量＝重要度：長く描写されたものが重要だと仮定する
  → 逆用：**決定的な手がかりを、退屈な描写の中に短く置く**。最も汎用性の高い手法のひとつ
- B6 文体＝視点の同一性：文体が同じなら同じ視点人物だと仮定する

**C. 推論バイアス（読者の思考のクセ）**

- C1 確証バイアス：一度容疑者を定めると、それに合う情報だけを拾う（ミスリード役が効く原理）
- C2 アンカリング：最初に提示された数字・仮説に引きずられる（第一発見者・最初の死亡推定時刻）
- C3 専門家の権威：医師の死亡判定や鑑識の報告は無謬だと仮定する（※ここを裏切る場合は「なぜ専門家が間違えたか」の強烈な必然性が必要）
- C4 二分法バイアス：「犯人はAかBか」と問われると、Cがいる可能性を忘れる（偽の二択）

**D. ジャンル・社会バイアス（作中に書かれていない前提）**

- D1 ジャンル慣習：探偵役は犯人ではない／死者は殺されている／視点人物は無実【擦り切れ】
- D2 語り手＝主人公＝善玉だと仮定する
- D3 役割の固定：助手は助手、被害者は被害者のまま
- D4 社会通念：職業・立場・年齢から人物像を補完する（介護者は善意、専門家は有能）
- D5 共感バイアス：感情移入した人物は疑わない
  → 本作の中核テーマ（他者の主観へのアクセス不可能性・二重共感問題）と直結する領域

**E. メタバイアス（読書行為そのものに由来）**

- E1 残量の判断：残りページが厚いのでまだ終わらないと判断する（※電子書籍では効きません）
- E2 挑戦状の信頼：「読者への挑戦状」の時点で解けるはずだという信頼
- E3 シリーズ前提：レギュラーは死なない／探偵は勝つ
- E4 作者への信頼：フェアに書かれているはずだという信頼

> ⚠️ **E4だけは裏切ってはいけません。** E1〜E3を裏切るのは仕掛けですが、E4を裏切るのは事故です。
> 「読者の期待を裏切る」と「読者との契約を破る」の境界がここにあります。

### 🪝 章末の「引き」設計テンプレート

**使う場面**：ページをめくらせる推進力が足りないと感じるとき。

```text
[章：例「第5章」]の結末について、読者が次章を読まずにいられなくなる「引き」の案を[数：例「5つ」]提案してください。

・引きの種類を分けること（新事実の開示／危機の発生／意味深な一言／視点の切り替え／読者だけが知る不穏 など）。
・それぞれについて「次章の冒頭がどう始まるか」までセットで書くこと。
・安易な引き延ばし（不自然な中断、翌章ですぐ肩透かしになるもの）は避け、そう判断した案は理由を添えて除外すること。
・⭐推奨案を1つ選び、理由と次点を添えてください。
```

### 🎯 ログライン・あらすじ作成テンプレート

**使う場面**：投稿サイト用の紹介文や、自分の中で作品の軸を再確認したいとき。

```text
この作品について、以下の3つの長さの紹介文を作成してください。

1. ログライン（1文・60字以内）：主人公／状況／障害／賭かっているものが分かる形
2. あらすじ（200字程度）：投稿サイトの紹介欄に載せる想定。ネタバレなし
3. あらすじ（800字程度）：物語の魅力と主要な謎が伝わる形。ネタバレなし

・それぞれ「この作品の最大の売り」が何であるかを踏まえて書くこと。
・書き終えたあとに、あなたが考える「この作品の売り」を1行で明記してください（私の認識とズレていないか確認するため）。
```

### 📝 文体ガイドライン準拠のドラフト生成

**使う場面**：構成が決まったシーンを、実際の本文として書き起こしたいとき。

```text
以下の条件でシーンの本文ドラフトを書いてください。

【参照する資料】
・文体：@00_作品コンセプト＆トータル設定/文体のガイドライン.md

【シーンの仕様】
・視点人物：[誰]／人称：[一人称／三人称]／時制：[過去形／現在形]
・場所と時刻：[ ]
・このシーンの目的：[例「読者に○○を印象づけつつ、実は伏線を仕込む」]
・入れる要素：[ ]／絶対に書かない要素：[例「犯人の内心」]
・目安の文字数：[例「1500字前後」]

【文章の条件】
・説明的な地の文で状況を要約せず、行動・会話・描写で見せること。

```

### 🌿 情景・五感描写の生成テンプレート

**使う場面**：舞台の空気感が書けず、筆が止まったとき。

```text
[場所・状況：例「夏の夕方、無人になった島の分校の教室」]の描写素材を集めたいです。

・五感（視覚・聴覚・嗅覚・触覚・味覚）ごとに、具体的なディテールを[数：例「5つずつ」]挙げてください。
・一般的な連想ではなく、その土地・季節・時刻でなければ成立しない固有のディテールを優先してください。
・[視点人物]の心情が[例：不安]であるとき、同じ風景がどう歪んで見えるかのバリエーションも添えてください。
※これは素材出しなので、完成した文章ではなく箇条書きで構いません。
```

### 🗨️ 会話シーン生成テンプレート

**使う場面**：情報を会話で開示したいが、説明台詞になってしまうとき。

```text
[人物A]と[人物B]の会話シーンを書いてください。

・伝えたい情報：[例「Aは事件当夜アリバイがないこと」]
・ただし、この情報を直接説明させず、[方法：例「二人の口論の流れの中で、Aが言い淀むことで読者に察させる」]形にすること。
・二人の関係性：[例「表面上は友好的だが、Aは内心Bを疑っている」]
・会話の途中で関係性が[変化：例「わずかに悪化する」]こと。
・地の文と会話文の比率は[例「4:6」]程度。
・書き上げたあと、「説明台詞になってしまった行」があれば自己申告してください。
```

### 🧹 推敲・リライト テンプレート

**使う場面**：書き上げた原稿の質を上げたいとき。

```text
以下の原稿を推敲してください。ストーリーや設定は変更せず、文章の精度だけを上げてください。

【チェックしてほしい観点】
・視点のブレ（視点人物が知り得ない情報を書いていないか）
・時制の乱れ、主語と述語のねじれ
・同じ語尾の連続、同じ単語・表現の重複
・説明過多で物語が停滞している箇所
・逆に、説明不足で読者が置いていかれる箇所
・冗長な修飾、削っても意味が変わらない一文

【出力形式】
・修正版の全文を提示すること。
・そのうえで、大きく手を入れた箇所については「元の文 → 修正後 → 修正理由」を別途リストで示すこと。
・作者の癖として繰り返し出ている問題があれば、最後にまとめて指摘してください。
```

> 💡 **コツ**：最後の「作者の癖」の指摘は、次に書くときの改善につながります。定期的に実行する価値があります。

## 🔬 9. 検証・監査（ミステリー品質の担保）

書いたものが「読者に対してフェアか」「破綻していないか」を点検する工程です。
ミステリーでは、この工程を飛ばすと後で全面改稿になります。

### ⚖️ フェアネス監査テンプレート

**使う場面**：真相が決まったあと、読者を騙す仕掛けがアンフェアになっていないか検証したいとき。

```text
あなたは本格ミステリーの評論家です。以下の[プロット／原稿]について、読者に対するフェアネスを厳しく監査してください。

【監査項目】
1. 真相を推理するために必要な手がかりは、すべて本文中に提示されているか（後出しはないか）
2. 地の文で明示的な虚偽を書いていないか（読者の誤読を誘う書き方と、嘘を書くことは別物）
3. 真相を知った読者が冒頭から読み返したとき、矛盾する記述はないか
4. 逆に「二度目に読むと意味が変わる」記述は十分にあるか
5. 「驚き」はあるが「納得」が置き去りになっていないか
6. 読者バイアスへの依存が過剰でないか（特定のバイアスを持たない読者にも成立するか）

・各項目について、問題があれば該当箇所を引用し、なぜ問題かを説明してください。
・問題がない項目についても、その判断根拠を1行で述べてください。
・忖度は不要です。厳しく評価してください。
```

> 💡 **コツ**：この監査は**別セッション（できれば別モデル）で、「他人の投稿原稿」として**投げてください。
> 同じセッションで自作を評価させると、AIは身内びいきと追従を起こして甘い判定を返します。項目6を詳しくやる場合は 5-9 を使ってください。

> 💡 **関連**：本格的な設計は既存スキル `twist-trick-forge`（`/fal-twist`）が担当します。これはその簡易版・単発チェック用です。

### 🧵 伏線一覧・回収チェックテンプレート

**使う場面**：伏線を張ったつもりが、回収し忘れていないか確認したいとき。

```text
以下の[原稿／プロット]から、伏線として機能している（または機能させるつもりと思われる）記述をすべて抽出し、台帳を作成してください。

【各伏線について記載する項目】
・伏線の内容（本文からの引用）
・設置箇所（第何章のどのあたり）
・初読時に読者にどう見えるか
・回収箇所（あれば）／未回収の場合はその旨
・回収されたときの効果（意味が反転する／伏線が伏線だったと分かる 等）

【併せて指摘してほしいこと】
・未回収のまま放置されている伏線
・回収はされているが、設置から回収までが遠すぎて読者が忘れる恐れがあるもの
・伏線のつもりだが、読者には伏線と気づかれないほど埋もれているもの
・逆に、あからさますぎて真相が読めてしまうもの
※回答は表形式ではなく、伏線ごとのカード形式で書いてください。
```

### ⏱️ 時系列・位置関係の整合チェックテンプレート

**使う場面**：アリバイや移動時間の破綻を潰したいとき。ミステリーでは必須の工程です。

```text
以下の[原稿／プロット]から、事件に関わる出来事の時刻・場所・登場人物の所在をすべて抽出し、時系列表を再構成してください。

【検証してほしいこと】
・同一人物が、物理的に不可能な時間で移動していないか
・複数の記述の間で、時刻・曜日・天候・明るさなどに矛盾がないか
・「誰がいつ何を知ったか」の情報伝達の順序に矛盾がないか（まだ知り得ない情報に反応していないか）
・記述が曖昧で、時刻が確定できない箇所（＝矛盾の温床）はどこか

・矛盾が見つかった場合は、該当箇所を引用し、どちらを正とすべきかの推奨案を添えてください。
・回答は時系列順のブロック形式（表は使わない）で書いてください。
```

### 🔩 トリック実現可能性の検証テンプレート

**使う場面**：考えたトリックが、現実の物理・法医学・技術で成立するか裏を取りたいとき。

```text
以下のトリックについて、専門家の視点から実現可能性を検証してください。

【トリックの内容】
[詳細に記述]

【検証してほしい観点】
・物理的・技術的に成立するか（成立しない場合、どの段階で破綻するか）
・[分野：例「法医学的・警察捜査の実務」]の観点から、現実には即座に露見してしまう要素はないか
・実行者にとって不確定要素が多すぎないか（偶然に頼りすぎていないか）
・成立させるために必要な条件（前提設定）を列挙すること

・「成立させるにはこう変えればよい」という修正案も併せて提示してください。
・あなたの知識で断定できない部分は、推測であると明記してください。
```

### 👓 初読読者シミュレーション テンプレート

**使う場面**：自分では判断できない「読者がどこで真相に気づくか」を推定したいとき。

```text
あなたはこの作品を初めて読む、ミステリーを年間50冊読む読者です。以下の原稿を、先入観なく順に読んでいく体で読んでください。

【出力してほしいもの】
・章ごとに、その時点であなたが立てている「犯人・真相の仮説」と、その確信度（％）
・真相に気づいた（または強く疑った）ポイントと、その決め手になった記述
・逆に、読んでいて退屈だった箇所、意味が分からず引っかかった箇所
・読み終えた時点での満足度と、その理由

※作者への配慮は不要です。読者としての正直な反応を書いてください。
```

> 💡 **コツ**：真相を先に伝えてしまうとシミュレーションが成立しません。**真相を書いていないファイルだけ**を読ませてください。

### 🔁 既視感・類似作品チェックテンプレート

**使う場面**：思いついた仕掛けが「どこかで見たもの」でないか確認したいとき。

```text
以下のアイデア（トリック・設定・展開）について、既視感の観点から評価してください。

【アイデア】
[記述]

・構造が類似する既存作品（小説・映像作品）があれば、作品名と類似点を挙げてください。
・「よくある型」に分類できる場合、その型の名前と一般的な実装例を説明してください。
・そのうえで、このアイデアの独自な点はどこか、独自性が弱い場合はどこをひねれば差別化できるかを提案してください。

【作品名を挙げるときの厳守事項】
・**該当作が思い当たらない場合は「なし」と答えてください。** 数を埋めるために作品を捻り出さないこと。
・挙げる場合は「書名・著者名・出版年・あらすじ」の4点セットで書くこと。
・記憶が不確かなものは「うろ覚え」と明記してください（事実確認は私が行います）。
```

> ⚠️ **この用途は、AIが最も事実を捏造しやすい工程です。**
> 実在しない書名・著者・あらすじが、実在するものと区別できない自然さで出てきます。しかも**マイナーな作品ほど捏造されやすい**ため、既視感チェックが狙う領域（誰も知らない先行作）と危険地帯が完全に重なります。
> 上位数本は必ず自分で実在確認してください。また「実在が確認できなかった＝既視感がない」ではありません。確認できた1本のほうが、確認できない29本より重い意味を持ちます。（→ 方法論ファイル「4-3 書誌の幻覚」）

## 🔍 10. リサーチ・分析

### 📚 用語集・リスト作成 テンプレート


### 🛠️ テーマ分析・メタ視点フィードバック テンプレート

### 🔬 専門分野リサーチ テンプレート

**使う場面**：作中で扱う専門知識（医学・生物学・法制度など）の正確さを担保したいとき。

```text
[テーマ：例「うつ病における『鉛様麻痺』の症状」]について、小説の描写に使える精度で調査してまとめてください。

【まとめてほしい内容】
・基本的な定義と、現在の一般的な理解
・当事者の主観的な体験としてどう感じられるか（描写に使える具体性で）
・創作でよくある誤解・ステレオタイプと、それがなぜ不正確か
・描写する際に配慮すべき点

【条件】
・確立した知見と、議論が分かれている点を区別して書くこと。
・可能な範囲で情報源の種類（学術／公的機関／体験談 など）を示すこと。
・あなたの知識が古い可能性がある領域は、その旨を明記すること。
```

### 🧩 既存作品の構造分解テンプレート

**使う場面**：好きな作品の「なぜ面白いか」を自作に取り込みたいとき。

```text
[作品名]について、ミステリーの構造という観点から分解・分析してください。

【分析してほしい項目】
・全体の構成（各パートの役割と、転換点の位置）
・読者を騙すために使われている仕掛けの種類と、その配置
・伏線の設置タイミングと回収のパターン
・情報開示のペース配分
・この作品でなければ成立しない要素（＝模倣できない部分）と、技法として抽出できる要素（＝学べる部分）の切り分け

※未読者へのネタバレ配慮は不要です。構造の分析が目的なので、真相に踏み込んで書いてください。
※記憶が曖昧な部分は、断定せず「うろ覚え」と明記してください。
```

## ⚙️ 11. AI環境の運用（スキル・ワークフロー）

Antigravity / Claude Code などのAI環境そのものを整えるためのプロンプトです。

### 🔎 スキル・ワークフロー検索

```text
Antigravity環境で利用可能な、ネット上で評判が良く、小説執筆のアイデア出し（ブレスト）に使えるスキルやワークフローを探しています。
「grill-me」のように対話形式で深掘りでき、選択肢ベースで進行できるようなものが希望です。該当するものがあれば教えてください。
```

### 🏗️ ワークフロー・エージェントスキル作成の最強メタプロンプト

**使う場面**：繰り返し使う手順を、AI自身にコーディングさせて `/コマンド` 化したいとき。最新のメタプロンプト（プロンプトにプロンプトを作らせる）知見を取り入れた、最も堅牢な仕様書作成テンプレートです。

```text
以下の作業を、Antigravity（またはCursor等）で繰り返し呼び出せる「スキル（ワークフロー）」として実装するための設定ファイル（Markdown）を生成してください。

【自動化したい作業・目的】
[例：シーン本文の執筆、特定ファイルの定期監査、どんでん返しのブレスト など]

【AIに遵守させるべき構造（メタプロンプトの仕様）】
このワークフローは、AIが確実に意図通り動くよう、以下の構造で構成してください。
1. **Role & Objective (役割と目的)**：このスキルを呼び出した際のAIの振る舞い。
2. **Trigger (起動条件)**：ユーザーがどういう意図でこれを呼ぶか。
3. **Context Gathering (前提知識の収集)**：作業前に必ず読み込むべきファイルパス。
4. **Step-by-Step Instructions (実行手順)**：工程を3〜5ステップに分割すること。各ステップは「推論（Chain of Thought）」と「出力」を明確に分けること。
5. **HARD-GATE (必須の確認関門)**：ユーザーの承認（Human-in-the-loop）を得ずに勝手に進めてはならない工程（幻覚ループ防止のため）を明記すること。本プロジェクトでは最低限、次の3つを含めること。
　 ・ユーザーが選ぶ前にファイルを書き換えない
　 ・AIが思いついた内容を、承認なしに `02_設定/` や確定ファイル（あらすじ・真相・決まったこと）へ書き込まない
　 ・削除・統合の前に、その対象がどのファイルから参照されているかを洗い出して提示する
6. **Constraints (制約事項)**：絶対にしてはいけないこと（例：既存設定の破壊、要約による情報の欠落など）。

【プロジェクト固有のルール】
・名称の冒頭には必ず「fal-」をつけること（例：fal-scene-writer.md）。
・出力する設定ファイルは、既存の `.agents/skills/*/SKILL.md` や `.agents/workflows/*.md` のフォーマットに合わせること。
・既存スキルと役割が重複しないこと。重複する場合は既存スキルの呼び出しを組み込むこと。
・既存のスキル／ワークフローを**廃止・吸収する場合**は、必ず次の順で行うこと。移譲漏れの確認前に削除してはならない。
　 1. 新しいスキルを作る
　 2. 旧スキルへの参照を全文検索して書き換える（過去の経緯として書かれているだけの記述は残す。判断に迷うものは残す側に倒し、一覧で報告する）
　 3. 削除対象のファイルを一覧で提示し、承認を得てから削除する
・全工程の出力は日本語で行うよう指示に含めること。

【進め方】
いきなりファイルを出力せず、まずは「どのようなフェーズ構成（ステップ）で設計するか」の概要案を提示し、私の承認を得てから最終的なファイルの中身を出力してください。
```

### 📜 プロジェクト・エージェントの「ルールファイル」作成メタプロンプト

**使う場面**：AIエージェントの振る舞いや、プロジェクト全体のコーディング規約・執筆ルール（`.cursorrules` や `.agents/rules/`）を定義するファイルを作らせたいとき。

```text
本プロジェクトにおけるAIエージェントの振る舞いを規定する「ルールファイル（Markdown形式）」の原案を作成してください。

【定義したいルールのテーマ】
[例：ミステリー小説執筆時のAIのスタンス、出力フォーマットの統一、禁止事項 など]

【ルールに盛り込むべき構造（ベストプラクティス）】
エージェントがコンテキストを見失わないよう、以下の要素を漏れなく組み込んでください。
1. **Core Identity (中核となるアイデンティティ)**：AIが常に保持すべきペルソナ（例：プロの編集者、レッドチーム検証者）。
2. **Global Constraints (絶対的な制約)**：いかなる例外も認めない禁止事項（例：地の文で嘘を書かない、ユーザーの指示がない限りファイルの上書きをしない等）。
3. **Output Formatting (出力形式の指定)**：回答時のレイアウト（例：表は使わずカード形式、Markdownのブロック活用等）。
4. **Context & Workflow Rules (固有のワークフロールール)**：特定の操作をする際の決まり（例：案を出すときは名前と一言説明を添える、変更時は「fal用メモ」に記録を残す等）。
5. **Anti-Patterns (アンチパターン)**：過去にAIが失敗した典型的なNG例（よくあるハルシネーションやご都合主義）と、その回避策。

【進め方】
まずは上記項目に沿って「どのようなルールを規定するか」の箇条書きのリストを作成してください。内容をすり合わせた後、エージェントが直接読み込める形式（YAMLフロントマター付きのMarkdownなど）で最終出力してください。
```

## 🚀 12. このプロンプト集をスキル/ワークフロー化するアイデア

このファイルは「探して・コピーして・`[ ]` を埋める」という手作業が前提です。
以下は、その手間をAI側に肩代わりさせるための構想メモです。

### ✅ 案A：プロンプト・ディスパッチャー `/fal-prompt`（実装済み）

やりたいことを一言告げると、この集から最適なテンプレートを選び、`[ ]` を埋めた完成版プロンプトを提示し、そのまま実行まで行うワークフロー。

- 入力例：`/fal-prompt 第5章の伏線が回収できてるか見て`
- 動作：このファイルを読む → 該当テンプレート（9-2 伏線チェック）を選定 → 対象ファイルを推定 → 不足パラメータだけを1問ずつ質問 → 完成プロンプトを提示 → 承認後に実行
- 利点：**このファイルを唯一の情報源（Single Source of Truth）として維持できる**。テンプレートを増やせば自動的にコマンドの能力が増える

**実装ファイル**
- `.agents/skills/prompt-dispatcher/SKILL.md` … 手順の本体
- `.agents/workflows/fal-prompt.md` … `/fal-prompt` コマンド（Antigravity）
- `.claude/commands/fal-prompt.md` … `/fal-prompt` コマンド（Claude Code。上記を参照するだけの薄い橋渡し）

**仕様のポイント**
- 実行前に必ず完成プロンプト全文を提示する（`[ ]` が残ったままの実行を禁止）
- 腰を据えたブレストや、どんでん返しの設計に該当する依頼は `/fal-brainstorm` `/fal-twist` へ委譲を提案する
- `02_設定/AGENTS.md` の「表を使わずカード形式」を常時付与する
- 実行後、**このファイルに追記すべきテンプレート案があれば提案する**（使うほど育つ設計）
- 「プロンプトだけ」と言えば実行せず、完成プロンプトの提示で停止（他のAIツールに貼る用途）

#### 🔧 メンテナンス：このファイルを編集するときの注意

`/fal-prompt` は**起動のたびにこのファイルを読み直す**設計です。したがって、内容の更新は基本的に自由に行えます。

**そのまま使える変更（メンテ不要）**

- テンプレートの追加・削除・書き換え、条件行の追記
- `[ ]` プレースホルダの増減
- 章番号の変更、章の並べ替え（スキル側は番号ではなく「工程」で照合しているため）
- 章タイトル・セクション名・テンプレート名の変更
  （スキル側に「名称は例示。一致しなければ内容から相当箇所を特定する」と明記済み）
- 新しい工程の章を追加（既存9工程に当てはまらない章も、内容から照合されます）

テンプレートを増やせば、その分 `/fal-prompt` の対応範囲もそのまま広がります。

**唯一メンテが必要な変更：このファイルの移動・改名**

`01_free_memo/プロンプト集.md` というパスは2箇所にハードコードされています。移動・改名する場合は両方を修正してください。

- `.agents/skills/prompt-dispatcher/SKILL.md`（「起動時の必須動作」の項）
- `.agents/workflows/fal-prompt.md`（手順2）

**将来的に注意が必要なこと**

- **ファイルの肥大化**：`/fal-prompt` は毎回このファイル全体を読み込みます。現状の規模では問題ありませんが、数千行規模になると起動が重くなります。その時点で「章ごとの分割＋このファイルを索引（ハブ）にする」再編が必要です（→ 2章の「ファイル分割・ナレッジ整理テンプレート」が使えます）。
- **テンプレートの重複**：似たテンプレートが増えると選定がぶれます。定期的に統合してください（→ 2章の「ファイル整理・統合テンプレート」）。

### 案B：整合性監査スキル `consistency-audit` ＋ `/audit`

第9章（フェアネス／伏線／時系列／実現可能性／初読者シミュレーション）と 5-9（バイアス依存度）をチェックリスト化し、順に実行して監査レポートを出力するスキル。

- 監査結果を `audit/YYYYMMDD_監査レポート.md` に蓄積し、前回との差分（解消済み／未対応）を追跡
- 「監査を省略して完了と報告してはならない」を HARD-GATE 化（`twist-trick-forge` と同じ設計思想）
- 執筆が進むほど価値が上がる。手作業では絶対に続かない工程なので、自動化の効果が大きい

### 案C：シーン執筆ワークフロー `/scene`

第8章の「文体ガイドライン準拠のドラフト」を定型化。

- 文体ガイドライン → 該当キャラの設定ファイル → 直前の章 の順に自動ロード
- シーン仕様（視点・場所・目的・禁止事項）を1問ずつ確認
- ドラフト生成 → 8-4 の推敲観点でセルフレビュー → 差分提示
- 毎回同じファイルを手で指定する手間が消えるのが最大の効果

### 案D：キャラボイステスト `/voice`

7-3 の自動化。`02_設定/キャラクター/` から指定キャラのセリフを機械的に抽出し、話者名を伏せた状態で別セッションのAIに当てさせ、正答率と混同ペアを報告する。

- キャラ数が多い本作（探偵・助手・鳥たち・AI等）では、声の差別化が崩れやすいため効果が高い
- 「誰と誰が混ざりやすいか」が定量的に出る

### 案E：伏線台帳の自動更新 `foreshadow-ledger`

9-2 を単発チェックではなく、常設の台帳として運用するスキル。

- `03_伏線台帳.md`（新規）を維持し、章を書き足すたびに追記・ステータス更新
- 未回収の伏線を常に一覧できる状態にする
- 案Bの監査スキルから呼び出す形にすると役割が重複しない

### 案F：メモ整理ワークフロー `/tidy`

第2章（整理・統合＋レイアウト調整）を定型実行。`02_設定/AGENTS.md` の「表を使わずカード形式」ルールを常に適用する。

- `01_free_memo` に溜まった断片メモの定期的な棚卸しに使う
- 既存の `/fal-refill-free_memos` と組み合わせると、メモ運用が一周する

### 実装の優先順位

1. ~~**案A `/fal-prompt`**~~ … ✅ 実装済み。他のすべての案の入り口になる
2. **案B `/audit`** … 品質面のリターンが最大。本文執筆が始まったら必須（次の候補）
3. **案C `/scene`** … 本文執筆フェーズに入った時点で着手
4. 案D・E・F … 必要を感じた時点で追加

> 💡 案A・B・Cは、既存の `mystery-deep-brainstorm`（発想）と `twist-trick-forge`（仕掛け設計）とは工程が異なるため、役割が重複しません。
> 「発想 → 仕掛け設計 → 構成 → 執筆 → 監査」というパイプラインのうち、後半3工程を埋める形になります。
